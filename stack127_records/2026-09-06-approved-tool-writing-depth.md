# Approved tool-writing depth

Teja approved Domain Age content revision 5 as the direction for future tool content. The reference is its editorial judgment, not a reusable six-section outline or a requirement to include a table on every page.

Current rules live in `stack127_docs/writing-style.md` and `stack127_docs/visual-first.md`. The tool-writing, content-and-SEO planning, visual-first, and orchestration skills now follow them:

- Keep the working interface concise and the tool first. Give supporting content enough useful depth to interpret and verify the answer.
- Preserve useful existing coverage during rewrites. Remove repetition and filler without removing the reasoning between facts.
- Use original, conversational, Verge-inspired writing with accurate technical detail and natural search-focused headings.
- Choose media by what they explain. Do not force components or discard useful prose to satisfy a media ratio.
- Treat word and section limits as explicit user constraints, not default quality measures.

The content-plan template and pipeline validator no longer require a five-section, 700-word ceiling, prose-minority declaration, or numeric word limit for every writing assignment. Source facts, scope, repetition guards, stable assignments, upstream fingerprints, and the primary tool medium remain checked. The validator's test fixture was updated to the existing nine-column input contract so those checks can run against the current interface schema.

No page content, tool behavior, database values, or publication state changed in this skill update. Repository skills remain canonical; the existing `.agents/skills` and `.claude/skills` symlink adapters use them directly.
