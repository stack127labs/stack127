## Cost examples — our calculations

Checked 2026-11-04. These are our calculations, not vendor quotes or capacity benchmarks. Baseline: one **international Singapore `ap-singapore` Pro environment**, current credit billing, USD before tax, no trial assumed, monthly plan credits otherwise unused. List subscription **$20** and **200,000 credits = $20 of eligible usage**; current promotional subscription **$15** has the same published credits. These are separate prices, not currency conversions. Exact promotion eligibility/end date is purchase-page dependent. [Current Pricing](https://www.tencentcloud.com/document/product/1266/85593), [Plan/reset rules](https://www.tencentcloud.com/document/product/1266/85595), [Terms — fees/taxes](https://www.tencentcloud.com/document/product/301/9248).

For eligible metered usage value `U` in USD at published credit conversion, monthly model is **subscription + max(U − $20, 0) + outside-quota charges**. A $20 subscription is not $20 plus all gross usage again. Credit packs can cover excess but require prepaid purchase and expire; no pack purchase assumed. Metering can lag two days. Per-event/duration/currency rounding and the exact stacking of SDK, resource and HTTP-gateway calls were not fully established; arithmetic below retains precision and is a model, not invoice cents. [Credit basis and meters](https://www.tencentcloud.com/document/product/1266/85593), [Pack validity](https://www.tencentcloud.com/document/product/1266/85594), [Overage/service state](https://www.tencentcloud.com/document/product/1266/85595).

For shared PG, let `H` be **active five-minute slots expressed as equivalent active hours**, from zero to at most the scenario's 730 hours. Each active hour bills 0.5 core-hour. Compute = `H × 0.5 × $0.06 = $0.03H`. A single request/connection or internal transaction/job can make the whole five-minute slot active. Query counts cannot determine `H`; no arbitrary milliseconds-per-query assumed. Shared database storage = GB × retained hours × $0.0002. Dedicated instances use allocated cores and allocated storage instead. [International capability metering](https://www.tencentcloud.com/document/product/1266/74429), [Original Chinese five-minute rules](https://docs.cloudbase.net/database/postgresql/database-management), [International PG rates](https://www.tencentcloud.com/document/product/1266/85593).

The actual value cannot be selected from read/write counts. **5GB native database egress, logs, extra capacity and any billing rounding remain unpriced**, so neither is a complete total. SDK/PostgREST instead of native connections would add the applicable call meters. ### 2. Full app backend

Inputs: the small SQL workload plus 1,000 MAU, 1GB files, 100,000 file reads, 10,000 uploads, **20GB total** internet delivery and 10,000 short function calls. Function assumption: ordinary function, one second at **128MB**, no retries, memory-to-GBs relation following the vendor's 512MB × two-second example. API/auth counts are not derivable from MAU; for this illustration only, assume 2,000 auth calls. Assume 5GB database output (unpriced) plus 15GB file CDN output, all 15GB requiring origin fetch, and a 30-day/720-hour file month.

Known usage components at published rates:

- PG compute/storage: `$0.03H + $0.146`.
- File occupancy: `1GB × 30 days × $0.00066667 = $0.0200001`.
- File reads/writes: `110,000 / 10,000 × $0.002 = $0.022`.
- Functions: `10,000 / 10,000 × $0.002 + 10,000 × 1s × 0.125GB × $0.0000167 = $0.022875`.
- File network: `15 × ($0.09 CDN + $0.072 origin) = $2.43`.
- Illustration-only auth count: `2,000 / 10,000 × $0.10 = $0.02`.
