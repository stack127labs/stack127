## Field problems

- The directory row calls Milvus a “vector and search database.” Its primary role is a vector database/search engine with a collection/field model, not a general SQL database.
- The documentation presents several deployment modes and parallel version lines. Lite package versions and server release tags are not interchangeable, so each is labeled separately.
- The self-hosted offer has no vendor usage bill. Pricing, scale-to-zero, region, and egress fields therefore describe operator-selected infrastructure only or are marked not applicable to the Milvus product.
- Milvus requires object storage internally, but this is not user file storage. File fields are marked not applicable to avoid transferring storage-provider rates to the database.
- A database Function may call an external embedding provider; its provider bill is separate from the Apache software license.
- Snapshot and backup are different: current 3.0 snapshots restore as collections in the same cluster; the current Milvus Backup repository supports 3.0.1+, but the older docs matrix still ends at 2.6.x.
- The terms and privacy URLs were not accessible through the research tool. The Apache license and product FAQ were available for the self-hosted license and price facts, so this did not block those required fields. Other unknowns name the official pages searched.
