# Crunchy Bridge

**Acquisition and retirement notices:** Crunchy Data announced joining Snowflake on June 2, 2025; current Bridge terms contract with Snowflake Inc. Bridge remains offered with current plans and self-service entry. No dated whole-service shutdown or forced migration notice was found in the official product, changelog and terms review. See [acquisition announcement](https://www.crunchydata.com/blog/crunchy-data-joins-snowflake) and [current terms](https://www.snowflake.com/en/legal/other/crunchy-bridge/terms-of-service/).

**Version sunsets:** Postgres 15 new provisioning was restricted in May 2026; Bridge's version table ends PG15 availability May 10, 2027. The same page's PG14 table says availability ended June 11, 2026, despite lingering prose about limited access. Treat that inconsistency as unresolved, not a new-PG14 offer. See [version policy](https://docs.crunchybridge.com/concepts/postgres-versions) and [retirement changelog](https://docs.crunchybridge.com/changelog). Container Apps remains public beta, subject to the preview terms; it is not a retirement notice.

## Cost examples — our calculations

Checked 2026-11-05. These are our calculations, not vendor quotes. Use the published AWS East examples, normally AWS us-east-1; no other region is silently given the same rate. Prices are USD before taxes. [Plans and Pricing](https://docs.crunchybridge.com/concepts/plans-pricing) quotes full calendar-month prices and second proration; [main pricing](https://www.crunchydata.com/pricing) supplies storage and inclusions. The requested 730 hours are treated as the comparison's full month, not multiplied by an invented hourly divisor.

We choose 10 GB allocated disk as an illustrative reference for a 1 GB database. This is an assumption, supported as an example disk size in [autoresize documentation](https://docs.crunchybridge.com/concepts/autoresize), not a verified minimum or measured actual disk requirement. Call actual required allocation S GB. PostgreSQL system data, indexes and WAL also occupy disk. No free allowance/trial credit is subtracted: none was established. Standard backups and transfer are included; extended retention and paid support are excluded.

### 1. Small SQL/document app

Inputs: 1 production database, 1 GB stored, 100,000 reads, 20,000 writes, 10 peak connections, 5 GB internet transfer and 730 hours online.

Using AWS East Standard-4, our full-month reference formula is `70 + (10 × 0.10) = $71`. Under the stated allocation and inclusions, **$71/month before tax** is the reference; the general expression is `$70 + $0.10S`. It is not a proven absolute minimum or a benchmark that this instance meets every latency goal. Source: [AWS East plan table](https://docs.crunchybridge.com/concepts/plans-pricing), [storage and transfer inclusions](https://www.crunchydata.com/pricing).

The same configuration with HA gives `2 × (70 + 10 × 0.10) = $142/month`, following the [documented cluster-price doubling](https://docs.crunchybridge.com/concepts/plans-pricing); no additional ordinary backup fee is invented. Current uptime-contract conflict remains below.

For development only, Hobby-0 reference `9 + 10 × 0.10 = $10/month`. That is not the production recommendation: [Hobby excludes HA/pooling and is not intended for production](https://docs.crunchybridge.com/concepts/plans-pricing). Query counts do not imply measured CPU demand, especially with burstable Hobby cores.

### 2. Full app backend

Inputs: case 1 plus 1,000 monthly active users, 1 GB files, 100,000 file reads, 10,000 uploads, 20 GB total internet transfer and 10,000 short function calls. To state a concrete compute assumption, use one second/512 MiB per call: `10,000 × 1 = 10,000 execution-seconds`.

**Full total unknown.** The $71 database reference does not include an established native consumer-login/upload/CDN/function bundle. [Container Apps](https://docs.crunchybridge.com/container-apps) can host configured API software, but is beta and shares database-host resources; it does not provide a separately priced 512 MiB function allocation. Formula: database + externally selected auth/files/delivery/compute + any email/SMS. Which provider serves the extra 15 GB is unspecified, so it is not priced automatically as Bridge egress.

### 3. Small file store

Inputs: 100 GB hot storage for 30 days, 100,000 writes, 1 million reads and 100 GB internet delivery; objects stay for the month.

**Not applicable to ordinary Bridge as a standalone object store.** Formula needs object storage + operation/retrieval + delivery prices from the actual file provider. SQL values and [database backups](https://docs.crunchybridge.com/concepts/backups) are not app buckets. Separate Crunchy Data Warehouse appears in the [changelog](https://docs.crunchybridge.com/changelog) as its own offering with managed storage and different pricing; its object rates are not mixed into this record.

### 4. Small vector search app

Inputs: 100,000 vectors, 1,536 float32 values each, 1 KiB metadata each, 100,000 searches, 10,000 updates and 5 GB internet transfer.

Our raw payload calculation: `100,000 × (1,536 × 4 + 1,024) = 716,800,000 bytes = 0.7168 decimal GB`. [pgvector reference](https://access.crunchydata.com/documentation/pgvector/latest/) adds 8 bytes per vector datum, giving `716,800,000 + 100,000 × 8 = 717,600,000 bytes` before row/index/TOAST/WAL/free-space overhead. The raw payload is not the allocated/billed disk requirement.

Reference database formula remains `70 + 0.10S`; an illustrative S=10 yields $71 before tax. **Actual total/sizing unknown** because required S, CPU/memory headroom and model costs are not established. [Bridge Vector](https://docs.crunchybridge.com/extensions-and-languages/vector) demonstrates 1,536 dimensions; version-specific index limits are recorded above, not assumed identical on every existing cluster. Embedding/reranking providers and rates remain unpriced.

### 5. Small job workload

Inputs: 10,000 jobs, one active second, requested 0.5 vCPU and 0.5 GB RAM each, peak 5 concurrent, no retries/waits. Requested work is `10,000 active seconds = 5,000 vCPU-seconds + 5,000 GB-seconds`.

**Exact worker total unknown.** [SQL scheduler](https://docs.crunchybridge.com/concepts/scheduler) runs inside the database; [containers](https://docs.crunchybridge.com/container-apps) share its host, with no verified per-job 0.5-vCPU/0.5-GB allocation or separate invocation rate. A provisioned database fee continues through idle/wait periods; external workers require their own bill. Do not multiply database rates by requested worker seconds.

Retry/wait variant: one retry for every job doubles active work to 20,000 seconds; a further 10 seconds waiting per job adds 100,000 waiting-seconds. Whether waiting occupies billable external worker resources depends on the selected runtime; no zero-price wait assumption is made.

### 6. Idle project

Inputs: same 1 GB retained database and illustrative 10 GB disk, zero queries/jobs/downloads for the month.

Running Standard-4: `70 + 10 × 0.10 = $71/month`. Manual suspend for the whole month: `0 + 10 × 0.10 = $1` **accrued storage usage**, with compute off. Sources: [closure/suspension charges](https://docs.crunchybridge.com/concepts/account-closure), [storage rate](https://www.crunchydata.com/pricing). This is not an online database and has no demonstrated wake-on-query.

The [billing rule](https://docs.crunchybridge.com/concepts/billing) says usage below $5 is not charged. If the entire Team has only that $1 suspended usage and the rule applies, the collected charge is $0, while accrued usage is $1. Other clusters/add-ons on the Team can change collection. Do not describe this as free hosting. Extended-retention settings must first be removed to permit suspension, per [Backups](https://docs.crunchybridge.com/concepts/backups).
