## Cost examples — our calculation

All inputs/rates checked **2026-11-05**. Amounts retain the published **$** symbol; no currency conversion is used. Terms §4 says charges exclude taxes. The pricing/rate pages do not explicitly identify an ISO currency code for every rate, so none is invented. These examples assume one workspace, one stated billing month, the selected listed region **us-east-1**, no other workspace usage and no legacy Accelerate connection. No region surcharge is published in the inspected plan table. [Pricing](https://www.prisma.io/pricing), [Terms §4](https://www.prisma.io/legal/terms), [regions](https://www.prisma.io/docs/postgres/faq); checked 2026-11-05.

Database operation/storage allowances are shared at workspace level. Define the query path: for these examples, **one specified autocommit SQL query = one billed operation**, with no additional metadata/health-check/transaction-control requests. Prisma Client batching can produce different operation counts. Assume the stated stored size means the total metered database footprint, rather than only application row payload. Exact sampling, billing increments and invoice rounding were not established. [Operation rules](https://www.prisma.io/docs/postgres/faq), [Console billing scope](https://www.prisma.io/docs/console), [pricing](https://www.prisma.io/pricing); checked 2026-11-05.

The paid database formula is `base + max(0, operations − included) / 1,000,000 × operation rate + max(0, stored GB − included GB) × storage rate`. Optional Compute is metered separately but **the shared plan base is counted once**. DB egress is included. A database does not require a 730-hour allocated-compute charge; 730 hours only matters to an app/scheduler deliberately kept awake. Object Store tariffs remain unpublished and are never set to zero in a total. [Database FAQ](https://www.prisma.io/docs/postgres/faq), [Compute pricing](https://www.prisma.io/docs/compute/pricing), [Object Store](https://www.prisma.io/docs/compute/object-storage); checked 2026-11-05.

### 1. Small production SQL app

Inputs: one database, **1 GB total metered storage**, **100,000 reads**, **20,000 writes**, **10 peak pooled connections**, **5 GB internet database transfer**, retained for the month.

Our operation calculation: `100,000 + 20,000 = 120,000 operations`.

- **Free allowance arithmetic:** `$0 + $0 overage = $0/month`, because 120,000 < 200,000 operations and 1 GB < 2 GB. Ten pooled clients reach the Free concurrency ceiling; they do not prove a particular throughput/latency. There are no Free snapshots or SLA. Current Free-production guidance conflicts as recorded in C06; this is the published-allowance result, not a blanket production recommendation.
- **Normal smallest paid path, Starter:** `$10 + max(0,120,000−1,000,000)/1,000,000×$8 + max(0,1−10)×$2 = $10/month`. Includes activity-day daily snapshots retained seven days, but no SLA.
- **SLA-covered variant, Pro:** the same workload stays under 10M operations/50 GB, so the listed base is **$49/month**, with the contractual 99.95% service promise subject to its conditions. This does not establish a customer-selectable replica topology or PITR.

DB transfer adds no charge in these paths. A 730-hour retained month does not add an hourly database compute line. Extra queries, other workspace databases or a larger physical/index footprint can change the calculation. [Rates/limits](https://www.prisma.io/pricing), [operation rules](https://www.prisma.io/docs/postgres/faq), [pooling](https://www.prisma.io/docs/postgres/database/connection-pooling), [backups](https://www.prisma.io/docs/postgres/database/backups), [SLA](https://www.prisma.io/legal/sla); checked 2026-11-05.

### 2. Full app backend

Inputs: the SQL case plus **1,000 MAUs**, **1 GB files**, **100,000 file reads**, **10,000 uploads**, **20 GB total internet transfer**, and **10,000 function calls**, each **1 second, 0.5 active vCPU and 0.5 GB provisioned memory**. The requested per-call resource shape is an assumption, not a verified selectable Compute machine.

For a known subtotal, route **5 GB** directly from the database and **15 GB** from Compute: 20 GB total, not 20 GB on top of the original 5 GB. Assume all inbound requests fit Starter's 5M allowance, including database-facing routes/file routes. For the specified 10,000 calls only:

`memory = 10,000 × 1 × 0.5 / 3,600 = 25/18 GB-hours`

`CPU = 10,000 × 1 × 0.5 / 3,600 = 25/18 vCPU-hours`
