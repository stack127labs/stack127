## Cost examples: our calculation

Checked **2026-11-05**. CouchDB is free self-hosted software under a royalty-free Apache License 2.0 grant. The project does not publish a hosted billing currency or a CPU/storage/request tariff. **0 software-license charge is not a 0 infrastructure invoice.** No third-party server price, free VM or unsupported minimum machine is assumed. Sources: https://couchdb.apache.org/ ; https://www.apache.org/licenses/LICENSE-2.0 ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/performance.rst.

### Small document app and idle project

Approved inputs: one database, 1 GB retained for a month, 100,000 reads, 20,000 writes, 10 peak client connections, 5 GB internet transfer and 730 hours of availability. CouchDB's HTTP JSON model fits the document-app case. Actual CPU/RAM/disk depend on document sizes, revision churn, view/index design, authentication, attachments, replication and compaction; operation counts alone do not select a valid machine. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/intro/overview.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/performance.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/compaction.rst.

**Our calculation:**
- Software-license charge: **0** under the Apache grant.
- Single-node logical copy volume: 1 GB × 1 copy = **1 GB** before indexes, metadata, old revisions and backup copies.
- For an explicitly configured n=3 cluster: 1 GB × 3 document replicas = **3 GB of logical replicated content**, before overhead/compression/indexes. With default q=2, there are 2 × 3 = **6 shard-replica files**; that is not 6 full copies of the database.
- Actual monthly cost = **compute hosting + billable disks + backup/snapshot storage + billable transfer + optional support + operation work**. Every infrastructure rate is unknown until a host/topology is selected, so **total incomplete**.

Sources for replication/compaction inputs: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/config/cluster.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/cluster/theory.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/backups.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/compaction.rst. Three nodes is strongly recommended for a cluster; a standalone node is also supported. Quorum acknowledgements and available shard copies matter more than merely counting servers. No request-per-second or failure-recovery benchmark was run.

For the **idle variant**, requests and job execution become zero but the same data/host/backup allocations remain unless the operator changes them. Software royalties stay 0. The operator's host and storage charges cannot be inferred from CouchDB's license. A 3.5.3 note about internal Erlang process hibernation is not a hosted scale-to-zero billing offer. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/whatsnew/3.5.rst ; https://www.apache.org/licenses/LICENSE-2.0 ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/backups.rst.

### Backup and high-availability variants

For a **backup variant**, choose a retention policy and add the actual backup bytes, storage rate, transfer and restoration work to the formula above. The docs support replication, copying .couch files and filesystem snapshots; configuration and relevant logs need coverage. A continuously updated replica does not preserve an independently retained point-in-time archive. No automatic 7-/30-/35-day vendor retention is assigned. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/backups.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/compaction.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/replication/conflicts.rst.

For a **cluster variant**, account for the chosen nodes and n replicas. During compaction, the affected file is rewritten and can need roughly twice its disk space temporarily. Do not size a disk to the live JSON bytes alone or mechanically double the entire cluster's monthly bill: concurrent compactions, indexes, snapshots, compression and filesystem allocation determine physical usage. Recovery/uptime responsibility stays with the operator. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/setup/cluster.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/config/cluster.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/compaction.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/backups.rst.

### File/attachment scenario

Approved inputs: 100 GB average attachment payload for a 30-day month, 100,000 writes, 1 million reads and 100 GB internet transfer. CouchDB can serve document attachments, subject to each attachment/request's configured limits: the 3.5.3 default reference lists **1,073,741,824 bytes per attachment** and **4,294,967,296 bytes per HTTP request body**. The workload does not specify individual file sizes, so upload fit cannot be guaranteed. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/rel/overlay/etc/default.ini ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/config/http.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/api/document/attachments.rst.

**Our calculation:** software-license charge **0**; 100 GB × 3 configured copies = **300 GB logical attachment-replica payload** for n=3, before compression, document/index metadata, old revisions and backups. Single-node logical payload remains 100 GB. Network usage includes client delivery, replication, backups and retry behavior, rather than an invented free-egress allowance. Hosting/disk/network rates and real physical allocation are not known, so **total incomplete**. Sources: https://www.apache.org/licenses/LICENSE-2.0 ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/config/cluster.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/replication/intro.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/backups.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/config/misc.rst.

This is document-attached file storage. It is not an S3 bucket tariff, separate archival tier, CDN plan or guaranteed object-version-retention product. HTTP Content-Type/auth/revision behavior comes from the attachment API. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/api/document/attachments.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/api/database/security.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/maintenance/compaction.rst.

### Full backend, vectors and jobs

The full-backend scenario adds 1,000 monthly active users, 1 GB files, 100,000 file reads, 10,000 uploads, **20 GB total** internet transfer and 10,000 short function calls. CouchDB supplies database users/authentication, documents and attachments, but an application still needs its own user flows and any general function/worker execution. There is no hosted MAU/function tariff here. The 20 GB replaces, rather than adds to, the smaller scenario's 5 GB. Email/SMS and other external services remain unpriced. **Full-backend total incomplete.** Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/intro/security.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/api/document/attachments.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/ddocs/ddocs.rst ; https://www.apache.org/licenses/LICENSE-2.0.

The dedicated vector-search scenario is **not applicable to the documented native modules**: the inspected query catalog covers Mango, MapReduce and optional Lucene text search, with no vector/embedding API to map 100,000 1,536-dimensional vectors and 100,000 ANN searches onto. Storing arbitrary JSON arrays is not a supported indexed vector-service price. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/ddocs/mango.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/ddocs/ddocs.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/ddocs/nouveau.rst.

The 10,000-job scenario at a target 1 active second/0.5 vCPU/0.5 GB and peak 5 concurrent jobs is **not a CouchDB worker entitlement**. _changes can drive a separately hosted consumer, but it guarantees only the latest change per document rather than every intermediate event. General retries, 60-second waiting/delays, cron, worker logs and result retention require an external application/runtime and its own resource bill. No job execution total or retry/wait price is fabricated from a database query function. Sources: https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/api/database/changes.rst ; https://raw.githubusercontent.com/apache/couchdb/3.5.3/src/docs/src/ddocs/ddocs.rst ; https://www.apache.org/licenses/LICENSE-2.0.
