## Notices checked first

NATS and Synadia Cloud are active. The current CNCF page records NATS as a Graduated project from November 2, 2026. NATS Server v2.15.2 is the latest stable release checked, dated October 26, 2026. The 2025 CNCF/Synadia dispute ended in an agreement: NATS stayed in CNCF under Apache-2.0, Synadia agreed to assign its two registered NATS trademarks to the Linux Foundation, and Synadia said it would not fork NATS Server under the Business Source License. Synadia continues to support the project. CNCF’s June 2025 board minutes described a positive resolution and stronger collaboration.

## Conflicts and unknowns

- The Synadia Cloud pricing table uses “Standard” and “HA” for JetStream allowances. A current Cloud JetStream management guide says Synadia is changing those labels to “R1” and “R3.” I kept the price-table labels because those are the names attached to its current published limits; the documentation appears to describe the same single-replica and three-replica classes. Source: https://docs.synadia.com/cloud/pricing ; https://docs.synadia.com/cloud/user-guides/jetstream-mgmt
- Synadia’s public Cloud price pages show dollar symbols but no ISO currency code. I kept “$” as published and did not assume USD. The Synadia Deploy enterprise terms specify USD for that separate service, so I did not use those terms to infer Cloud currency.
- Synadia Cloud’s public FAQ and account guide explain free-account inactivity and account/team deletion, but not a fixed inactivity interval or physical data-removal timeline. I checked the Cloud FAQ, pricing page, Cloud account guide, and Synadia site. The separate Synadia Deploy terms were not treated as Cloud terms.
- The Cloud product page lists four named service regions, while the regional endpoint page lists five broad connection regions. I preserved the two different lists because one is a location-code list and the other is a connection endpoint grouping.
- Cloud plan ceilings are not the only safeguards. The FAQ says other subscription, JetStream asset, and usage limits may apply, but does not enumerate all of them.
- The NATS server’s 64 MB configurable max_payload is not a claim that every stream or Synadia Cloud plan accepts messages that large. Hosted plan caps are lower and separately listed.
- Synadia Cloud does not publish a general throughput figure or workload CPU/RAM size in the plan and workload pages checked. No performance estimate was inferred from product marketing.

## Field problems

- C12, C13, C15, and C21: Cloud prices show “$” but do not state an ISO currency code or tax treatment. Values retain the published dollar symbol.
- C03: I did not find a public customer Terms or Privacy page specific to Synadia Cloud. The located Synadia Deploy enterprise terms describe another Synadia product and were not substituted.
- C14 and J02: Cloud publishes workload counts but not CPU, memory, per-run duration, or a distinct idle-compute billing rule.
- J04: JetStream message retention is configurable per stream, so there is no single default retention duration suitable as a product-wide value.
- H01: No single hardware minimum or self-hosting bill is meaningful across different traffic, retention, and replica configurations; the official pages did not publish one.
