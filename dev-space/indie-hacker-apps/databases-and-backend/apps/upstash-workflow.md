## Conflicts and unknowns

- The pricing FAQ does not itemize whether the initial `client.trigger` adds a separate billed step beyond workflow commands. It was checked against the pricing FAQ, pricing page and trigger API; cost examples use only the explicitly documented step counts.
- The Workflow price page's active-schedule overage says $0.01 per active schedule beyond 1,000 but does not state a billing period or eligible plan; the plan grid omits the metric. QStash schedule limits are separate and were not copied here.
- Workflow docs hard-limit a run to 1,000 logical steps. A September 2026 Upstash blog discusses a separate QStash internal limit of 10,000 entries for a run. The blog's internal-entry count is not treated as the Workflow logical-step cap.
- The privacy policy and region docs do not provide a complete contractual residency statement for Workflow run state, logs and backups. Migration docs say logs/DLQ remain in the old region.
- General terms give inactivity and deletion provisions but do not explain if a sleeping Workflow run is considered an inactive resource.
- The current pricing table uses `$` without an ISO currency code. No country or company-location inference was used to call this USD.
- Pages checked for open product questions included Workflow pricing/FAQ, docs pricing, Workflow limits, trigger, steps, retry, sleep, wait, parallelism, schedules, logs, DLQ, regions, local development, terms, privacy, security measures, changelog, official blog and GitHub repositories/discussions.

## Field problems

- The advertised machine-readable `https://upstash.com/pricing/workflow.md` returned an unsupported `text/markdown` content type in the research fetcher. The official HTML pricing page exposed the needed rates and limits and was used instead.
- Workflow uses a regional QStash delivery service. Its Workflow pricing table was used for Workflow's step meter and plan limits; separate QStash plan facts remain in `upstash-qstash.md`.
- The price page does not print a currency code and does not clearly identify the period/plan for the active-schedule overage.
- `context.run` code executes on the customer's host, so its runtime timeout can also be imposed by that host. Upstash's maximum HTTP response duration is a distinct per-plan delivery limit.
