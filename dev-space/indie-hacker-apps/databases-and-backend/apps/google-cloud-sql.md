## Cost examples — our calculations

Checked 2026-11-05. All prices below are USD, Iowa (`us-central1`), on-demand, without a committed-use discount, promotion or tax. These are calculations from published rates, not vendor quotes or measured sizing results. Source: [Cloud SQL pricing](https://cloud.google.com/sql/pricing?hl=en), CPU/memory, storage, network and license tables; [instance settings](https://docs.cloud.google.com/sql/docs/postgres/instance-settings), custom machines and disk minimum; [Cloud Terms](https://cloud.google.com/terms/), §2.2 Taxes. ### 1. Small SQL app

Inputs: one PostgreSQL 18 **Enterprise** general-purpose dedicated instance, single zone, 1 vCPU, 3.75 GiB billed RAM, 10 GiB billed SSD capacity, 730 hours; 1 GB logical app data, 100,000 reads, 20,000 writes, 10 peak connections and 5 GB internet egress. Explicitly choose Enterprise because PostgreSQL 18 creation otherwise defaults to Plus in the documented interfaces. Configure connections to accommodate the application and allow for database/internal work. Sources: [edition defaults](https://docs.cloud.google.com/sql/docs/postgres/editions-intro), [connection limits](https://docs.cloud.google.com/sql/docs/postgres/quotas), checked 2026-11-05.

The settings guide calls its disk minimum **10 GB** and memory minimum **3.75 GB**, while pricing bills **GiB**. This example explicitly assumes 10 GiB of billed provisioned disk and 3.75 GiB of billed memory; it does not silently convert a decimal 10 GB request. Logical 1 GB = 1,000,000,000 bytes = 0.9313225746154785 GiB. The provisioned disk also holds database/system overhead, logs and indexes.

Our calculation:

| Component | Formula | Result before rounding |
| --- | --- | --- |
| Dedicated compute | 730 × (1 × $0.0413 + 3.75 × $0.007) | $49.3115 |
| Provisioned SSD | 730 × 10 × $0.000232877 | $1.7000021 |
| Internet egress | (5 × 1,000,000,000 ÷ 1,073,741,824) × $0.19 | $0.88475644588470458984375 |
| Subtotal without backup | $49.3115 + $1.7000021 + $0.88475644588470458984375 | $51.89625854588470458984375 → **$51.90** |
| Standard backup assumption | 1 GiB average used backup storage × 730 × $0.000109589 | $0.07999997 |
| Subtotal with that backup assumption | $51.89625854588470458984375 + $0.07999997 | $51.97625851588470458984375 → **$51.98** |

The assumed **one-GiB average backup footprint is not derived from one GB of live data**. Daily changes and retained backup chains can change it. Query counts have no per-read/write Cloud SQL price here, but query complexity, concurrency, indexes and working memory determine whether this small configuration is sufficient. Therefore this is a priced configuration subtotal, **not an exact cheapest adequate workload total**. More disk, CPU, logs, exports, support, external application hosting, network attachments and taxes can add cost. Optional HDD is cheaper per GiB in this series, but performance adequacy is untested; changing only the disk line gives $0.9000024 for 730 hours and a $51.17625881588470458984375 subtotal with the same backup/egress assumptions (rounded **$51.18**).

**HA variant — our calculation:** same assumptions, but a regional HA primary/standby. Compute = 730 × ($0.0826 + 3.75 × $0.014) = $98.623. HA SSD = 730 × 10 × $0.000465753 = $3.3999969. Add $0.07999997 assumed standard backup and $0.88475644588470458984375 egress: $102.98775331588470458984375 → **$102.99**. The HA rate already includes the regional topology; no second multiplication by two. This configuration qualifies for the Enterprise HA SLA only subject to its conditions. Sources: [HA architecture](https://docs.cloud.google.com/sql/docs/postgres/high-availability), [SLA](https://cloud.google.com/sql/sla), checked 2026-11-05.

**Backup variants — our calculation:** retaining B average GiB as standard backups for 730 hours adds B × 730 × $0.000109589. For an Enhanced Iowa vault under active Cloud SQL protection, the displayed storage plus management rates give B × 730 × ($0.000061644 + $0.000068493) = B × $0.09500001 before transfer and policy effects. Retention policies determine B; this is not a fixed one-backup price. Source: [Backup and DR pricing](https://cloud.google.com/backup-disaster-recovery/pricing), storage and Cloud SQL management tables, checked 2026-11-05.

**Free-offer comparison:** no lasting Cloud SQL recurring free instance allowance established. An eligible $300 general trial credit could offset eligible usage during its 90-day term; allocation across other products and exclusions affect the out-of-pocket result. ### 4. Small vector search app

Inputs: PostgreSQL/pgvector, 100,000 vectors, 1536 float32 values/vector, 1 KiB metadata/vector, 100,000 searches, 10,000 updates/month and 5 GB internet egress.

Our raw-payload calculation: 100,000 × (1536 × 4 + 1024) = **716,800,000 bytes = 0.667572021484375 GiB**. The pgvector value itself also has an eight-byte header per vector: another 800,000 bytes. Table rows, indexes, WAL, free space and replicas add more. The 1536 dimensions fit pgvector's 2,000-dimensional float32 ANN index limit, but that does not prove RAM adequacy. Sources: [hosted extension versions](https://docs.cloud.google.com/sql/docs/postgres/extensions), [upstream pgvector storage/index reference](https://github.com/pgvector/pgvector), checked 2026-11-05.

**Result: incomplete.** For a chosen provisioned configuration the cost formula remains billed vCPU-hours + RAM GiB-hours + provisioned disk GiB-hours + backup GiB-hours + route-specific egress + any model use. The same ten-GiB/one-vCPU configuration would have the rates in example 1, but neither raw vector size nor search counts establishes adequate index memory/CPU. Embedding generation/reranking needs text volume, model, region and provider billing inputs; Cloud SQL storage does not include an unlimited model allowance. Model price-table unit wording remains unclear as recorded in V03. Sources: [Cloud SQL rates](https://cloud.google.com/sql/pricing?hl=en), [embedding integration](https://docs.cloud.google.com/sql/docs/postgres/generate-manage-vector-embeddings?hl=en), [model endpoints](https://docs.cloud.google.com/sql/docs/postgres/model-endpoint-overview), [model pricing](https://cloud.google.com/model-garden/pricing), checked 2026-11-05.

### 5. Small job workload

Inputs: 10,000 app jobs/month, 1 active second/job, 0.5 vCPU and 0.5 GB RAM per job, peak five concurrent jobs, no waiting/retries. Our resource arithmetic gives **5,000 vCPU-seconds and 5,000 GB-seconds**, before platform overhead. A variant with one retry on 10% of jobs gives 11,000 executions and 5,500 vCPU-seconds/5,500 GB-seconds. Waiting is unspecified and remains outside that variant.

**Result: not applicable as an all-in Cloud SQL job bill.** pg_cron schedules database SQL; it does not provide the specified arbitrary application-worker machine. Database SQL consumes an allocated running instance, while external worker execution, queue/orchestration, logging and transfer need separate pricing. No job fee is inferred by dividing the database price by seconds. Sources: [pg_cron and worker restrictions](https://docs.cloud.google.com/sql/docs/postgres/extensions), [Cloud SQL features](https://docs.cloud.google.com/sql/docs/postgres/features), [instance pricing](https://cloud.google.com/sql/pricing?hl=en), checked 2026-11-05.

### 6. Idle project

Inputs: retain the selected ten-GiB disk, one GB logical app data and **one GiB of retained on-demand backup** for 730 hours; zero app requests, jobs and transfer. A retained on-demand backup is assumed here so it does not roll off the ordinary automated-backup retention window.

- **Still running — our calculation:** $49.3115 compute + $1.7000021 disk + $0.07999997 backup = $51.09150207 → **$51.09**.
- **Manually stopped, retained idle public IPv4 — our calculation:** $0 compute + $1.7000021 disk + $0.07999997 backup + (730 × $0.01 IPv4) = $9.08000207 → **$9.08**.
- **Stopped with no billable idle IPv4 — our calculation:** disk + backup = $1.78000207 → **$1.78**, before any independently billed private endpoint, DNS, networking or other service. This is a conditional Cloud SQL subtotal, not an assertion that private infrastructure is free.

Stop/resume is manual; requests do not automatically wake the instance. Read replicas cannot simply use the NEVER stop policy. Product-trial expiry/grace/deletion rules differ from ordinary paid stop behavior. Sources: [start/stop](https://docs.cloud.google.com/sql/docs/postgres/start-stop-restart-instance), [pricing](https://cloud.google.com/sql/pricing?hl=en), [product trial](https://docs.cloud.google.com/sql/docs/postgres/free-trial-instance), all checked 2026-11-05.
