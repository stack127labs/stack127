# Bunny Database

**Lifecycle check — 2026-11-05:** Active **Public Preview**, launched February 3, 2026. Current [Database docs](https://bunny.net/docs/database) still say Preview, and the [SQL API](https://bunny.net/docs/database/connect/sql-api.md) has its own beta warning. No shutdown, sunset or acquisition notice was found in the inspected [product page](https://bunny.net/database/), [launch announcement](https://bunny.net/blog/meet-bunny-database-the-sql-service-that-just-works/), [changelog](https://bunny.net/docs/changelog) or [release-stage guide](https://bunny.net/docs/product-release-stages).

**Offer and recovery notes:** Database is currently free during Preview; the displayed usage schedule is separate from the platform's 14-day account trial. [Pricing](https://bunny.net/database/), [account trial rules](https://bunny.net/docs/faq.md). The [durability guide](https://bunny.net/docs/database/durability-and-consistency.md) warns that writes acknowledged on the primary can be lost during failover before their WAL batch reaches storage. It describes persistence every ten seconds or 4,096 changed-page frames, whichever comes first. Internal snapshots do not establish customer-controlled historical backup retention.

## Cost examples — our calculation

Checked **2026-11-05**. All amounts preserve the vendor's displayed **$** currency symbol; an explicit Database ISO currency code was not established. No conversion is made. [Taxation](https://bunny.net/docs/billing/taxation.md) says prices exclude tax.

**Current offer:** Database is free during Public Preview. There is no published end date or guaranteed lasting GA allowance in [product pricing](https://bunny.net/database/). The [14-day account trial](https://bunny.net/docs/faq.md) has separate credit/expiry rules; [trial-account disabling](https://bunny.net/docs/account/account-suspended.md) means a no-card trial account's continued Database access must not be assumed.

**Published-rate illustration:** The prices below show what the stated usage schedule would produce if charged. They are not a quote for a presently sold paid Database tier, or a promise of future GA rates. Full totals remain incomplete where transfer, account minimum or exact metering is unresolved.

### Inputs and formula

Use [Database pricing](https://bunny.net/database/), [launch pricing](https://bunny.net/blog/meet-bunny-database-the-sql-service-that-just-works/) and [Metrics](https://bunny.net/docs/database/metrics.md):

- Reads: `$0.30 × R / 1,000,000,000`, where **R is billed rows**, not SQL request count.
- Writes: `$0.30 × W / 1,000,000`, where **W is billed rows**, not SQL request count.
- Primary storage: `$0.10 × S` for **S GB retained for a full billed month**.
- Replica storage: `$0.10 × sum(S_i × active_month_fraction_i)`. A replica active for a full month has fraction one. The price page mentions hourly metering but does not publish the month-hour divisor/rounding needed for exact partial-month calculations.
- Known Database component formula: `$0.30R/10^9 + $0.30W/10^6 + $0.10S + replica storage`.
- Complete account total also needs any applicable `transfer + backup + external service charges + tax`. Unknown components are not set to zero.

[Add Funds](https://bunny.net/docs/billing/add-funds.md) states an account-wide $1 monthly floor when active zones exist. Its application to a Database-only free-preview account is unresolved. If it applies, with other qualifying usage **O** and Database charges **D**, the account expression would be `max($1, O + D)` before remaining charges/tax. Do not add another $1 for every database. If other usage already satisfies the floor, it would not create a second minimum for this database.

### 1. Small SQL app

Fixed inputs: one production database; 1 GB stored for the full month; 100,000 reads and 20,000 writes; ten peak connections; 5 GB internet transfer; 730 hours for an always-on comparison.

The [default maximum](https://bunny.net/docs/database/limits.md) is 1 GB/database. [Size metrics](https://bunny.net/docs/database/metrics.md) include indexes and metadata, so 1 GB of logical application payload is not proof of fit. Ten peak connections also cannot be compared with an unpublished concurrent-connection quota. No workload was run.

For an explicit illustration assume the measured total billed storage is **S=1 GB**, billed **R=100,000 rows**, **W=20,000 rows**, one primary and no active replica. This assumption is not derived from request counts:

`reads = 100,000/1,000,000,000 × $0.30 = $0.00003`

`writes = 20,000/1,000,000 × $0.30 = $0.006`

`primary storage = 1 × $0.10 = $0.10`

`known published-rate components = $0.10603/month`

That is **$0.11 rounded to cents**, but it is not an exact full bill. Transfer for the stated 5 GB, any account floor and other applicable meters remain unresolved. A SELECT returning/scanning many rows or writes maintaining indexes could change billed counts; the docs do not fully specify every case.

**Current Preview variant:** covered Database components are **$0** while the Preview waiver and account access apply. This does not prove an entirely free bunny.net account, permanent free production hosting or free external delivery.

**Replica/HA variant:** one 1-GB replica serving traffic for the full month would add `1 × $0.10 = $0.10` under the schedule, giving **$0.20603** known components (**$0.21 rounded**). Partial-month traffic needs the vendor's actual hourly proration. [Automatic primary failover](https://bunny.net/docs/database/durability-and-consistency.md) still permits loss of recently unuploaded WAL changes; replication is not a retained backup.

**Backup variant:** internal snapshots/WAL restoration are documented, but customer-retained backup/PITR terms and tariff were not established. No exact backup-inclusive total is available.

### 2. Full app backend

Inputs: the SQL workload plus 1,000 monthly active app users, 1 GB independent files, 100,000 file reads, 10,000 uploads, 20 GB internet transfer and 10,000 application-function calls. Define each function call as one active second at 0.5 GB memory, if the chosen host offers that allocation.

Formula: `Database + app authentication + independent file storage/requests + function host + delivery`.

[Database overview](https://bunny.net/docs/database) and its [Edge Scripting](https://bunny.net/docs/database/connect/scripting.md)/[Magic Containers](https://bunny.net/docs/database/connect/magic-containers.md) integrations do not supply a bundled MAU/file/function allowance. A server holding the Database token is also needed for safe end-user access. The database subtotal can follow scenario 1 if its assumptions hold; the **full backend total is unknown** until the other services and transfer route are chosen. No email/SMS charge or host allowance is silently assigned zero.

### 3. Small file store

Inputs: 100 GB average hot objects for a 30-day month, 100,000 writes, one million reads, 100 GB internet transfer; objects retained all month.

Formula: `object GB-months + object request/retrieval charges + delivery`.

This workload **does not fit Database alone**. [The SQL API](https://bunny.net/docs/database/connect/sql-api.md) and the [1-GB default database cap](https://bunny.net/docs/database/limits.md) do not establish an independent file-storage service. BLOB columns are database values, and their pricing cannot be substituted for Bunny Storage objects/CDN delivery. Public/private file access, multipart assumptions and a full total remain unknown until a separate object service is selected.

### 4. Small vector search app

Inputs: 100,000 vectors, each 1,536 float32 values plus 1 KiB metadata; 100,000 searches, 10,000 updates and 5 GB internet transfer.

Raw payload, **our calculation**:

`100,000 × (1,536 × 4 + 1,024) = 716,800,000 bytes = 0.7168 decimal GB`

1,536 dimensions fit the [65,536-dimension type limit](https://bunny.net/docs/database/sql-extensions/vector-search.md). Raw payload excludes vector headers, row/page/index overhead, build workspace, WAL, backups and replicas. It does not prove that the indexed dataset fits the 1-GB Preview quota. Support-request capacity increases have no published entitlement/price here.

A payload-only multiplication is `0.7168 × $0.10 = $0.07168/month`; **this is not the billed storage size or total**. SQL search counts do not establish billed R/W. For example, if measured billed counts were R=500,000 and W=10,000, their row components would be `500,000/10^9 × $0.30 + 10,000/10^6 × $0.30 = $0.00315`. That is an explicit hypothetical input, not an inference about ANN candidate visits or index updates.

Full formula: `billed database storage/rows + replicas/transfer + embedding/reranking provider`. Model/token inputs, complete index size and metering are unknown, so the **total is incomplete**. Current Preview can waive covered Database components, but there is no established general embedding/reranking budget.

### 5. Small job workload and retry/wait variant

Inputs: 10,000 one-second jobs; requested 0.5 vCPU/0.5 GB where a host offers it; peak five concurrent; no retries/waiting in the base case.

`active work = 10,000 × 1 = 10,000 aggregate seconds`

[Database](https://bunny.net/docs/database) executes SQL, while external application logic needs a host. Its migrations and transactions do not establish a managed queue/worker allowance.

Formula: `chosen worker host + orchestration/retries + database row/storage work + logs + transfer`. Without an identified host/runtime and measured database work, the **total is unknown**. No Database job invocation or vCPU tariff is invented.

Retry/wait variant: if 10% of jobs execute one extra one-second attempt and each original job waits five seconds:

`active = 10,000 + 1,000 = 11,000 seconds`

`waiting = 10,000 × 5 = 50,000 seconds`

Combined aggregate is **61,000 seconds**, not elapsed uptime. Whether waiting/retries cost money depends on the external host. Repeated SQL writes can add billed rows and duplicate side effects unless the application prevents them.

### 6. Idle project

Inputs: same retained 1 GB total database size, zero user requests and zero jobs for the month; no traffic-serving replica.

At the published schedule:

`read/write components = $0`

`retained primary storage = 1 GB × $0.10/GB-month = $0.10/month`

This is a **known storage component**, not an all-in idle account total. An applicable account-wide minimum could raise the bill; its Database-only scope is unresolved. [Idle compute](https://bunny.net/docs/database/replication.md) moves to object storage, but the [pricing rule](https://bunny.net/database/) still charges one primary's storage continuously.

**Current free-preview case:** covered Database storage/operation components are **$0** while eligible and accessible. The unspecified idle threshold is not a documented deletion timer. An expired trial, nonpayment or account termination follows separate account policies.

[Negative Balance](https://bunny.net/docs/billing/negative-balance.md) explicitly says Database storage can continue accruing while services are disabled. An empty credit balance is therefore not a dependable dollar cap or a substitute for deleting unwanted resources.
