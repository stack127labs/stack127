## Cost examples — our calculations

Checked **2026-11-05**. Region **US East (N. Virginia), us-east-1**; currency **USD**, before taxes and account credits. These are **our calculations**, not AWS quotes or measured performance. Rates come from the Vectors-specific regional SKUs, published **2026-11-04**, effective **2026-10-01**. The pricing page defines **1 GB = 2^30 bytes** and **1 TB = 1024 GB**. Its displayed processing prices are rounded TB values; arithmetic below uses the full price-list GB values.

### Small vector workload: explicit inputs

Required workload: 100000 vectors, 1536 float32 values/vector, 1 KiB metadata/vector, 100000 searches, 10000 updates/month and 5 GB internet transfer.

Additional assumptions for this calculation:

- One existing vector index with a stable 100000-vector live population, retained for a full month.
- Unique **32-character ASCII keys**: 32 logical key bytes/vector.
- All **1024 metadata bytes/vector are filterable**. This fits the native 2 KB filterable-metadata limit; a different split changes processing charges.
- Each query fits one response page, with **topK 10**, metadata returned, and all ten results present. GetVectors/ListVectors/control-plane calls are excluded unless separately shown.
- Updates overwrite existing same-size records. Uploads are batched at up to **500 vectors/PUT**, provided the serialized request fits **20 MiB**.
- No optional KMS key, PrivateLink endpoint, paid support package, CloudTrail data-event trail, embedding model or OpenSearch resource is priced into the native subtotal.
- The 5 GB internet-transfer requirement remains an **unpriced extra** because an explicit vector-specific route/allowance mapping was not established. Returned-data charges below are a different meter from internet transfer.

Sources: [current vector limits](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-limitations.html), [float32 input](https://docs.aws.amazon.com/AmazonS3/latest/API/API_S3VectorBuckets_PutVectors.html), [vector key constraints](https://docs.aws.amazon.com/AmazonS3/latest/API/API_S3VectorBuckets_PutInputVector.html), [returned metadata/API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_S3VectorBuckets_QueryVectors.html), [regional rates](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/us-east-1/index.json), [meter definitions/units](https://aws.amazon.com/s3/pricing/).

### Raw logical bytes and recurring known components

Our calculations:

- Vector bytes = 100000 × 1536 × 4 = **614400000 bytes**.
- Metadata bytes = 100000 × 1024 = **102400000 bytes**.
- Key bytes = 100000 × 32 = **3200000 bytes**.
- Total logical data = **720000000 bytes**; ÷ 1073741824 = **0.6705522537231445 priced GB**.
- Per vector = **7200 logical bytes**. This is not its JSON request/response wire size or a measured physical ANN-index footprint.

| Component | Our formula | Result, USD |
| --- | --- | ---: |
| Full-month logical storage | 0.6705522537231445 GB × 0.0600000000/GB-month | 0.04023314 |
| 10000 batched updates | (10000 × 7200 ÷ 2^30) GB × 0.2000000000/GB | 0.01341105 |
| 100000 query API requests | 100000 × 0.0000025000/request | 0.25000000 |
| Query processing, first 100000-vector tier | 100000 queries × (100000 × 7200 ÷ 2^30) GB/query × 0.0000039060/GB | 0.26191771 |
| Query returned-data meter | 10 × max(256, 32 + 1024) = 10560 bytes/query; below both published 500/512 KB thresholds | 0.00000000 |
| **Known recurring component subtotal** | Sum using unrounded values | **0.56556189** |

Results are rounded to **eight decimal places for display**; no final invoice-cent rounding is assumed. This subtotal excludes internet transfer, embeddings/reranking, optional resources, any extra management/GET/LIST calls and transient overwrite/reclamation effects. **The all-in monthly total is incomplete.**

The processing fee is based on the full applicable logical index size, not merely the ten returned matches. A selective metadata filter is not assumed to lower that index-size meter. ### Initial upload and batch-size variant

An initial complete upload is separate from recurring updates:

- **200 batches of 500** vectors: 720000000 logical bytes ÷ 2^30 × USD 0.20/GB = **USD 0.13411045**, rounded to eight decimals. Each batch's 3600000 logical bytes exceeds the 128 KB minimum; actual serialized-body limits still apply.
- Known first-month native components = recurring subtotal + initial upload = **USD 0.69967234**, with the same exclusions and transient-size caveat.
- **Unbatched update variant:** 10000 single-vector PUTs each fall below 128 KB. Using 128 × 1024 bytes/request explicitly, billed upload = 10000 × 131072 ÷ 2^30 GB; × USD 0.20 = **USD 0.244140625**.
- **Unbatched initial-load variant:** 100000 × 131072 ÷ 2^30 × USD 0.20 = **USD 2.44140625**.
- Extra GET/LIST/other operations, when needed, cost **request count ÷ 1000 × USD 0.055** in this region. They are not charged at regular S3 Standard request rates. No unspecified monthly request count is invented.

The main pricing text labels the minimum 128 KB; this calculation explicitly interprets it as **131072 bytes**, consistent with the page's binary unit convention. ### Metadata, overwrite and result-size qualifications

- If all 1 KiB metadata is instead designated **non-filterable**, total logical storage and PUT bytes remain the same. Processing bytes/vector become 6144 + 32 = **6176**. Our processing calculation is 100000 × (100000 × 6176 ÷ 2^30) × 0.0000039060 = **USD 0.22466719**, rounded to eight decimals. Those metadata fields then cannot be used in query filters.
- Overwritten/deleted data can remain in billed index storage for **up to a day**. The steady live-population table above excludes those transient retained bytes and their effect on processing tiers. Actual update timing and reclamation are needed for an exact bill; there is no silent zero-charge assumption.
- Larger topK/returned metadata can add data-returned fees and pagination. General formula: sum over queries of max(0, sum over returned results of max(256 bytes, logical key + returned metadata bytes) − applicable free threshold) ÷ 2^30 × USD 0.01. The page disagrees between **512 KB** and **500 KB**; the ten-result baseline avoids that boundary. Request-page behavior must also be considered when budgeting a larger query.
- No embedding/reranking total is possible without the selected model, token/image volume and provider usage rates. Bedrock/OpenSearch resources remain separate.

Sources: [processing/reclamation/returned-data rules](https://aws.amazon.com/s3/pricing/), [non-filterable metadata](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-indexes.html), [pagination](https://docs.aws.amazon.com/AmazonS3/latest/API/API_S3VectorBuckets_QueryVectors.html), [integration boundaries](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-bedrock-kb.html), [exported OpenSearch collection](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/s3-opensearch-vector-bucket-integration.html).
