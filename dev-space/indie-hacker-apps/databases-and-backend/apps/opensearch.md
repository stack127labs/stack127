## Conflicts and unknowns

- Release status: GitHub and version history show 3.9.0, while the official release schedule's status table still says 3.7.0 is current and 2.19.6 is the latest 2.x. I recorded this as one conflict and used the current release pages for latest versions.
- gRPC status: The general API reference broadly calls the gRPC subset experimental, while the detailed gRPC page marks Bulk and k-NN generally available since 3.2 and other gRPC search functions experimental. I recorded the difference and followed the operation-specific page.
- Hosted services: I checked AWS OpenSearch Service's FAQ, Serverless docs, and pricing page, plus the official Aiven provider page. Those are separate services with their own prices, features, regions, terms, and support; no hosted plan figures are used as facts about self-hosted OpenSearch.
- Transactions: I checked document APIs, Bulk API, Query DSL, API reference, and FAQ. They document per-document concurrency and refresh, but I did not find a multi-document ACID transaction or rollback guarantee.
- Connection and record ceilings: I checked networking, index settings, cluster settings, vector mappings, and API reference. The docs publish request, vector, mapping, pagination, and shard bounds, but not a universal connection, document-count, or single-document byte ceiling.
- Runtime compatibility: I checked the official client list, API reference, and product overview. They list server-oriented clients and APIs but no universal browser, edge, or serverless-runtime support matrix.
- Hardware sizing: I checked installation, OS compatibility, cluster-tuning, and benchmark docs. They recommend storage and give setup guidance but no universal RAM/CPU budget for a production workload.
- Terms and privacy: I checked the Apache license, project FAQ, trademark policy, Foundation pages, official site search, and community forum legal pages. Direct OpenSearch site paths `/terms/`, `/privacy-policy/`, and `/privacy/` were not accessible through the research tool. The accessible forum terms explicitly apply only to forum use, and the forum privacy page links to the Linux Foundation privacy policy; neither is a policy for the self-hosted engine. No separate self-hosted product terms or privacy policy surfaced. Hosted-provider terms do not apply to it.
- Company and newsroom check: I checked the official OpenSearch blog, News, Announcements, release policy, and GitHub releases for acquisition, shutdown, sunset, or retirement. No such notice surfaced. The current Foundation governance and release stream are active.
- Nothing here treats a missing mention as proof that a capability or policy does not exist.

## Field problems

- OpenSearch has no single first-party hosted plan. AWS OpenSearch Service and Aiven for OpenSearch are named only as examples of independent managed products; their prices and limits need separate records.
- OpenSearch is document-oriented. Its SQL plugin is a query interface, not a relational storage engine or transaction guarantee.
- The file-storage and job-runner groups do not apply to the search database itself. Internal snapshots, maintenance tasks, and server logs are not user file storage, queues, or hosted run history.
- The official release schedule has a stale status table even though its release history and GitHub releases are current. The latest-release facts and the conflict are both recorded.
