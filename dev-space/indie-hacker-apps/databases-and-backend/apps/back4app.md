## Cost examples — our calculation

Checked date: 2026-11-04. All dollar figures retain the pricing page's $ notation. These are our calculations, not vendor quotes. Region: USA, using the standard managed MongoDB backend; no Enterprise, PostgreSQL, own-bucket or separate Container/Agent subscription. Annual commitment is explicit. Taxes, external email/SMS/model services and any custom work are excluded. No workload was run.

Inputs shared by the examples: [annual plans, allowances and overages](https://www.back4app.com/pricing/backend-as-a-service), [API-request definition](https://help.back4app.com/hc/en-us/articles/115001377071-What-is-an-API-request), [operation examples](https://help.back4app.com/hc/en-us/articles/115001377872-What-operations-are-counted-as-API-requests). These inputs were checked on 2026-11-04. The formula uses whole published overage blocks where a numeric overage is shown; fractional-block billing is unknown.

1. **Small document app — subscription subtotal, capacity fit incomplete.** Inputs: one app, 1GB database all month, 100,000 reads, 20,000 writes, ten peak connections, 5GB internet transfer and 730 hours retained. Assume each read/write is one API call, no batching, extra queries or dashboard traffic. R = 100,000 + 20,000 = 120,000. Free fails both database and request allowances. MVP's quoted pools cover 1GB, 120,000 requests and 5GB. Formula: $15 base + $0 quoted overage = **$15/month equivalent, $180/year base commitment** (15 × 12). No separate hourly charge is published. A ten-connection guarantee and CPU requirement cannot be validated, so this is not a proven all-in workload quote. Daily seven-day snapshots are the included backup variant; Dedicated/PITR or a defined high-availability topology requires separate pricing. [Backup scope](https://help.back4app.com/hc/en-us/articles/115001377111-What-is-the-backup-and-data-ownership-policy), checked 2026-11-04.

2. **Full app backend — conditional subscription subtotal.** Inputs: the small database workload plus 1,000 MAU, 1GB files, 100,000 file reads, 10,000 uploads, 20GB total internet transfer and 10,000 one-second function calls. Requested function memory: 0.5GB; Back4app does not publish a matching per-call allocation. Assume one login per MAU, one API upload per file, no extra internal function queries, database writes already include file-reference rows, and at most one metered request per file read. R = 120,000 + 1,000 + 10,000 + 10,000 + X, with X = 0 or 100,000 depending on CDN request accounting: **141,000–241,000 requests**. Both cases fit MVP's request pool; files and 20GB transfer fit too. Formula: $15 + $0 stated overages = **$15/month equivalent, $180/year base**, conditional on those assumptions. Free cannot hold the 1GB database. No distinct MAU rate is published, but user records/auth calls consume normal resources. This is incomplete for guaranteed memory/concurrency and external delivery services. [Function timeout/runtime capability](https://www.back4app.com/features/cloud-functions), checked 2026-11-04.

3. **Small file store — incomplete total with two explicit accounting cases.** Inputs: 100GB hot files throughout a 30-day month, 100,000 single-POST uploads, 1,000,000 direct public file reads, 100GB total internet transfer; every file below the documented 20MB cap and retained all month. Assume associated metadata stays within MVP's database pool and no extra listing/row requests. Free fails storage, transfer and upload request allowances. File excess: (100 − 50)GB ÷ 10GB × $1 = **$5**; transfer stays within 250GB. Case A, only uploads count: R = 100,000, so **$15 + $5 = $20/month equivalent**. Case B, every download also counts: R = 1,100,000; excess (1,100,000 − 500,000) ÷ 100,000 × $5 = **$30**; subtotal **$50/month equivalent**. These are conditional examples, not a guaranteed $20–$50 bill range: CDN accounting, additional metadata operations, partial-month measurement and private delivery remain unresolved. Annual base commitment $180; usage extras shown for one month. [Public delivery and upload cap](https://www.back4app.com/features/storage), checked 2026-11-04.

4. **Small vector search app — no defensible service total.** Inputs: 100,000 vectors × 1,536 float32 values, 1KiB metadata each, 100,000 searches, 10,000 updates and 5GB transfer. Raw payload calculation: 100,000 × ((1,536 × 4) + 1,024) = **716,800,000 bytes**. This is raw vector/metadata payload, not MongoDB document, BSON or index usage. No conversion into vendor GB is used to assert plan fit. Total formula: subscription + billed database/index bytes + request usage + transfer + embedding/reranking service + any required native search configuration. HNSW setup, plan access, overhead and model rates are unresolved, so **total unknown**. An array-field storage claim is insufficient to price similarity search. [Vector product claims and illustrative helper](https://www.back4app.com/glossary/vector-database-embeddings), checked 2026-11-04.

5. **Small job workload — request-only subtotal, compute fit incomplete.** Inputs: 10,000 jobs/month, one second active each, requested 0.5vCPU/0.5GB and peak five concurrent; no waits or retries. 6. **Idle backend — fixed base remains.** Retain the full-backend example's 1GB database and 1GB files for a month; zero API requests, zero function/job runs and zero transfer.
