**Storage-unit assumption:** the scalability FAQ states a minimum 10 GiB volume. The billing guide calls storage GiB/month, while pricing and the catalog label the rate GB-month. For the numerical examples, we interpret ten GiB as ten of AWS's billed storage units, following the billing guide. Thus the assumed minimum storage line is `10 × $0.10 = $1.00/month` Standard or `10 × $0.225 = $2.25/month` I/O-Optimized. This interpretation is explicit and remains a source-unit conflict, not a silent decimal/binary conversion. If the invoice uses a different unit definition, replace ten with actual billed usage. The restricted Free plan's 1 GB/GiB ceiling is a separate offer.

### 1. Small SQL app

Inputs: one production database, 1 GB logical data for a month, 100,000 reads, 20,000 writes, ten peak connections and 5 GB internet-out. Native-driver access avoids Data API/Secrets Manager fees in this variant. Logical data is not the whole physical volume.

| Conditional configuration | Formula | Result and missing costs |
| --- | --- | --- |
| Provisioned Standard t4g.medium, one writer | `730 × $0.073 + 10 × $0.10` | **$54.29** conditional compute/storage subtotal: $53.29 compute + $1.00 storage. Add physical I/O and any surplus CPU credits. This does not establish workload throughput or response time. |
| Serverless Standard, one writer held at 0.5 ACU all month | `730 × 0.5 × $0.12 + 10 × $0.10` | **$44.80** conditional subtotal: $43.80 compute + $1.00 storage. Autoscaling above 0.5 increases it; physical I/O remains unknown. |
| Serverless I/O-Optimized, same constant 0.5 ACU assumption | `730 × 0.5 × $0.16 + 10 × $0.225` | **$60.65** conditional compute/storage subtotal. Read/write I/O is included; performance/capacity sufficiency is still unknown. |
| Provisioned Standard with same-sized reader in another AZ | `2 × 730 × $0.073 + 10 × $0.10` | **$107.58** conditional compute/shared-storage subtotal. Add I/O/CPU credits. Storage is not doubled for the reader. |

For Standard, let `Q` be actual billable storage I/Os: `I/O cost = Q / 1,000,000 × $0.20`. A sensitivity case of **120,000 physical I/Os** costs **$0.024**. This is not an assertion that 120,000 SQL reads/writes cause 120,000 I/Os: cache hits, pages, indexes and write logging change that relationship. Pricing's worked storage example uses data-page reads and write-page operations, not one charge per SQL query.

The 5 GB internet-out line is $0 **only if** at least 5 GB of the shared 100 GB allowance remains and the route qualifies. If other AWS services consume it, the paid-transfer line is unresolved. Same-AZ application placement avoids the documented cross-AZ application-transfer meter; other network infrastructure may bill separately.

Backups variant: with excess retained backup usage `B` GB-month above the applicable allowance, add `B × $0.021`. For example, an explicitly assumed ten excess billed GB-month adds **$0.21**. Restoring creates additional resources. HA, backup excess and transfer should not be silently folded into a base single-writer price.

Free comparison: an eligible new-customer Aurora PostgreSQL express cluster can be credit-funded within its 4 ACU and two-cluster/two-instance account restrictions. The 1 GB/GiB data ceiling leaves no demonstrated room for 1 GB logical app data plus engine/index overhead. There is therefore no confirmed free fit for the full SQL scenario. Credits can offset eligible paid-plan usage while valid, but are temporary and their expiry wording conflicts.

### 4. Small vector search app

Inputs: 100,000 vectors, 1,536 float32 values each, 1 KiB metadata each, 100,000 searches, 10,000 updates and 5 GB internet-out.

Our raw-payload calculation:
- Vector values: `100,000 × 1,536 × 4 = 614,400,000 bytes`.
- Metadata: `100,000 × 1,024 = 102,400,000 bytes`.
- Combined raw input: **716,800,000 bytes**. This excludes row headers, identifiers, text, vector-type headers, indexes, free space, replicas and backups.

A 1,536-dimension HNSW vector fits the ordinary 2,000-indexed-dimension case in the [AWS vector guide](https://docs.aws.amazon.com/decision-guides/latest/decision-guides/vector-database-guide.html); [Aurora's Bedrock setup](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraPostgreSQL.VectorDB.html) shows that dimension and HNSW/text/metadata indexes. Checked 2026-11-04.

Formula: `measured ACU-hours × $0.12 + billed Standard storage units × $0.10 + actual physical I/Os / 1,000,000 × $0.20 + backup excess + transfer + external model/reranking costs`. I/O-Optimized substitutes $0.16/ACU-hour and $0.225/storage unit-month and removes ordinary read/write I/O charges.

**Result: incomplete.** The same conditional $44.80 constant-0.5-ACU Standard subtotal could illustrate a retained small cluster, but is not a demonstrated vector workload fit. Index size and compute per search/update are unknown; do not price only the raw 716,800,000 bytes. Embedding generation/reranking requires a model and adds another bill.

### 5. Small job workload

Inputs: 10,000 jobs, one active second each, target 0.5 vCPU/0.5 GB RAM, peak five jobs, no retry/wait in the base case.

Our activity calculation is `10,000 × 1 = 10,000 job-seconds`. With 10% of jobs retried once, `11,000 × 1 = 11,000 job-seconds`. If every job waits ten seconds, that adds `10,000 × 10 = 100,000 waiting job-seconds`. These are sums over jobs, not elapsed cluster time or ACU-seconds.

**Result: incomplete and not a general-worker machine match.** pg_cron and the MySQL Event Scheduler run SQL inside the database. One ACU has approximately 2 GiB memory with corresponding CPU, so neither a fixed vCPU conversion nor a dedicated 0.5 vCPU/0.5 GB worker can be inferred. Billing formula is `actual cluster ACU-hours × regional ACU rate + stored data + physical I/O + logs + any external scheduler/worker`, not `job-seconds × a made-up vCPU rate`.

[pg_cron](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/PostgreSQL_pg_cron.html) defaults to five concurrent jobs but needs sufficient background-worker slots. [Auto-pause](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2-auto-pause.html) skips due schedules while paused and can cancel running jobs; a job definition does not wake the database. An external scheduled connection/function can wake it, with separate compute and retention behavior. Connections or retries can prolong billed capacity. Sources checked 2026-11-04.
