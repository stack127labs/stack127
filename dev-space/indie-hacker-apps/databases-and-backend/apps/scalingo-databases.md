## Lifecycle and access notices

- **Sandbox retirement:** no new Sandbox databases from March 2, 2026; requests select the smallest paid Starter plan, and existing instances are being migrated. Old “free plan” wording on engine pages must not be treated as a current lasting free tier. Source: https://doc.scalingo.com/changelog (March 1, 2026 entry; checked 2026-11-05).
- **PostgreSQL 14:** support ends November 12, 2026; forced upgrade to PostgreSQL 15 is scheduled for January 11, 2027. Source: https://doc.scalingo.com/changelog (June 9 PostgreSQL notice; checked 2026-11-05).
- **MySQL 8.0:** support ended April 30, 2026; a forced-upgrade campaign to 8.4 was announced for October 12, 2026. The overview still lists 8.0, so this research does not claim the campaign has completed for every instance. Sources: https://doc.scalingo.com/changelog and https://doc.scalingo.com/databases/mysql/about/overview (lifecycle/versions; checked 2026-11-05).
- **Caching naming:** Scalingo for Redis was renamed Scalingo for Caching. Redis OSS versions remain in its Start guide, while newer backup docs refer to Valkey. The exact migration coverage remains unclear. Sources: https://doc.scalingo.com/databases/redis/start, https://doc.scalingo.com/databases/about/backup-policies and https://doc.scalingo.com/changelog (checked 2026-11-05).
- **Restricted editions:** Dedicated Resources PostgreSQL is not generally available and requires selected-customer access. Enterprise is also restricted. Sources: https://doc.scalingo.com/databases/about/architecture-models and https://doc.scalingo.com/databases/about/service-classes (checked 2026-11-05).
- The lifecycle-first check of official product pages, changelog and targeted shutdown/sunset/acquisition searches did not identify a retirement of the whole Scalingo database portfolio or a company-acquisition notice. This is a bounded search result, not a guarantee about future availability. Sources: https://scalingo.com/databases and https://doc.scalingo.com/changelog (checked 2026-11-05).

### Small vector search app

Inputs: **100,000 vectors × 1,536 float32 dimensions**, **1 KiB metadata/vector**, **100,000 searches**, **10,000 updates** and **5 GB Internet transfer**. A 1,536-dimension vector fits the documented 2,000-dimension standard pgvector ANN index limit.

Our calculation of a lower-level data component:

- Raw float32 elements: 100,000 × 1,536 × 4 = **614,400,000 bytes**.
- pgvector's documented 8-byte overhead/vector: 100,000 × 8 = **800,000 bytes**.
- Metadata: 100,000 × 1,024 = **102,400,000 bytes**.
- Combined vector values plus stated metadata = **717,600,000 bytes = 0.7176 decimal GB**, using 1 GB = 1,000,000,000 bytes. This is **not** physical billed disk: table rows, indexes, update/dead-row space and other database contents add storage.

The Starter base component remains €7.30 only **if** the actual RAM/CPU/disk needs fit that plan. The index's working memory and the workload's query cost cannot be inferred from raw bytes. **An exact suitable-plan total is unknown.** Embedding generation and reranking are external costs with no chosen model/rate; no model fee is invented.
