## Cost examples — our calculation

Checked **2026-11-05**. PostgreSQL's software license permits use without a fee. It does **not** publish a hosted compute/storage plan. No host, country/region, hardware, electricity price, backup store, transfer route or paid support contract has been selected. Therefore **no all-in monthly amount or currency can be supported**. Hosted-plan fields were marked not applicable, as requested; no hosted tariffs were searched. [PostgreSQL License](https://www.postgresql.org/about/licence/), grant; [Architectural Fundamentals](https://www.postgresql.org/docs/18/tutorial-arch.html), operator-run server; checked 2026-11-05.

For applicable cases, our calculation is:

`core software license fee = 0`

`total = allocated server/compute + persistent storage + backup/archive storage + transfer + optional external services/support + operating work`

The zero is a **software license fee**, not a zero monthly operating bill. Rates for the other terms are unknown. There is no expiring trial or free quota to subtract from a paid hosted path. With existing hardware, cash costs can differ from a new rented server; neither is guessed. [License](https://www.postgresql.org/about/licence/), checked 2026-11-05.

### 1. Small production SQL app

Inputs: **one production database**, **1 GB data**, **100,000 reads**, **20,000 writes**, **10 peak connections**, **5 GB internet transfer**, and **730 running hours**. **Our calculation: zero core license fee; operating total incomplete.** Query counts do not determine server CPU, memory, I/O, index size or WAL/archive growth. The 1 GB logical dataset is not the total disk allocation. The default connection ceiling is typically 100, but actual settings/reserved slots and resources must be checked before accepting the workload. [Connection settings](https://www.postgresql.org/docs/18/runtime-config-connection.html), [hard limits](https://www.postgresql.org/docs/18/limits.html), checked 2026-11-05.

**Backup variant:** add scheduled dumps or a base-backup/WAL archive, retained storage and restore testing. **HA variant:** add standby server/storage, replication traffic and failure detection/coordination; another licensed copy still has no PostgreSQL license fee. No fixed retained days, replica tariff or recovery time is supplied by the core project. [Backup and Restore](https://www.postgresql.org/docs/18/backup.html), [PITR](https://www.postgresql.org/docs/18/continuous-archiving.html), [Failover](https://www.postgresql.org/docs/18/warm-standby-failover.html); checked 2026-11-05.

### 2. Full app backend

Inputs: the SQL case plus **1,000 monthly active users**, **1 GB files**, **100,000 file reads**, **10,000 uploads**, **20 GB total internet transfer**, and **10,000 function calls**, each **1 second at 0.5 vCPU and 0.5 GB RAM**. Requested active function resources are `10,000 × 1 × 0.5 = 5,000 vCPU-seconds` and **5,000 GB-seconds**.

**Our calculation: zero PostgreSQL core license fee plus unknown database infrastructure, application authentication, upload/delivery, worker resources, and email/SMS costs. Total incomplete.** Database roles and procedural functions do not constitute a hosted full-backend package. The 20 GB is total application traffic, not an extra 20 GB added to the original 5 GB database traffic. [Database architecture](https://www.postgresql.org/docs/18/tutorial-arch.html), [core capabilities](https://www.postgresql.org/about/), [License](https://www.postgresql.org/about/licence/); checked 2026-11-05.

### 3. Small file store

Inputs: **100 GB average hot files for 30 days**, **100,000 writes**, **1 million reads**, **100 GB internet transfer**, files retained for the month. **Our calculation: not applicable as a standalone managed file-store comparison.** PostgreSQL can store binary values, but that does not supply an object bucket, resumable upload service, signed file delivery or a sourced storage tariff. An application using database-backed files would need database sizing and a separate upload/delivery design; no exact total follows from these inputs. [Object-relational server scope](https://www.postgresql.org/docs/18/intro-whatis.html), [field/size limits](https://www.postgresql.org/docs/18/limits.html); checked 2026-11-05.

### 4. Small vector search app

Inputs: **100,000 vectors**, **1,536 float32 values each**, **1 KiB metadata each**, **100,000 searches**, **10,000 updates**, **5 GB transfer**.

Our raw-payload calculation: `100,000 × (1,536 × 4 + 1,024) = 716,800,000 bytes`.

This excludes vector headers, row/TOAST overhead, indexes, build space, WAL, replicas and backups. It is **not billed index size**. Optional pgvector v0.8.5 supports this dimension count for vector HNSW/IVFFlat indexing, but resource/recall targets and actual index space still need sizing.

**Our calculation: zero core PostgreSQL license fee; total incomplete for server/storage, the installed extension environment and embedding/reranking compute or provider fees.** No semantic model call allowance is bundled into the license. [pgvector v0.8.5 README](https://raw.githubusercontent.com/pgvector/pgvector/v0.8.5/README.md), Installation, Indexing, Filtering and Hybrid Search; [PostgreSQL License](https://www.postgresql.org/about/licence/); checked 2026-11-05.

### 5. Small job workload and retry/wait variant

Inputs: **10,000 jobs**, **1 active second**, **0.5 vCPU and 0.5 GB RAM each**, **peak 5 concurrent**, no base retries/wait. Our requested-resource calculation gives **10,000 active seconds**, **5,000 vCPU-seconds**, **5,000 GB-seconds**, and **2.5 vCPUs/2.5 GB RAM** at the specified peak.

Optional pg_cron schedules SQL that shares the database's resources. Its configurable concurrency default of 32 is not a reservation of these per-job machine resources. **Our calculation: zero core license fee; no exact all-in job execution total.** Choose and price appropriate database/extension resources for SQL jobs, or general workers for application-code jobs. No invocation/wait tariff is supplied by PostgreSQL. [pg_cron v1.6.7 README](https://raw.githubusercontent.com/citusdata/pg_cron/v1.6.7/README.md), execution/settings; [License](https://www.postgresql.org/about/licence/); checked 2026-11-05.

Variant: one additional 1-second attempt for **1,000 jobs** gives **11,000 active seconds**, **5,500 vCPU-seconds**, **5,500 GB-seconds** at the input resource shape. A **60-second wait each** adds **60,000 elapsed waiting seconds**. This does not establish automated retry support or priced worker idle time; those depend on implementation and infrastructure. Same sources and checked date.

### 6. Idle project

Inputs: **same 1 GB logical data**, zero queries/jobs, retained for **730 hours**. **Our calculation: zero software license fee, with retained compute/storage/backups and operations costs unknown.** Stopping PostgreSQL can stop query execution, but does not itself stop an external machine's rental or remove persistent disks/backups. A clean stop is not an automatic wake-on-request service.
