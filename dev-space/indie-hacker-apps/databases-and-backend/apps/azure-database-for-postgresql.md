# Azure Database for PostgreSQL

## Shutdown, sunset and acquisition check

Checked first on 2026-11-05. [Flexible Server is currently offered](https://azure.microsoft.com/en-us/products/postgresql) with a public [creation guide](https://learn.microsoft.com/en-us/azure/postgresql/configure-maintain/quickstart-create-server). No acquisition or complete Flexible Server shutdown notice was found in the inspected official product, pricing and lifecycle pages. This is a bounded notice check, not measured availability or a guarantee about future operation.

- **Single Server retired March 28, 2025.** Scheduled vaulted backups for that deployment stopped; retained recovery points still have storage fees. Flexible Server is the current deployment in this record. [Official retirement/backup changes](https://learn.microsoft.com/en-us/azure/backup/backup-azure-database-postgresql-overview#changes-to-vaulted-backups-for-postgresql-single-servers) (checked 2026-11-05).
- **Azure Cosmos DB for PostgreSQL, formerly Hyperscale (Citus), is on a retirement path and is not recommended for new projects.** Microsoft directs PostgreSQL workloads to Azure Database for PostgreSQL Elastic Clusters. A final shutdown date was not established in this research. [Official product-updates notice](https://learn.microsoft.com/en-us/azure/cosmos-db/postgresql/product-updates) (checked 2026-11-05).
- **PG11–13 are in paid Extended Support.** Azure standard support ended July 31, 2026; enrollment began August 1, with billing from September 1 after the grace month. PG11/12/13 Extended Support ends March 31, 2027 / November 13, 2027 / November 12, 2028 respectively. PG14 standard support ends January 31, 2027, followed by Extended Support through November 11, 2029. [Version policy](https://learn.microsoft.com/en-us/azure/postgresql/configure-maintain/concepts-version-policy), [Extended Support](https://learn.microsoft.com/en-us/azure/postgresql/configure-maintain/extended-support) (checked 2026-11-05).
- **azure_local_ai is retired.** The page’s opening notice says it is no longer supported or maintained. The old Preview description remains below it; no effective calendar date appears in the warning. The named alternative is remote `azure_ai` integration. [Local AI retirement notice](https://learn.microsoft.com/en-us/azure/postgresql/extensions/azure-local-ai) (checked 2026-11-05).

## Cost examples — our calculation

Checked 2026-11-05. These are our calculations from published prices, not vendor quotes or benchmark results. Region: **East US (`eastus`)**. Currency: **USD**, before tax, ordinary consumption pricing, 730 hours if always on.

### Rates and assumptions

The [public Retail Prices API query](https://prices.azure.com/api/retail/prices?%24filter=serviceName+eq+%27Azure+Database+for+PostgreSQL%27+and+armRegionName+eq+%27eastus%27+and+priceType+eq+%27Consumption%27&currencyCode=%27USD%27) returned 147 records on one page. Retired Single Server, Azure Cosmos DB for PostgreSQL, and HorizonDB meters were excluded. The API still contains all those product names; membership in the same service-name filter does not make them this offer.

For a production-oriented resource example, choose documented **General Purpose D2ds_v5**, 2 vCores/8 GiB RAM, and **32 GiB Premium SSD v2** on a supported GA PostgreSQL version such as 17. [Compute specifications](https://learn.microsoft.com/en-us/azure/postgresql/compute-storage/concepts-compute), [SSD v2 eligibility](https://learn.microsoft.com/en-us/azure/postgresql/compute-storage/concepts-storage-premium-ssd-v2) and [pricing configuration/billing FAQ](https://azure.microsoft.com/en-us/pricing/details/postgresql/flexible-server/) supply the constraints.

- API Standard_D2ds_v5/2-vCore meter: **$0.178 per server-hour**. This particular meter prices the complete SKU. The older Ddsv4 vCore meter is $0.089 **per vCore-hour**; these are different meter shapes.
- Premium SSD v2: **$0.115/GiB-month**, meter `c300bb4b-f148-5138-b081-2a72643c5ed0`. At 32 GiB, 3,000 disk IOPS and 125 MB/s disk throughput are included. The selected host has its own performance ceiling.
- Beyond included v2 performance, add `extra provisioned IOPS × $0.02/IOPS-month + extra provisioned MB/s × $0.08/MB/s-month`. These are configured performance charges, not a price per logical SELECT or physical read.
- Assume no HA/read replica, Autonomous Tuning, external AI calls, extra private-network resources or paid support in the base case. Use default native backup retention and assume backup usage stays within its included primary-capacity allowance. Actual backup volume depends on changes and WAL.
- Internet transfer uses the [Microsoft Premium Global Network table](https://azure.microsoft.com/en-us/pricing/details/bandwidth/): first 100 GB/month free, then $0.087/GB in the next 10 TB from North America/Europe. The allowance is shared beyond this individual server. With enough unused allowance, 5 GB contributes $0; if exhausted, `5 × $0.087 = $0.435`. These exact decimals are not silently rounded.

**Unit limitation:** original Premium SSD and backup API meters say GB/month, while the pricing FAQ uses GiB/month. No equivalence was silently assumed. The main v2 storage example has a matching GiB API meter. Legacy/Burstable storage and additional backup examples use explicit *billable meter quantities*. One logical GB of rows does not set the provisioned amount.

### 1. Small SQL app

Inputs: one production database, 1 GB logical data retained for the month, 100,000 reads/20,000 writes, ten peak connections, 5 GB internet transfer, 730 running hours.

**Normal paid resource example:**

`compute = 730 × $0.178 = $129.94`

`storage = 32 GiB-month × $0.115 = $3.68`

`base = $129.94 + $3.68 = $133.62/month`

Extra v2 IOPS and throughput are $0 under the chosen baseline configuration. Ten direct connections are below the documented 844 default available user slots for this SKU. This does not establish that every query mix fits its CPU/memory.

Complete conditional expression:

`$133.62 + $0.02I + $0.08T + $0.095U + $0.087E + optional resource charges`

Here `I` and `T` are extra month-weighted provisioned v2 IOPS/MB/s; `U` is extra backup usage in the API’s billable GB-month unit; `E` is egress GB charged at the stated first paid tier. If all extras are zero and enough egress allowance remains, the allocated-resource total is **$133.62 before tax**. The directory’s query counts do not prove that this is the required or smallest safe server, so a guaranteed workload total remains unknown.

**Burstable cost comparison:** B1ms compute is `730 × $0.017 = $12.41`. It cannot be newly provisioned with SSD v2. For original Premium SSD let `G` be its billable API GB-month quantity: `$12.41 + $0.115G + applicable extras`. At an assumed invoice quantity `G=32`, the subtotal is **$16.09**. That is conditional billing arithmetic, not a verified decimal-GB conversion from a 32-GiB portal setting. B1ms has 35 default user connections, CPU-credit limits, and a production/support warning.

**Eligible free-resource variant:** the [Azure free-product PostgreSQL card](https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account?icid=azurefreeaccount) and [offer terms](https://azure.microsoft.com/en-us/pricing/offers/ms-azr-0044p) describe 750 B1MS hours, 32 GB storage and 32 GB backups per eligible month for 12 months. Covered compute is `max(730 − 750, 0) × $0.017 = $0`; the stated eligible storage/backup quantities would contribute $0 if within the exact offer meters. This is a Burstable offer, not free D2ds_v5/v2 storage. Production permission, unit mapping and usage outside the offer must be resolved before promising an all-in $0 bill. The $200 introductory credit is separate and only lasts 30 days.

**Backup variant:** if the account reports **eight additional billable backup GB-months**, `8 × $0.095 = $0.76` extra. The [geo-backup formula](https://learn.microsoft.com/en-us/azure/postgresql/backup-restore/concepts-backup-restore) is `max(2 × local backup amount − primary provisioned amount, 0) × rate`, using compatible vendor billing units. Eight extra units cannot be inferred from one GB of live data or seven retained days.

**HA variant:** for a supported pair with the same D2ds_v5/32-GiB-v2 resources, `2 × $129.94 + 2 × $3.68 = $267.24/month` before excess backup, optional performance, transfer and tax. [HA billing](https://azure.microsoft.com/en-us/pricing/details/postgresql/flexible-server/) charges both compute/storage allocations. Only charges established for this configuration are included.

**Old-engine fee variant:** a running eligible 2-vCore legacy server in Extended Support at the published first/second-year rate would add `2 × 730 × $0.07 = $102.20/month`. This is an extra fee only. Do not add it to the PG17/v2 example as though PG13 were compatible: [v2 limitations](https://learn.microsoft.com/en-us/azure/postgresql/compute-storage/concepts-storage-premium-ssd-v2) specifically exclude PG13. Version-specific billing dates are in the lifecycle table.

### 4. Small vector search app

Inputs: 100,000 vectors, 1,536 float32 values/vector, 1 KiB metadata/vector, 100,000 searches, 10,000 updates and 5 GB internet transfer.

Raw payload, **our calculation**:

`100,000 × (1,536 × 4 + 1,024) = 716,800,000 bytes`

`716,800,000 / 1,000,000,000 = 0.7168 decimal GB`

`716,800,000 / 1,073,741,824 = 0.667572021484375 GiB`

The 1,536 dimensions fit the [documented 2,000-dimension pgvector index ceiling](https://learn.microsoft.com/en-us/azure/postgresql/extensions/how-to-optimize-performance-pgvector). Raw payload excludes tuples, indexes, build memory/temp files, WAL, backups and replicas; it is not the billed index size.

For the same allocated D2ds_v5/v2 example, the base resource bill would remain $133.62 **if that configuration can actually hold/build/query the chosen index and no paid extras arise**. Formula: `allocated compute/storage + extra provisioned performance + backup/transfer + selected embedding/reranking resources`. The workload does not determine index RAM, build time, query latency or additional model tokens. Complete total: **unknown**. [azure_ai](https://learn.microsoft.com/en-us/azure/postgresql/azure-ai/generative-ai-azure-overview) calls configured remote services; [retired azure_local_ai](https://learn.microsoft.com/en-us/azure/postgresql/extensions/azure-local-ai) is not a current included local-embedding option.

### 5. Small job workload and retry/wait variant

Inputs: 10,000 jobs at one active second, target 0.5 vCPU/0.5 GB, peak five concurrent jobs, no retries/waits. Active work: `10,000 × 1 = 10,000 seconds`.

[pg_cron](https://learn.microsoft.com/en-us/azure/postgresql/extensions/concepts-extensions-considerations) can schedule SQL in the database. It does not expose an independently sized 0.5-vCPU application worker. The [default count of 32 concurrent jobs](https://learn.microsoft.com/en-us/azure/postgresql/parameters/parameters-customized-options) is a scheduler setting, not proof of adequate memory or CPU for five jobs. For SQL-only work, use `whole-server allocation + storage/performance + history/log growth`; an always-running selected server still has the $133.62 resource base. Do not price it as `10,000 seconds × an unrelated serverless worker rate`.

Variant: 10% of original jobs get one extra active one-second execution; each original also waits five seconds. Active time is `10,000 + 1,000 = 11,000 seconds`; extra waits are `10,000 × 5 = 50,000 seconds`. Total aggregate active/wait time is 61,000 seconds; parallel work means this is not elapsed server uptime. Allocated server charges remain, and result/log rows can grow. Retry policy and general application-code hosting are not supplied by this example. Complete target-worker total: **unknown**.

### 6. Idle project

Inputs: the SQL scenario’s retained 1 GB logical data, zero app requests/jobs and the same allocated server/storage.

- **Left running 730 hours:** the conditional GP/v2 base remains **$133.62**, before excess backup and optional features. Idle traffic does not deallocate a running server.
- **One manual stop:** the [guide](https://learn.microsoft.com/en-us/azure/postgresql/configure-maintain/how-to-stop-server) automatically restarts after seven days (168 hours). For a 730-hour month, an illustrative exactly aligned stop followed by continuous running leaves `730 − 168 = 562` billable compute hours.
- GP/v2 conditional compute/storage is `562 × $0.178 + 32 × $0.115 = $103.716`. This is exact arithmetic; rounded to cents it is **$103.72**. Maintenance, start timing and hourly rounding may change the real bill.
- B1ms legacy-storage illustration at `G=32` invoice units is `562 × $0.017 + 32 × $0.115 = $13.234`, or **$13.23** explicitly rounded to cents, before extras and unit-resolution work.
- Repeated stop automation could change running hours but is not a guaranteed all-month zero-compute plan. Storage persists; the pricing FAQ keeps backup above the ordinary primary-capacity allowance billable.
- Eligible temporary free resources may cover their own B1ms/storage components during the offer term. Expiry, overages and required PAYG upgrade still apply. A lasting $0 idle-retention guarantee was not established.
