## Scope and evidence

This record covers managed PostgreSQL on metal/AWS, privately offered AWS BYOC, GCP preview and the separately operated open-source platform. It does not treat Ubicloud VMs, Kubernetes, AI inference or GitHub runners as included database services. Internal backup buckets are not an app-file-storage product. Scheduled SQL through supported pg_cron is covered separately from general application workers.

Every fact row was checked on **2026-11-05** against exact official URLs. Notes name the section and scope. PostgreSQL 18, pgvector 0.8.2 and pg_cron 1.6 upstream docs supplement the provider's explicit supported-version/extension list. Facts are paraphrases; cost examples are our calculations. No signup, login, form submission, live account API or database access occurred.

### Small vector-search app

Inputs: 100,000 vectors × 1,536 float32 values, 1 KiB metadata each, 100,000 searches, 10,000 updates, 5 GB internet transfer. Supported pgvector 0.8.2 uses `4×dimensions + 8` bytes per vector. Our payload calculation is:

`100,000 × ((4×1,536 + 8) + 1,024) = 717,600,000 bytes`

That is **0.7176 decimal GB**, or **0.6683170795440673828125 GiB**. This explicitly defines the conversions (1 GB = 10^9 bytes; 1 GiB = 2^30 bytes), rather than equating the price table's GB to the provisioning API's GiB.

The 1,536 dimensions fit pgvector's 2,000-dimension vector-index limit. Raw bytes exclude tuple/page overhead, HNSW/IVFFlat or VectorChord index space, WAL, replication and temporary build memory. Query/update counts do not prove CPU/RAM fit on Hobby. There is no published standalone per-vector-search or per-update tariff to add to the allocated instance price. **Known budget references remain the selected instance's advertised monthly amount; exact active/idle indexed workload and transfer total are incomplete.** Embedding/reranking and optional external model inference have no included token tariff established. ## Field problems

- Monthly display prices plus “per minute” do not disclose the exact billing denominator/rounding. The approved 730-hour scenario remains an incomplete invoice even when a monthly budget reference is clear.
- “GB” in public bundle tables differs from “GiB” in the provisioning API. Occupied app data also excludes WAL, logs, index space and system overhead. No silent unit equivalence is used.
- A generic VM networking/IP rate is not proof of the managed-Postgres rate. Backup-download S3 credentials are not an app-storage plan; F01–F07 are therefore not applicable.
- HA standbys, read replicas, PITR forks and self-managed platform deployments have different cost/operating scopes. A same-size standby does not prove an identical all-in rate.
- pg_cron makes the SQL-job fields relevant, but it does not turn the database into a general hosted-worker/queue product. Upstream SQL job-history tables are separate from seven-day provider log retention.
- A broad availability headline, private BYOC access, GCP preview label, marketing SLA and current Terms must be recorded at their actual scope. None establishes a universal residency/compliance/uptime guarantee.
