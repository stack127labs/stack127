## Conflicts and unknowns

- The Object Storage marketing page (`https://www.vultr.com/products/object-storage/`) and dynamic pricing page (`https://www.vultr.com/pricing/`) returned 403 or no readable dynamic figures. I checked the current Object Storage docs, billing pages, provisioning guide, and product overview for numbers; those official docs publish the rates recorded above. I also tried the public API paths `https://api.vultr.com/v2/object-storage/clusters` and `https://api.vultr.com/v2/object-storage/tiers`; the web reader could not access them. The CLI docs describe an authenticated tier-list command, but no API values were obtained.
- The Archive announcement (May 7, 2026) describes overage bandwidth as $0.01/GB; current pricing and limits docs use $10/TB. I chose the newer current docs' unit and retained it as published; the unit/block rounding is not stated. The regular-tier billing page publishes extra storage as $ per GB but does not name a billing block. The example applies the listed rate to a full-month excess and does not claim partial-month proration.
- Vultr's current security guide says “full S3 API compatibility,” but the specific S3 matrix lists unsupported operations. I used the detailed matrix for supported operations and recorded the inconsistency.
- The Archive standalone tier's price and included amounts are distinct from Standard with archival enabled. Do not combine the Archive $6 base with Standard's base fee, or include Vultr CDN/Compute rates in either.
- Public Object Storage rates are not presented per region. The public cluster list confirms 14 named locations (19 cluster codes), but it does not give location-specific tier prices. Vultr's general pricing note allows some product variation by data center, so a location-specific price still requires a console quote. USD invoices and tax treatment are documented separately.
- Pages checked for lifecycle/acquisition: Vultr blog index/search, the 2025 relaunch post, 2026 Archive post, platform release notes, and official News page. News page fetch returned 403; no later Object Storage shutdown/acquisition notice appeared in the official blog search.
- Unknowns remain: numeric maximum object/multipart sizes; separate API request/restore prices; standard-tier minimum object billing/early deletion; exact Archive overage block rounding; private-only endpoint; Object Storage-specific SLA/durability percentage; and post-deletion data purge interval. ## Field problems

- Vultr's public-facing rates use dollar signs; the billing FAQ confirms invoices are in USD, and a separate tax FAQ says listed website prices exclude applicable taxes.
- The public clusters endpoint confirms the available Object Storage locations, but not tier prices by location. The general billing note says some Vultr product rates can differ by data center; no console login or order quote was attempted, so the existing general tier rates remain distinct from a regional quote.
- The detailed compatibility matrix conflicts with a broad “full S3 API” phrase in a security guide. The operation-specific matrix is the useful source for implementation choices.
- Storage units vary in source text: regular tiers use GB; Archive bandwidth is stated in TB. Units are left as published, not converted or rounded.
- `C14` is genuinely not applicable because Object Storage has no compute meter. `C10` is not applicable because no product-specific recurring free plan exists; account promotional credits are separate.
