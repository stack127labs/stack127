# Amazon ElastiCache

**Lifecycle notices:** ElastiCache is active; no whole-service shutdown, sunset or acquisition notice was found in the official pricing, FAQ, deployment and engine-lifecycle pages searched. **Redis OSS 4/5 standard support ended 2026-01-31**, with paid extended support from 2026-02-01; its end date is 2029-01-31, after which the docs describe automatic upgrading to Valkey. **Redis OSS 6 standard support ends 2027-01-31.** Sources checked 2026-11-05: [current deployment options](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/WhatIs.deployment.html), [version/EOL schedule](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/engine-versions.html), [Extended Support](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/extended-support.html), [pricing](https://aws.amazon.com/elasticache/pricing/).

**Current deployment differences:** Node-based Valkey 9+ can enable optional transactional-log durability; Serverless cannot. Search is documented for **node-based Valkey 8.2+**, with broader hybrid/text capabilities from 9.0. Serverless Valkey 9+ can use a public internet endpoint with IAM and TLS 1.3. These features must not be copied across engines or deployment modes. [Durability constraints](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/Durability.Limitations.html), [search limits](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/search-features-limits.html), [public connections](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/connecting-public-endpoint.html).

## Cost examples — our calculations

All prices below are **USD, US East (N. Virginia), `us-east-1`**, checked 2026-11-05. The [public regional catalog](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonElastiCache/current/us-east-1/index.json) and [ElastiCache pricing examples](https://aws.amazon.com/elasticache/pricing/) agree on the quoted node/Serverless rates. Calculations use **730 hours**, except the explicitly stated 30-day file scenario. They exclude tax, paid support, optional monitoring, backups unless named, application hosting and any separately charged network path. No workloads were run.

1. **Small key-value app — normal paid node path.** Reference inputs: one production cache, 1 GB data, 100,000 reads, 20,000 writes, 10 peak connections, 5 GB internet output and 730 hours. A 0.5 GiB micro is too small even before overhead: `1,000,000,000 ÷ 1,073,741,824 = 0.9313225746… GiB`. A Valkey t4g.small has 1.37 GiB nominal RAM and costs `730 × $0.0256 = $18.688`; Redis OSS/Memcached t4g.small is `730 × $0.032 = $23.36`. These are **node-capacity subtotals**, conditional on usable memory/CPU fitting after reserves and metadata. A Valkey medium alternative is `730 × $0.052 = $37.96`, with 3.09 GiB nominal RAM; it is not declared the cheapest necessary size without testing.

   Network assumption: the application connects in the same AZ and sends 5 GB internet output while the account has its full shared 100 GB/month allowance available; the quoted transfer component is **$0** under that assumption. If the application crosses AZs for exactly 5 GB of chargeable traffic, the application-side component is `5 × $0.01 = $0.05`; read/write/replication traffic can be more than that. Application hosting and a depleted internet allowance need separate prices. Node request counts add no ECPU line, but they do not prove sufficient CPU. **Result: incomplete all-in app total, with the above known cache components.** Sources: [catalog](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonElastiCache/current/us-east-1/index.json), [network/running-hour rules](https://aws.amazon.com/elasticache/pricing/), [memory-reserve responsibilities](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/backups.html), [limits](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/RedisConfiguration.html).

2. **Same app — Serverless path, including the byte assumption.** Request counts alone do not fix ECPUs. To make the reference **5 GB output** concrete, assume 100,000 simple GETs transferring **50 KB each**, plus 20,000 simple SETs transferring **1 KB each**, with KB/GB interpreted as decimal units for this illustration. Then reads are `100,000 × 50 = 5,000,000 ECPUs`; writes `20,000 × 1 = 20,000 ECPUs`; total **5,020,000 ECPUs**. This assumes processor work costs no more than those byte-based amounts and excludes additional commands/retries/protocol-accounting differences. Setting every request to ≤1 KB while also attributing 5 GB output to those reads would be inconsistent.

   For **1 GB of measured average billable cache data**, no raised minimums, and 730 hours:
   - Valkey storage: `1 × 730 × $0.084 = $61.32`.
   - Valkey ECPUs: `5.02 × $0.0023 = $0.011546`.
   - **Valkey conditional cache subtotal: $61.331546.**
   - Redis OSS/Memcached storage: `1 × 730 × $0.125 = $91.25`.
   - Redis OSS/Memcached ECPUs: `5.02 × $0.0034 = $0.017068`.
   - **Redis OSS/Memcached conditional cache subtotal: $91.267068.**

   Choose a VPC endpoint for the cache/application path: current ElastiCache pricing waives in-region transfer for that Serverless path. Internet delivery from the app uses the same otherwise-unused shared allowance assumed above. A direct public cache endpoint is available only for Valkey 9+, requires IAM/TLS 1.3, and has its own route conditions. Serverless's managed multi-AZ redundancy is already part of its rate; do **not** multiply storage by three merely because three AZs are used. CPU-heavy commands, a different size distribution or extra requests make the ECPU total incomplete. Sources: [regional rates](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonElastiCache/current/us-east-1/index.json), [ECPU and network definitions](https://aws.amazon.com/elasticache/pricing/), [redundancy](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/WhatIs.deployment.html), [public-endpoint conditions](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/connecting-public-endpoint.html).

3. **High-availability and durable variants.** For node-based Valkey with one small primary and one same-sized replica, `2 × 730 × $0.0256 = $37.376` node capacity/month, assuming the dataset fits each copy and the chosen version/configuration supports Multi-AZ. This is ordinary asynchronous replication and **not a zero-data-loss durability quote**. Cross-AZ application traffic, snapshot storage and other extras remain separate.
