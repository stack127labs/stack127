## Conflicts and unknowns

- **Default region:** The same official region page says the default is AWS us-west-2, then labels US West Seattle sea1 as default in the region table. I retained both and marked the default description conflicting rather than assuming the aliases mean the same thing.
- **Service use for app end users:** Terms bar using the service “on behalf of or to provide services to third parties,” while the product is designed for app uploads. The checked pages do not explain the intended boundary. Ask the company for written clarification before relying on it for a commercial app serving customers.
- **Latest release date:** The official GitHub release page shows uploadthing@7.7.4 and “17 Aug” without a year. The SDK repository remains active, but the year is not printed on the opened release page; I have not treated a third-party package tracker as proof.
- **Overage details:** Current pricing publishes the Usage Based storage rate but not its metering interval or rounding. It gives no fixed 100GB plan overage rate or quota-exceeded behavior.
- **Bandwidth:** The free plan says unlimited uploads/downloads, and the 2025 usage-pricing post says no bandwidth charge. No 100GB plan-specific traffic rate or cap was found.
- **Where files live:** Customers can select a listed region on paid plans. The docs name AWS us-west-2 for the default but do not identify the storage provider for every other listed region, or publish a backup/replica map. Privacy policy’s statement about personal-information processing is not a file residency guarantee.
- **Self-hosting:** The v7 migration guide says work on a self-hosted version had begun. Current UTApi docs expose custom API URLs for self-hosted instances/testing, and a release mentions self-hosted URL formats, but I did not find an official end-to-end self-host deployment guide or a separately licensed hosted-service backend. Treat the available managed offer as hosted; SDK MIT licensing does not make the hosted service open source.
- **Data ownership wording:** The privacy policy says all data transmitted through the site and services is owned by T3 Tools; the Terms say UploadThing obtains no right, title or interest in user content except a license to provide the service. The two statements conflict and I found no clarification.
- **Pages checked for lifecycle/news:** Official blog index and its pricing/v7/outage posts, GitHub releases, current product homepage, status page, terms and privacy policy. The blog contains a September 2024 post about the first major outage and the v7 infrastructure migration, but no acquisition or shutdown notice. No separate official newsroom page appeared in the checked site search.
- **Other pages searched before marking not published:** Pricing homepage, docs landing page, FAQ, file routes, upload flow, working with files, regions/ACL, UTApi, OpenAPI, terms, privacy and security policy. These checks did not establish card requirement, inactivity deletion, tax treatment, fixed-plan egress/overage, global file ceiling, S3 compatibility, restore retention, custom domains or transformations.

## Field problems

- **C06 commercial restrictions:** Terms language about serving third parties is broad and may be read more widely than the app-user upload workflow described in docs. I marked this unclear instead of interpreting a legal term.
- **C03 data ownership:** The terms and privacy policy use conflicting language about ownership of user content. I recorded both statements rather than resolving the contradiction.
- **C11 inactivity:** The compute-specific “idle pause” idea does not fit this storage product; it is not applicable. Automatic file/project deletion on inactivity remains a separate not-published question.
- **C13/F01 storage overage interval:** Price and included volume are public, but measurement, rounding and the exact period attached to the incremental USD $0.08/GB are not. The calculation makes its assumption explicit.
- **C17 default region:** The source page contradicts itself about which entry is the default.
- **F04 maximum size:** Route-level size can be configured and file-size units include GB, but the docs do not state a global max object size for the managed service.
- **F05 compatibility:** UploadThing exposes its own REST/API/SDK surface. The S3 compatibility field is useful to test but no official S3-compatibility claim or operation matrix was found.
