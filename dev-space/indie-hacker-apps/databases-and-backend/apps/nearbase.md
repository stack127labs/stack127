## Cost examples

**Our calculations**, checked 2026-11-05. These are estimates from public rates, not a vendor quote, capacity benchmark or accepted checkout. Use **Singapore, ap-southeast-1**, and the listed **pg.n2e.1c.1m, General Purpose Economy ARM, 1 vCPU/2 GB RAM**, if available for creation. All prices remain **USD per month**; no local-currency conversion is made.

The [public pricing table](https://nearbase.dev/pricing/) gives compute at USD 6/month and provisioned storage at USD 3.6 per 10 GB/month, with a calculator minimum of 20 GB. The [official calculator component](https://nearbase.dev/_astro/PricingCalculator.CavGnOKS.js) computes the combined amount, rounds to six decimal places, then applies **Math.ceil**, rounding upward to a whole dollar. Thus the displayed estimate is **ceil[compute + (storage GB × 3.6/10)]**. This explains the USD 14 display; USD 13.20 is the unrounded rate subtotal.

Nearbase's [CLI/docs](https://docs.nearbase.dev/cli.md) say creation revalidates price and class availability. No quote/create operation was run. The [terms](https://nearbase.dev/terms/) exclude applicable taxes; [Billing Profile](https://docs.nearbase.dev/billing/billing-profile.md) currently says Nearbase does not add VAT/GST and the customer may need to self-assess. That is not a claim that every customer owes no tax.

### 1. Small SQL app

Inputs: one production database, **1 GB actual data**, **100,000 reads**, **20,000 writes**, **10 peak connections**, **5 GB internet transfer**, and **730 hours** for an always-on comparison month. The smallest public instance is provisioned with **20 GB**, even though only 1 GB is used.

Formula: USD 6 compute + (20 GB ÷ 10 GB × USD 3.6) = **USD 13.20 unrounded**; official calculator rounding gives **ceil(13.20) = USD 14/month**. [Pricing docs](https://docs.nearbase.dev/billing/pricing.md) add no per-query/connection fee within the instance limit and state no egress charge. The 730 hours do not multiply a monthly subscription price; they only describe the comparison's always-on use.

**Result: USD 14/month public base estimate, before applicable tax, subject to the instance handling the workload and any unpriced requirements below.** Actual max_connections, query intensity and fair-use thresholds are not published. Ten peak connections is within the docs' suggested application-pool sizing for one CPU, but that suggestion is not proof of the server's configured connection ceiling.

No general free allowance is applied: no public fixed signup amount was found. The [UIUC club sponsorship](https://nearbase.dev/blog/uiuc-postgres-club-sponsorship/) is restricted and lacks public allocation/eligibility-duration details, so it cannot produce a defensible general free-path total.

Alternative listed class if the app needs a standard x86 configuration: 2 vCPU/8 GB compute USD 77 + USD 7.20 minimum storage = **USD 84.20 unrounded; ceil = USD 85/month**. This is a different resource allocation, not a guaranteed remedy for every workload.

Backup variant: daily backups are [documented as included](https://docs.nearbase.dev/instances/backups.md), so no separately published standard backup charge is added. **Retention days, extra retention/backup capacity prices and a contractual restore guarantee remain unknown.** Support handles manual/PITR restore. The [terms require independent off-site backups](https://nearbase.dev/terms/); their storage/transfer/automation costs are unpriced, so a fully protected deployment total is **incomplete**, not necessarily USD 14.

High-availability/read-replica variant: **incomplete**. Included failover language does not publish node count or an orderable current HA/replica price. Buying two ordinary USD 14 instances would cost **2 × 14 = USD 28/month** at these assumptions, but does not establish supported replication or an automatically configured HA deployment. This arithmetic must not be labelled a Nearbase HA quote.

### 2. Full app backend

Inputs: the SQL workload plus **1,000 monthly active users**, **1 GB files**, **100,000 file reads**, **10,000 uploads**, **20 GB total internet transfer**, and **10,000 function calls**. Function assumption: 1 active second each at 0.5 vCPU and 0.5 GB RAM on an external worker where that allocation exists.

Work arithmetic: **10,000 × 1 second = 10,000 active worker-seconds**, nominally **5,000 vCPU-seconds** and **5,000 GB-seconds**, before any actual worker billing rules.

Formula: **USD 14 estimated database base + external application identity/authentication + file storage/requests/delivery + worker execution + logs/operations + any external email/SMS**. Use 20 GB total transfer, not 20 GB plus the database case's 5 GB.

**Result: incomplete.** Nearbase's [explicit product scope](https://nearbase.dev/blog/a-note-on-layerbase/) is managed PostgreSQL, not a backend bundle. Its database no-egress statement does not price a separate file CDN, authentication provider or worker host. Monthly active app users are not a Nearbase database-seat meter, and no external service or free allowance is invented.

### 3. Small file store

Inputs: **100 GB** average hot files for a **30-day month**, **100,000 writes**, **1 million reads**, **100 GB internet transfer**, files retained throughout the month.

**Result: not applicable as an object-storage quote.** The [product scope](https://nearbase.dev/blog/a-note-on-layerbase/) and [connection docs](https://docs.nearbase.dev/connecting.md) describe PostgreSQL access, not buckets, multipart uploads, signed delivery or S3 object operations. The database disk rate is not a hot-object-storage tariff. Storing file bytes in SQL would require an application upload/delivery design, a verified binary-value limit and separate capacity/recovery assumptions; no all-in file-hosting result is calculated.

### 4. Small vector search app

Inputs: **100,000 vectors**, **1,536 float32 numbers each**, **1 KiB metadata per vector**, **100,000 searches**, **10,000 updates**, **5 GB transfer** each month.

**Our raw-payload calculation:** 100,000 × [(1,536 × 4 bytes) + 1,024 bytes] = **716,800,000 bytes**, before row IDs, index layout, SQL overhead, replicas and backups. Four bytes per float32 and 1,024 bytes per KiB are workload assumptions, not a Nearbase billed-index estimate.

A conditional database floor is the same USD 14/month **only if** a permitted search implementation exists, the final stored/indexed data fits the 20 GB allocation and the smallest instance has enough resources. [Parameters](https://docs.nearbase.dev/instances/parameters.md) and the [full docs index](https://docs.nearbase.dev/llms.txt) do not establish installed pgvector, ANN index support or extension permissions.

**Result: incomplete and capability unverified.** Do not imply the approved vector workload is supported just because PostgreSQL is the engine. Extension/version/dimension limits, actual index size, search CPU/latency, embedding/reranking provider and token/transfer charges remain unknown. No native vector-service or model bill is guessed.

### 5. Small job workload

Inputs: **10,000 jobs/month**, each **1 active second**, **0.5 vCPU/0.5 GB RAM** where that worker allocation exists, **peak 5 concurrent**, no retries or waiting in the base case.

Arithmetic: **10,000 × 1 = 10,000 active seconds**. Nearbase does not document a general-code worker SKU, and [installed SQL scheduler support](https://docs.nearbase.dev/instances/parameters.md) was not established. Database instance resources are not a billable 0.5-vCPU function machine.

Formula: external worker/queue/orchestration + retained database (conditional USD 14 base if selected) + logs and transfer. **Result: incomplete.** No worker provider was selected, and there is no published Nearbase invocation price to multiply by 10,000.

Retry/wait variant, explicitly assumed for comparison: 1,000 extra one-second attempts yield **11,000 active seconds**; 1,000 jobs waiting 60 seconds add **60,000 elapsed waiting-seconds**. Whether waiting keeps a worker allocated, and how retries are charged, depends on the missing worker/orchestration provider. The [CLI's creation idempotency](https://docs.nearbase.dev/cli.md) does not establish duplicate prevention for application background jobs.

### 6. Idle project

Inputs: retain the SQL case's **1 GB actual data on 20 GB provisioned storage**, no requests or job execution for a month, and retain any selected backups.

Formula for an unchanged active subscription: **ceil[USD 6 + (20/10 × USD 3.6)] = USD 14/month**, before applicable tax. Zero queries do not change the [monthly instance price](https://docs.nearbase.dev/billing/overview.md). Added instances and independent backup storage would still have their own costs.

**Result: USD 14/month public base estimate while the subscription remains active; full protected-project cost incomplete.** No documented idle-credit or sleep discount is applied. A stopped status does not establish a billing exemption.

[Current cancellation docs](https://docs.nearbase.dev/instances/lifecycle.md) keep service through the paid period, then delete the instance without prorated credit. Do not calculate idle savings from the [older refund promises](https://nearbase.dev/blog/simpler-pricing/). Data-retention timing after cancellation is conflicting, so cancellation is not treated as a free database archive.
