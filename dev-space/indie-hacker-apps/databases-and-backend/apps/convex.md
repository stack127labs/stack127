## Cost examples — our calculation

These conditional estimates are not vendor quotes. Inputs were checked on 2026-11-04: [pricing](https://www.convex.dev/pricing), [meter definitions](https://docs.convex.dev/production/state/limits.md), [egress scope](https://docs.convex.dev/production/usage-limits.md), [upload flow](https://docs.convex.dev/file-storage/upload-files.md) and [vector billing](https://docs.convex.dev/search/vector-search.md). No promotion, tax or external-provider charge is included.

Define `[x]+ = max(x, 0)`. Let `S` be billable database GB including ordinary indexes, `I` monthly database I/O GB, `F` billable function/file calls, `A` billed action GB-hours, `U` file/backup GB-months, `X` search-index GB, `Q` monthly query-GB and `E` billable egress GB. Treating the stated internet transfer as `E` is an explicit assumption: the docs do not completely map database client traffic to the new meters.

Starter formula before invoice rounding:

`0.22[S−0.5]+ + 0.22[I−1]+ + (2.20/1,000,000)[F−1,000,000]+ + 0.33[A−20]+ + 0.033[U−1]+ + 0.55[X−0.5]+ + (0.11/1,000)[Q−3,000]+ + 0.132[E−1]+`

Apply each allowance once per team. Rates per million or thousand do not establish invoice rounding increments.

### 1. Small database app

Inputs: one production database, 1 GB retained for the month, 100,000 reads, 20,000 writes, 10 peak client sessions and 5 GB internet transfer. Assume one query/mutation call per operation, no subscription reruns, actions, search or backups. No 730-hour machine allocation is required.

- Free cannot hold the specified 1 GB database within its 0.5 GB cap.
- Starter: if 1 GB is the **entire billed database size**, `F=120,000`, `E=5` and `I≤1`, storage is `(1−0.5)×$0.22=$0.11`; egress is `(5−1)×$0.132=$0.528`. Conditional subtotal **$0.638/month**, before rounding/tax. Add `$0.22[I−1]+`, extra indexes or extra calls.
- Professional, one developer: **$25/month conditionally**, if database and I/O stay within 50 GB, calls within 25M and egress within 50 GB.
- With Starter allowances already consumed by other deployments, marginal cost is `1×$0.22+120,000×$2.20/1M+5×$0.132+I×$0.22=$1.144+$0.22I`, before extra indexed space.

Read/write counts do not determine database I/O. If 1 GB means raw records, rather than total billed storage, indexed space remains an additional input.

### 2. Full app backend

Add 1,000 MAU, 1 GB files, 100,000 file reads, 10,000 uploads, **20 GB total** internet transfer and 10,000 one-second Node actions. Use Node's 512 MiB allocation; no selectable 0.5-vCPU allocation is published.

Our raw decimal-GB memory-time model is `10,000×1×(512×2^20/10^9)/3,600=1.491308088… GB-hours`. The ellipsis marks a repeating calculation, not invoice precision. Billed normalization, overhead and duration rounding were not established; the example assumes billed `A≤20`.

Assume three billable calls/upload using the documented flow, one/download and one/database operation: `F=30,000+100,000+120,000+10,000=260,000`. This is a call model, not a measured billing trace; authentication, nested functions and URL generation can add work.

- Free exceeds database capacity and the assumed egress allowance.
- Starter: with `S=1`, `U=1`, `I≤1`, `A≤20`, `F≤1M` and `E=20`, conditional subtotal is `$0.11+19×$0.132=` **$2.618/month**.
- Professional, one developer: **$25/month conditionally** within its allowances.

The exact total is unknown. Auth records and identity/email/SMS provider costs are not determined by 1,000 MAU. Convex Auth's beta production permission is conflicting. No backups are included in this base case.

### 3. Small file store

Inputs: 100 GB average files for a 30-day month, 100,000 uploads, 1M direct file reads and 100 GB billable egress. Files stay for the month. Use single POST uploads and bearer-link downloads; no private HTTP proxy, image transformation or extra CDN is assumed.

Assuming the three-request upload flow yields three billable calls/upload, `F=3×100,000+1,000,000=1,300,000`.

- Free cannot hold 100 GB within its 1 GB allowance.
- Starter: storage `99×$0.033=$3.267`; egress `99×$0.132=$13.068`; modeled extra calls `0.3×$2.20=$0.66`. Conditional subtotal **$16.995/month**, plus database metadata/index capacity and I/O.
- Professional, one developer: files and modeled calls fit allowances; egress `(100−50)×$0.12=$6`. Conditional subtotal **$31/month**, including the seat, if metadata/database I/O fit its allowances.
- After Starter allowances are exhausted, modeled marginal files/calls/egress cost is `100×$0.033+1.3×$2.20+100×$0.132=` **$19.36**, plus metadata and I/O.

Unverified call mapping, invoice increments and unpublished storage minimums prevent an unconditional total.

### 4. Small vector app

Inputs: 100,000 vectors, 1,536 float32 values each, 1 KiB metadata each, 100,000 searches, 10,000 updates and 5 GB egress. Raw input: `100,000×(1,536×4+1,024)=716,800,000 bytes`, or 0.7168 decimal GB. Convex's API uses float64 arrays. This raw input size is neither billed document nor index size.

For a stable measured index of `X GB`, `Q=100,000X query-GB`: each search counts the whole index regardless of filters/results.

- Starter search term: `$0.55[X−0.5]+ + $0.11[100,000X−3,000]+/1,000`. Assumed egress adds `4×$0.132=$0.528`. Add database, I/O, calls, actions and external embeddings.
- Professional: one-developer $25 base plus `$0.50[X−1]+ + $0.10[100,000X−50,000]+/1,000` and any other exceeded allowances.
- Free fit and an exact paid total cannot be established from raw bytes. Actual index/document sizes, action duration, fetched results and embedding model are missing. Updates can change index size through the month.

### 5. Small jobs and retry/wait variant

Inputs: 10,000 one-second jobs, peak 5, no waits/retries. Closest native runtime is Node with 512 MiB and a 10-minute limit. S16 permits 8 scheduled jobs and 64 Node actions. The specified 0.5-vCPU/0.5-GB worker is not a selectable published machine.

If calls/action time and job-state storage/I/O fit Free allowances, **Free or Starter recurring usage can be $0**. This is conditional, not a matched-machine quote. Professional has its $25 one-developer base. After Starter allowances are exhausted, modeled marginal execution is `10,000×$2.20/1M+A×$0.33=$0.022+$0.33A`, plus scheduling/state/database work.

Variant: 1,000 jobs need one extra one-second attempt after a 10-second delay. Base actions do not retry automatically; use app rescheduling or a retry component. A pending delayed job is stored rather than executing continuously. Add 1,000 execution calls, their action time, and component scheduling/status/I/O. The marginal execution-call term alone is `1,000×$2.20/1M=$0.0022` after allowances. Holding an action open while it waits has incompletely documented billing; no free-wait claim is made.

### 6. Idle retained backend

Retain 1 GB **billed database space** and 1 GB files, with zero calls/actions/I/O/egress, no search and no backup archives.

- Starter: `(1−0.5)×$0.22+[1−1]+×$0.033=` **$0.11/month**, conditionally.
- Professional: **$25/month**, one developer.
- With Starter capacity allowances already consumed elsewhere, marginal storage is `1×$0.22+1×$0.033=` **$0.253/month**.
- Free cannot hold the specified database. Extra indexes, archives or workflow history add retained storage. Manual pause preserves data and does not remove storage fees. The Business/Enterprise idle deployment-fee waiver does not erase its plan minimum.

Backup variant: logical archives consume file/backup capacity and transfer; generating/restoring them also consumes database I/O. No archive size/frequency is supplied, so no exact backup surcharge is invented. Dedicated physical backups have separate included terms and a much higher deployment commitment.
