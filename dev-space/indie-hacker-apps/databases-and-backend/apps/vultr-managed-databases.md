### Vector-search scenario

Inputs: 100,000 vectors, 1,536 float32 values per vector, 1 KiB metadata per vector, 100,000 searches, 10,000 updates and 5 GB internet transfer per month. Vultr supports pgvector; its example displays 0.7.4. In upstream **v0.7.4**, one vector uses 4 × dimensions + 8 bytes, and 1,536 dimensions fit the vector index's 2,000-dimension limit. Sources: https://docs.vultr.com/support/products/managed-databases/how-to-fix-the-pgvector-could-not-open-extension-control-file-error.md ; https://raw.githubusercontent.com/pgvector/pgvector/v0.7.4/README.md.

**Our calculation:** 100,000 × [(1,536 × 4) + 8 + 1,024] = **717,600,000 bytes**, equal to **0.7176 decimal GB** (1 GB = 1,000,000,000 bytes), or **0.6683170795440673828125 GiB** (1 GiB = 1,073,741,824 bytes). This counts the specified vectors, pgvector's per-vector representation and the assumed metadata. It excludes row headers, other columns, indexes, WAL, replicas, backups and working memory.

The raw payload is not a priced index size or proof the 1 GB RAM starting node can run the search workload. Search/update counts do not determine required CPU or memory. The installed extension version, index choice, filtering selectivity, regional plan, transfer allowance and any embedding/reranking service are unresolved. **Total incomplete.** Do not present raw vector storage as a complete hosted vector bill.
