## Cost examples — our calculation

All rates and source checks are dated **2026-11-05**. These examples use the **Serverless SQL Database** section of the price page, with Paris selected. They are not provisioned managed-instance calculations. Sources: [current English pricing](https://www.scaleway.com/en/pricing/managed-databases/), [current French pricing](https://www.scaleway.com/fr/tarifs/managed-databases/), [Serverless SQL billing FAQ](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/faq.mdx), [scaling and idle rules](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/serverless-sql-databases-overview.mdx).

### Shared inputs and formula

Let:

- `H` be total billed **provisioned vCPU-hours**, including active queries, the pre-idle period, backup creation, restore/import work and other database activity. RAM is already included with each allocated vCPU. Do not substitute query CPU-seconds or read/write counts.
- `G` be average billable database GB over a 730-hour month, with the published **1 GB billing floor**. If size varies, integrate billed GB-hours rather than using an unweighted average.
- `T` be applicable network charges. The product-specific internet/cross-region/export tariff was not established.
- `E` be any separately required service costs, such as paid support, app/REST/worker hosting, model APIs or file delivery.

Our formula, before tax:

`monthly cost = (€0.13752 × H) + (€0.000272 × 730 × G) + T + E`

Included seven-day automatic backup **storage** has no extra line-item retention fee in the reviewed offer. Backup **creation/restore compute is already part of H**. Do not add that compute twice when it occurs within an already allocated period. Sources: [rates and billing units](https://www.scaleway.com/en/pricing/managed-databases/), [minimum billing FAQ](https://www.scaleway.com/en/serverless-sql-database/), [backup compute billing](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/faq.mdx).

No ordinary recurring free allowance was established. The normal paid formula therefore has no assumed free deduction. [Founders credits](https://www.scaleway.com/en/startup-program/founders-program/) are a separately reviewed, nonrenewable promotion for eligible new startups; they cannot be assigned to an unapproved account.

### Small SQL/document app

Approved inputs: one production database, **1 GB** stored for the month, **100,000 reads**, **20,000 writes**, **10 peak connections**, **5 GB internet transfer**. This is a SQL service; the document-store alternative in the generic scenario does not apply.

One billable GB retained for 730 hours costs:

`1 × 730 × €0.000272 = €0.19856`

The workload does not specify query duration, resource demand or request spacing, so it does not determine `H`. Ten peak connections are below the published overall connection ceiling, but a complete per-vCPU connection table was not established; a tested qualifying minimum configuration is not certified.

For a clearly stated illustration, **if total billed provisioned usage including backup activity equals 10 vCPU-hours**, and average billed storage remains exactly 1 GB:

`(10 × €0.13752) + €0.19856 = €1.57376`, **plus T and E**.

This is a conditional component calculation, not a prediction that the read/write workload consumes ten hours. Sources: [connection/scaling limits](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/serverless-sql-databases-overview.mdx), [provisioned-resource billing](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/faq.mdx), [rates](https://www.scaleway.com/en/pricing/managed-databases/).

A five-billed-minute component at one vCPU is:

`€0.13752 × (5 ÷ 60) = €0.01146`.

Actual wake-to-idle billing may be longer because query processing and the inactivity period matter. A burst of statements is not automatically billed as only their execution time.

### Idle project

Inputs: the same **1 GB** retained, zero application requests and no user jobs, minimum vCPU set to **zero**.

While idle, compute billing stops, but the database still incurs the **€0.19856 storage component** over 730 hours. Automatic daily backup creation is explicitly billable activity, so a quiet month is not proven to have zero total compute consumption.

If `H_backup` and `H_other` are the billed provisioned hours due to automatic backups and other required activity, our incomplete idle formula is:

`€0.19856 + [€0.13752 × (H_backup + H_other)] + T + E`.

Backup durations and their final billed active windows were not measured; do not turn them into zero or a universal five-minute-per-day estimate. Sources: [idle state](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/serverless-sql-databases-overview.mdx), [automatic backup activity](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/faq.mdx), [minimum compute setting](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/how-to/configure-autoscaling.mdx).

The product FAQ's approximate **€0.10/month** empty-database statement does not match the current 730-hour storage calculation. C12 records this conflict rather than silently rounding it away.

### Always-on configuration and SQL scheduler

For a configuration constrained to **one allocated vCPU**, including its **4 GB RAM**, for **730 hours**, with exactly **1 billable GB** retained:

`compute = 730 × €0.13752 = €100.3896`

`compute + storage = €100.3896 + €0.19856 = €100.58816`, **plus T and E**.

This shows the cost of keeping the minimum active configuration allocated, not a measured ability to serve the workload. Backup work occurring within this fixed one-vCPU period is not another set of allocated hours; larger allocation or extra resources would change the inputs.

The serverless extension catalog explicitly requires **permanently active compute of at least one vCPU for pg_cron**. Therefore the idle-to-zero example cannot also promise reliable in-database cron scheduling. Sources: [serverless pg_cron prerequisite](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/supported-postgresql-extensions.mdx), [minimum-one compute behavior](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/faq.mdx), [serverless rates](https://www.scaleway.com/en/pricing/managed-databases/).

The approved job scenario is **10,000 jobs**, **one second each**, **0.5 vCPU/0.5 GB RAM**, **five concurrent jobs**, no retries/waiting. That worker shape does not exist as a separately billed pg_cron worker in this product. Its arithmetic is `10,000 × 1 second = 10,000 active job-seconds`, but there is no sourced invocation/worker-second tariff to multiply by it. SQL tasks share the paid database, and concurrency/timeout limits remain unknown. Arbitrary application jobs need another execution service.

Retry variant: one additional one-second attempt per job means **20,000 active job-seconds**. This is an assumed application retry policy, not a hosted automatic-retry promise. Whether it increases `H` depends on allocated capacity/scaling; it does not justify doubling a fixed always-on compute subtotal. Waiting time does not erase the permanent-active prerequisite. Sources: [extension scope](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/supported-postgresql-extensions.mdx), [upstream execution behavior](https://raw.githubusercontent.com/citusdata/pg_cron/main/README.md), [allocation model](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/serverless-sql-databases-overview.mdx).

### Backup and reliability variants

Normal policy includes **daily logical backups for seven days**. Use the base storage tariff and add the actual backup/restore contribution to `H`; no provisioned managed-database snapshot GB-month rate applies. A customer-kept export or longer external retention needs separately sourced storage/transfer prices. Sources: [backup/export procedure](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/how-to/manage-backups.mdx), [backup billing](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/faq.mdx).

High availability is advertised as part of Serverless SQL and the [formal SLA](https://www.scaleway.com/en/cloud-database-solutions/sla/) names the service. No separately selectable primary/standby node or customer read-replica SKU was established for this product. No managed-instance HA surcharge is added to these examples.

### Small vector search app

Inputs: **100,000 vectors**, **1,536 float32 values** and **1 KiB metadata** per vector, **100,000 searches**, **10,000 updates/month**, **5 GB internet transfer**.

Our raw payload arithmetic:

`100,000 × [(1,536 × 4 bytes) + 1,024 bytes] = 716,800,000 bytes = 0.7168 decimal GB`.

This is not a measured SQL storage bill. It excludes tuple/page overhead, vector representation overhead, indexes, operational data and replicas. The one-GB billing floor still applies, while index overhead may push `G` above one.

pgvector support is documented, but this serverless service's deployed extension version and exact index/dimension limits were not established. Do not certify a 1,536-dimensional index from the separate managed product's extension version. Even if dimensions fit, search/update counts do not determine `H`.

Use `€0.13752 × H + €0.000272 × 730 × G + T + E`, with measured/known billed inputs. Embedding generation and reranking are separate unknown model costs, not included free calls. Sources: [serverless extension catalog](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/reference-content/supported-postgresql-extensions.mdx), [upstream pgvector reference](https://raw.githubusercontent.com/pgvector/pgvector/master/README.md), [database billing rates](https://www.scaleway.com/en/pricing/managed-databases/).

### Full app backend and small file store

Full-backend inputs add **1,000 monthly active users**, **1 GB files**, **100,000 file reads**, **10,000 uploads**, **20 GB total internet transfer** and **10,000 short function calls**. File-store inputs are **100 GB average hot storage for 30 days**, **100,000 writes**, **one million reads** and **100 GB transfer**. Neither is an all-in workload for this database-only product.

The SQL part can use the formula above. End-user login, file delivery/storage, arbitrary functions and any external email/SMS/worker need separate providers or Scaleway products. Function memory/duration and delivery route are not established here, so no full-backend/file total is calculated. PostgREST also needs its own process/host when used. Sources: [product boundary](https://www.scaleway.com/en/serverless-sql-database/), [separately run PostgREST integration](https://raw.githubusercontent.com/scaleway/docs-content/main/pages/serverless-sql-databases/api-cli/postgrest-row-level-security.mdx).

## Conflicts and unknowns

- **Storage floor price:** the product FAQ's approximate €0.10/month conflicts with our calculation of €0.19856 for one GB over 730 hours at the current tariff. The one-GB billed floor and zero-GB physical minimum have different meanings; they are not themselves a contradiction.
- **Indexed versus fresh compute rate:** fresh English/French Serverless SQL tables say €0.13752/vCPU/hour. Older indexed extracts say €0.13572. Current page retrieval takes precedence for this dated calculation; recheck before publication.
- **Contract dating:** Contracts lists v.09/06/26, while its exact linked GTS PDF's English and French covers say April 7, 2026. Both versions of the date are retained. A public official website proxy exposed the download URL after www direct requests failed; the PDF itself was successfully read.
- **Legal product scope:** the September 2026 Merged Specific Conditions include a managed PostgreSQL/MySQL section framed around node types, local/Block Storage, standalone/HA and read replicas. No explicit Serverless SQL section was found. It was read for general/support terms and unknowns; its managed-node feature configuration is not assigned to this serverless record. Sources checked 2026-11-05: [Specific Conditions](https://www-uploads.scaleway.com/2026_EN_MERGED_SPECIFIC_CONDITIONS_7070ad2ec4.pdf), [linked GTS](https://www-uploads.scaleway.com/Conditions_Generales_de_Services_v2026_a0028de41c.pdf), [DPA](https://www-uploads.scaleway.com/DPA_2024_ENG_b0abb5cc26.pdf).
- **Eligibility:** Create an account, identity-verification guide, GTS article 4, Specific Conditions and Contracts were checked for accepted countries/current solo use conditions. Personal accounts, valid-payment requirements and sanctions obligations are published; a complete geographic allowlist was not established.
- **Transfer:** own price/FAQ pages, Network pricing, GTS and Specific Conditions were searched for SQL-specific ingress, egress, cross-region and export rates. Silence and another product's free transfer are not a zero rate.
- **Spending/inactivity:** billing alerts, Billing FAQ, SQL FAQ/overview, GTS, DPA and Privacy policy were checked. CPU ceilings and warnings exist, but a hard euro cap, inactivity deletion interval and backup accessibility after database deletion were not established.
- **Database limits/recovery:** overview, Known differences, API, backup guides/troubleshooting and contracts were checked for exact connection-versus-CPU mapping, account quotas, maximum query execution duration, arbitrary-time recovery and configurable longer retention. These remain unconfirmed where stated. Daily logical backups and a seven-day window do not establish PITR.
- **Replica/client behavior:** overview, API, Known differences and contracts were checked for replica topology, promotion controls and offline sync. High availability is documented, but a customer read-replica configuration and durable offline client product were not established. LISTEN/NOTIFY delivery is explicitly not guaranteed.

## Field problems

- **C12/C13/C21:** compute usage must count provisioned active capacity and the five-minute idle window; query counts alone cannot produce a cost. Included backup storage can still incur backup compute charges. A zero-idle-compute claim is not a zero monthly bill.
- **C03/H01:** the engine is open-source, but this hosted service has no researched self-hosted edition. No upstream license is presented as a license for the managed cloud.
- **C18/D02:** IAM role mapping and transaction pooling alter normal per-user/session assumptions. A generic PostgreSQL checkbox would hide the RLS, session-setting, advisory-lock and ETL limitations.
- **D03:** preserve SQL request KB wording and exact prepared-statement byte/KiB limits separately. The overall 1,000-connection ceiling is not a published minimum-size entitlement.
- **D05/D06:** logical backup retention, backup compute, incident interruptions and built-in HA need separate facts; none establishes PITR or a user-managed read replica.
- **V01/J01–J05:** the extension catalog confirms capabilities but does not pin all hosted versions/settings. pg_cron's always-active requirement materially changes idle cost; the generic 0.5-vCPU worker scenario does not map to this SQL extension.
- **C20/C22:** support severity details and legal document dates require reading the terms, not only a plan table. The actual GTS download date disagrees with its index label.
- **States:** the permitted vocabulary has no `derived` state. Published inputs are confirmed; all formulas are labelled our calculation and preserve missing inputs.
- **Inventory:** no incorrect `apps.md` row was established. Its active status and warning to keep Serverless SQL billing separate are consistent with this research.
