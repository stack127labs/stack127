## Conflicts and unknowns

- **Payload retention:** Current pricing lists Free 7 days, Basic 30 days, and Professional 90 days. The general retention docs still describe 90 days without plan qualification. The plan-specific pricing page is used for tier comparison; the docs describe per-message shortening and Enterprise auto-deletion.
- **Release index:** The general GitHub release index surfaced server v1.101.0, while the direct v1.102.1 release is dated later and the October security notice recommends it. I used the direct dated server release.
- **Currency code:** Public prices use “$” but do not specify USD or another ISO currency code in the pricing page or Terms.
- **Ingest billing:** Pricing includes Ingest and Svix's comparison groups it with Dispatch, but the exact counting rule for an incoming message forwarded to one or more handlers is not explained. I checked the pricing page, official comparison, Ingest receiving docs, API docs, and Terms.
- **Free cap behavior:** Pages searched: Pricing, October plan announcement, and Terms. They say Free is capped at 50,000 messages/month but do not say whether further sends stop or convert to a paid plan.
- **Payload limit:** Pages searched: Pricing, Quickstart, API reference, and OSS README. The 64 KiB billing chunk is not a published maximum-size statement.
- **Idle and account deletion:** Pages searched: Pricing, docs index, Terms, and Privacy. No idle pause/expiry rule or exact account-content purge period was found.
- **Transfer price and spend controls:** Pages searched: Pricing, Docs, Terms, and subprocessors for transfer; Pricing and Terms for hard caps and budget alerts. No separate transfer price or configurable spend cap was published.
- **Acquisition/shutdown check:** The official Svix blog, changelog archive, press page, Terms, and GitHub releases/license were checked. No acquisition, shutdown, retirement, or license-change notice was found.
- **Current security notice:** The October eMudhra advisory is relevant to the self-hosted Server OSS update path; Svix says Cloud customers were already protected.
