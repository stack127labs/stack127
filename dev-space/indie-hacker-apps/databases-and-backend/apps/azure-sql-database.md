# Azure SQL Database

**Lifecycle check — 2026-11-05:** Current Microsoft service. No complete product shutdown or acquisition notice was found in the inspected [official product page](https://azure.microsoft.com/en-us/products/azure-sql/database), [overview](https://learn.microsoft.com/en-us/azure/azure-sql/database/sql-database-paas-overview?view=azuresql-db) and [What’s new](https://learn.microsoft.com/en-us/azure/azure-sql/database/doc-changes-updates-release-notes-whats-new?view=azuresql-db). These feature/hardware changes need attention:

- **Fsv2 retired October 1, 2026; Gen4 is also retired.** Their old price records do not establish current availability. [Hardware-generation notices](https://learn.microsoft.com/en-us/azure/azure-sql/database/service-tiers-sql-database-vcore?view=azuresql-db).
- **SQL Data Sync retires September 30, 2027.** New subscriptions without previous use cannot create sync groups. [Data Sync notice](https://learn.microsoft.com/en-us/azure/azure-sql/database/sql-data-sync-data-sql-server-sql-database?view=azuresql-db).
- **REST management API 2014-04-01 retires June 30, 2027.** This extends the earlier June 2026 deadline. [API retirement notice](https://learn.microsoft.com/en-us/rest/api/sql/retirement).
- **Elastic query SHARD_MAP_MANAGER support ends March 31, 2027.** Existing use continues unsupported; new external sources of that type will be blocked. [Elastic query notice](https://learn.microsoft.com/en-us/azure/azure-sql/database/elastic-query-overview?view=azuresql-db).
- **Intel SGX enclave support ends October 31, 2027.** Remaining DC-series databases will migrate to standard-series hardware with VBS enclaves. [DC-series notice](https://learn.microsoft.com/en-us/azure/azure-sql/database/service-tiers-sql-database-vcore?view=azuresql-db).
- **TLS 1.0/1.1 are retired and unavailable; minimum TLS is 1.2.** [Connectivity notice](https://learn.microsoft.com/en-us/azure/azure-sql/database/connectivity-settings?view=azuresql-db).
- **Earlier vector-index structures and TOP_N syntax are deprecated.** The latest vector indexes became GA in September 2026; migration requires recreating older indexes. [Index migration](https://learn.microsoft.com/en-us/sql/t-sql/statements/create-vector-index-transact-sql?view=azuresqldb-current), [Query syntax](https://learn.microsoft.com/en-us/sql/t-sql/functions/vector-search-transact-sql?view=azuresqldb-current), [Release notes](https://learn.microsoft.com/en-us/azure/azure-sql/database/doc-changes-updates-release-notes-whats-new?view=azuresql-db). A final removal date for old index structures was not established.
- **Hyperscale serverless auto-pause/resume and logical-server soft-delete remain Preview.** Their coverage/defaults differ from ordinary GP serverless and database-level restore. [Pause/resume](https://learn.microsoft.com/en-us/azure/azure-sql/database/serverless-tier-auto-pause-resume?view=azuresql-db), [Deleted logical server restore](https://learn.microsoft.com/en-us/azure/azure-sql/database/deleted-logical-server-restore?view=azuresql-db).

## Cost examples — our calculation

Checked 2026-11-05. Currency **USD**, region **East US (eastus)**, ordinary public retail prices before tax. No discount commitment, existing SQL Server license benefit, paid support or optional private-network service is assumed. These are our calculations, not vendor quotes or workload benchmarks.

The [public Retail Prices API query](https://prices.azure.com/api/retail/prices?%24filter=serviceName+eq+%27SQL+Database%27+and+armRegionName+eq+%27eastus%27+and+priceType+eq+%27Consumption%27&currencyCode=%27USD%27) returned 328 records on one page. Its catalog includes retired hardware, old Free DTU entries, alternative product names and repeated meter IDs. Only identified current configurations are priced below. [The pricing page](https://azure.microsoft.com/en-us/pricing/details/azure-sql-database/single/), [DTU billing](https://learn.microsoft.com/en-us/azure/azure-sql/database/service-tiers-dtu?view=azuresql-db), [serverless billing](https://learn.microsoft.com/en-us/azure/azure-sql/database/serverless-tier-billing?view=azuresql-db) and [storage billing](https://learn.microsoft.com/en-us/azure/azure-sql/database/service-tiers-sql-database-vcore?view=azuresql-db) were read separately.

### Inputs and pricing rules

- Basic B DTU: **$0.161/day** in the API; the service bills databases hourly. Explicit normalization: `$0.161 / 24` per billed hour. For 730 hours, `730/24 × $0.161 = $4.897083333333…`, or **$4.90** rounded to cents. Included data is 2 GB and ordinary DTU PITR backup storage has no extra charge. This is not a claimed minimum bill across every Azure SQL purchasing model.
- GP Gen5 serverless: **$0.521758/billed vCore-hour**, equivalent to `$0.521758/3,600` per billed vCore second. Do not substitute the documentation’s rounded illustrative $0.000145/second as a new exact East US tariff.
- Per-second billed compute is `max(min vCores, CPU vCores used, minimum memory GB/3, memory GB used/3)`. Let its monthly sum be **C billed vCore seconds**. Queries alone do not determine C.
- For a serverless illustration choose a documented **max-four/min-0.5-vCore** configuration with **2.1 GB minimum memory**, giving **0.7 billed vCore** while online at its floor. Its data maximum is explicitly **D = 32 GB**, not just the workload’s logical 1 GB.
- GP/BC storage includes an additional billable log allocation of 30% of maximum data size. At the GP API rate $0.115/GB-month: `32 × 1.3 × $0.115 = $4.784/month`. We preserve GB; no GB/GiB conversion is made. Pricing’s 5-GB minimum and the newer documentation’s 1-GB minimum disagree, so neither disputed floor is used in this example.
- For GP/BC, backup capacity up to maximum configured data size is included; extra backup bytes depend on history/changes. Let **U** be extra billable LRS backup GB-months, at **$0.10U**. LTR, replicas, zone configurations, external models and job agents have separate prices.
- [Network table](https://azure.microsoft.com/en-us/pricing/details/bandwidth/): with enough shared first-100-GB internet allowance left, this app’s 5 GB contributes $0. If that allowance is exhausted, `5 × $0.087 = $0.435` on the stated North American route. No per-database 100-GB allowance is invented.
- The API also exposes consumed-IO meters whose current charging scope was not resolved against pricing/docs. DTU explicitly bundles I/O; optional vCore/Hyperscale totals are not presented as complete if the selected configuration has another applicable meter.

### 1. Small SQL app

Inputs: one production database, 1 GB logical data for the month, 100,000 reads/20,000 writes, ten peak connections, 5 GB internet transfer, and 730 hours where always on.

**Normal paid DTU reference:** Basic has 5 DTUs, 2 GB data, 30 workers and 300 sessions. If data **including required indexes** fits that cap and performance is adequate, ten connections are within the published connection counts.

`database resource charge = 730/24 × $0.161 = $4.897083333333…`

With no separately purchased extras and sufficient network allowance, the conditional database/resource total is **$4.90/month rounded** before tax. It includes bundled compute/storage/I/O and normal PITR; it does not include geo-secondaries or LTR. Basic performance for these unspecified SQL statements was not tested, so this is not a guaranteed production sizing recommendation.

**Paid serverless illustration:** choose the configuration above and assume **C = 20,000 measured billed vCore seconds**, no excess backup and sufficient egress allowance.

`compute = 20,000/3,600 × $0.521758 = $2.898655555555…`

`compute + provisioned data/log storage = $2.898655555555… + $4.784 = $7.682655555555…`

Known subtotal is **$7.68 rounded**, before tax and any other applicable meter. Complete expression: `C/3,600 × $0.521758 + 1.3D × $0.115 + $0.10U + charged transfer + optional/applicable meter charges`. The stated logical reads/writes do not establish the chosen C. Active idle delays and memory are included in C, not ignored.

**Eligible recurring free variant:** [Free SQL](https://learn.microsoft.com/en-us/azure/azure-sql/database/free-tier?view=azuresql-db) covers 100,000 billed vCore seconds, 32 GB data and 32 GB backups per month/database for the subscription lifetime. At the explicit 20,000-second usage and within those data/backup limits, covered database components are **$0**. Networking and external resources remain separate. AutoPause can stop access when the monthly allowance is spent; paid overages avoid that stop and cannot be switched back. Free is recommended for development/proof of concept and has no SLA.

A vCore second is not a wall-clock second: at the documented 0.7 floor, `100,000/(0.7 × 3,600) = 39.6825396825…` online hours consume the allowance, even before higher CPU/memory usage. This is our illustration, not a vendor-provided fixed-hours entitlement.

**Backup variant:** eight extra billed LRS backup GB-months add `8 × $0.10 = $0.80` to an eligible vCore configuration. Eight LTR LRS GB-months add `8 × $0.025 = $0.20`. Basic’s PITR treatment differs; no unnecessary vCore PITR fee is applied to it.

**HA/replica variant:** local redundancy is built into the database. If a separately billed Basic geo-secondary has the same configuration for 730 hours, its resource charge is another $4.897083333333…, for **$9.794166666666…** combined, or **$9.79 rounded**, before cross-region traffic/optional services. This is asynchronous geo replication, not a zone-redundant Basic deployment. Other tier/zone replica combinations require their own prices.

### 4. Small vector search app

Inputs: 100,000 vectors, 1,536 float32 values and 1 KiB metadata each, 100,000 searches, 10,000 updates and 5 GB internet transfer.

Raw payload, **our calculation**:

`100,000 × (1,536 × 4 + 1,024) = 716,800,000 bytes = 0.7168 decimal GB`

Complete total is **unknown** because index sizing, search complexity and model/token inputs are absent.
