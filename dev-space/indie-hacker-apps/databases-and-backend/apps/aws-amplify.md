## Cost examples — our calculation

These are our calculations, not AWS quotes or performance benchmarks. Checked 2026-11-04. Use US East (N. Virginia), `us-east-1`, one Amplify Gen 2 backend, one DynamoDB Standard table explicitly configured **on-demand**, one AppSync GraphQL API and Basic Support. No frontend hosting, AppSync cache, replicas, secondary-index amplification, provisioned Lambda concurrency, VPC/NAT/proxy, custom KMS key, model inference or message delivery unless stated. Additional deployment artifact storage, logs and network processing remain separate. Account-wide allowances must still be available; promotional credits are applied only as a time-limited offset.

DynamoDB and S3 define storage GB as `2^30` bytes. For the 1GB/100GB scenarios below, the named stored quantity means **vendor binary GB**. If the directory later standardizes decimal GB, explicitly convert bytes before applying the rates. This unit choice is recorded rather than silently changing it. Sources: [DynamoDB units](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Constraints.html), [S3 units](https://aws.amazon.com/s3/pricing/).

### Small database

Inputs: 1GB for a full month; 100,000 reads and 20,000 writes; ten peak application connections; 5GB internet transfer. Additional assumptions needed for pricing: every operation addresses one item at most 1KB including attribute names, each read is strongly consistent, no transaction, scan, fan-out or secondary-index write. Every operation is one AppSync query/mutation and one corresponding DynamoDB operation. Ten application connections are HTTP/API concurrency, not ten persistent SQL sessions. No realtime subscription-minutes are specified.

| Line item | Formula — our calculation | Result before credits |
| --- | --- | --- |
| AppSync GraphQL | `(100,000 + 20,000) / 1,000,000 × $4` | $0.48 |
| DynamoDB strong reads | `100,000 × 1 unit / 1,000,000 × $0.125` | $0.0125 |
| DynamoDB writes | `20,000 × 1 unit / 1,000,000 × $0.625` | $0.0125 |
| Table storage with unused Standard allowance | `max(1GB − 25GB, 0) × $0.25` | $0 |
| Known API/database subtotal | `$0.48 + $0.0125 + $0.0125` | **$0.505/month** |
| Storage if allowance unavailable | `1GB × $0.25` | add $0.25; subtotal **$0.755** |

Sources: [AppSync rates](https://aws.amazon.com/appsync/pricing/), [DynamoDB US East rates/allowance](https://aws.amazon.com/dynamodb/pricing/), [unit sizes](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Constraints.html). Strong reads are an explicit custom/configured assumption, not a claim about the generated resolver default ([resolver consistency](https://docs.aws.amazon.com/appsync/latest/devguide/js-aws-appsync-resolver-reference-dynamodb-getitem.html)). With eventual reads, read units halve: API/database subtotal becomes `$0.48 + $0.00625 + $0.0125 = $0.49875` with storage allowance.

Transfer variant: if the [shared 100GB outbound allowance](https://aws.amazon.com/about-aws/global-infrastructure/global-network/faqs/) is available and covers this route, the 5GB internet line adds $0. DynamoDB's older allowance text conflicts with that policy; network processing or other routes need their own meter. **All-in backend total remains conditional**, including actual resolver work, logs and deployment resources.

An eligible unexpired [AppSync trial](https://aws.amazon.com/appsync/pricing/) could remove its $0.48 API line; it does not remove on-demand DynamoDB requests. An eligible credit balance can offset eligible charges to a temporary cash bill of $0 while it lasts, but this is not a permanent free Amplify plan ([account plans](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html)). A provisioned-table alternative can use the 25RCU/25WCU allowance, but peak requests per second were not supplied, so it is not declared the cheapest configuration that definitely fits.

Backup variant: PITR for the retained 1GB adds `1 × $0.20 = $0.20/month`; one restore adds `1 × $0.15 = $0.15`, before the resulting table's own storage/request charges. Sources: [DynamoDB disaster-recovery prices](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamodbDisasterRecoveryStrategy.html), [restore behavior](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Point-in-time-recovery.html). Backup does not include the rest of an Amplify app.

### Small vector search app

Inputs: 100,000 vectors; 1,536 float32 values plus 1KiB metadata per record; 100,000 searches, 10,000 updates and 5GB internet transfer. Raw representation, **our calculation**: `100,000 × (1,536 × 4 + 1,024) = 716,800,000 bytes = 0.7168 decimal GB = 0.667572021484375 vendor binary GB`. Dimension fits the underlying [4,096 maximum](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/ServiceQuotas.html).

This raw byte sum is not the DynamoDB base-table serialized size or billed vector-index size. The [base table and projected index storage bill separately](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/VectorSearchStorage.html). Vector values in the index use f32, while base-table attribute representation, keys and projections still need explicit sizing. Search billing depends on processed/returned bytes, not simply all 100,000 vectors per search.

Let `T` be measured base-table storage GB, `I` billed index storage GB, `W` indexed GB written for the 10,000 updates, and `Q` processed/returned search GB after the minimum. The [US East pricing example](https://aws.amazon.com/dynamodb/pricing/) supplies the illustrative rate formula:

`base-table request/storage bill + I × $0.25 + W × $0.52 + Q × $0.002 + custom API/Lambda integration + model inference + transfer/logs`.

**Exact total unavailable**: `T`, `I`, `W` and `Q`, top-K, projected attributes and an authorized Amplify integration are not defined by the base workload. Index writes/searches have a 1KB minimum according to the same pricing page. No guaranteed recurring vector request allowance is applied. The generated Amplify client mapping was not established; strict tenant isolation needs special attention because [SearchVectors does not honor fine-grained partition-key IAM restrictions](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/VectorSearchWorkingWith.html). Embedding/reranking token work is additional and unspecified ([Amplify model billing](https://docs.amplify.aws/react/ai/concepts/models/)).

### Small job workload, retries and waiting

The requested workload is 10,000 one-second jobs, 0.5vCPU/0.5GB RAM, peak five concurrent, no retries/waits. **A 512MB Lambda function is a RAM-priced alternative, not a verified 0.5vCPU machine.** CPU is proportional to memory, with one vCPU equivalent at 1,769MB ([Lambda limits](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html)). No exact cost for a guaranteed 0.5vCPU/0.5GB shape is claimed.

For the selected x86 Event Function alternative, assume one second is total **billed** duration including initialization, request payload <=256KB, no extra temporary storage and sufficient account concurrency. At [published Lambda example rates](https://aws.amazon.com/lambda/pricing/):

- Compute: `10,000 × 512/1,024 × 1 = 5,000 GB-seconds`; `5,000 × $0.0000166667 = $0.0833335`.
- Requests: `10,000/1,000,000 × $0.20 = $0.002`.
- **Without unused allowance:** `$0.0833335 + $0.002 = $0.0853335` theoretical execution subtotal. Precision follows the published rate; this is not a claim about invoice rounding.
- **With unused recurring Lambda allowance:** both quantities fit, so execution subtotal $0. Logs, triggers, network and deployment resources remain outside it.

Retry variant, our hypothetical caller workload: 1,000 jobs fail once, each retry has the same duration. `11,000 × 0.5 × 1 = 5,500 GB-seconds`; request count 11,000. Paid execution subtotal `5,500 × $0.0000166667 + 11,000/1,000,000 × $0.20 = $0.09386685`. Actual Lambda asynchronous [default retry policy](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async-error-handling.html) can make more attempts and duplicate delivery can occur; this variant is not its guaranteed billing outcome.

Waiting variant: if every invocation instead remains running for one additional second, total billed duration doubles while requests stay 10,000; paid execution subtotal `10,000 GB-seconds × $0.0000166667 + $0.002 = $0.168667`. Checkpointed durable waits, SQS, EventBridge Scheduler or Blocks AsyncJob would be different configurations with other meters. They are not silently substituted for an ordinary Amplify function. New accounts can have reduced concurrency, so peak-five fit must be checked against the account's actual quota.

## Field problems

- A single “Amplify plan price” would hide at least five backend services. Hosting, model inference, delivery, logs, backups and optional support can add more. Fields need component, Region, billing mode and account-offer eligibility alongside price.
- Recurring service allowances, an account that expires, an expiring credit balance and a legacy trial cannot share one free-tier flag. Account/payer/organization-wide usage also prevents assigning the full allowance to every app independently.
- The small database workload does not specify bytes, strong/eventual reads, scans, index writes, resolver fan-out or peak requests per second. Explicit one-item assumptions produce a useful subtotal but not a capacity guarantee or a universal database quote.
- DynamoDB/S3 vendor GB are binary. The file scenarios explicitly select vendor GB; the vector raw-byte example shows both binary and decimal conversion. Do not silently compare those raw sizes to another vendor's decimal GB price.
- Ten database “connections” is not a direct SQL connection requirement for an AppSync/DynamoDB API. Existing SQL through a proxy is a separate architecture, with provider capacity and fees.
- The job machine assumption does not map exactly to Lambda: 512MB is configurable but 0.5vCPU is not independently selected. Billed initialization, request payload size, retry source and account concurrency also matter. Ordinary function waiting must not inherit a durable-workflow suspended-wait price.
- A database backup cannot be labelled an Amplify project backup. Records, Cognito identities, S3 versions/files, configuration, secrets, artifacts and routing need component-specific exit/recovery steps. Deletion protection, retention policy and sandbox delete also have distinct effects.
- Vector limits now apply to a real DynamoDB feature, but a generated Amplify integration is still a different fact. Metadata projection, tenant authorization and base-table encoding must be collected rather than inferring them from a vector badge.
- “Self-managed hosting” refers to ownership of AWS frontend resources. The self-host field cannot imply on-premises Cognito/AppSync/DynamoDB or an included server machine. Blocks local runtime remains a separately labelled Preview path.
- C21 arithmetic is our calculation. The required state vocabulary has no derived state, so supported arithmetic is labelled confirmed and kept conditional where a complete invoice is unknown. C22 is a research-method row, not a product feature.
- No apps.md row error found. Its broad backend description remains correct. No index, fields, excluded or notes file was edited; no code/database/commit action was performed.
