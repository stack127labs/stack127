## Cost examples — our calculation

These are **our calculations**, not vendor checkout quotes or a server benchmark. The selected software has **US$0 license/subscription cost**. That does not make hosting or delivery free.

Inputs: one publication/user, one verified sender domain, shared SES sending IP, one recipient per message, no attachments, no introductory credits, no other campaign/confirmation/test traffic, and a full month of server operation. Extra sends change usage. Paid-reader revenue, SMS, ads and optional integrations are excluded.

### Named setup and formula

- **Software:** listmonk **v6.2.0**, free under AGPLv3. Sources checked 2026-11-05: https://listmonk.app/docs/ ; https://github.com/knadh/listmonk/releases/tag/v6.2.0 ; https://raw.githubusercontent.com/knadh/listmonk/v6.2.0/LICENSE .
- **Hosting:** one DigitalOcean Basic Regular Droplet, **2 GiB RAM, 1 vCPU, 50 GiB SSD, 2,000 GiB transfer, US$12/month**. Our setup is Ubuntu, the versioned listmonk image/binary, local PostgreSQL 16 and an HTTPS reverse proxy. It is a planning choice, not the vendor's minimum or a tested 50,000-reader installation. Sources checked 2026-11-05: https://www.digitalocean.com/pricing/droplets ; https://listmonk.app/docs/installation/ .
- **SMTP connection:** the server's primary IPv4 connection to the selected SES region using **STARTTLS on port 2587** and provider credentials. DigitalOcean documents blocks on 25/465/587; AWS explicitly supports 2587. This avoids those named blocked ports, but actual connectivity was not tested. Sources checked 2026-11-05: https://docs.digitalocean.com/products/droplets/details/limits/ ; https://docs.aws.amazon.com/ses/latest/dg/smtp-connect.html ; https://listmonk.app/docs/configuration/ .
- **Sender:** Amazon SES **Essentials**, **US$0.16 per 1,000 recipient emails** in the first tier; no fixed Essentials account fee is listed. The selected sender plan was checked independently for this app. AWS also offers à la carte US$0.10/1,000, which is a different plan choice. No credits or introductory benefits are deducted. Source checked 2026-11-05: https://aws.amazon.com/ses/pricing/ .
- **Additional/unpriced:** backups, domain, tax, maintenance labor, any applicable provider data/optional-service charges and changes needed after capacity testing. No external managed-support tariff is assumed. Sources checked 2026-11-05: https://aws.amazon.com/ses/pricing/ ; https://listmonk.app/docs/configuration/ ; https://listmonk.app/docs/upgrade/ ; https://raw.githubusercontent.com/knadh/listmonk/v6.2.0/LICENSE .

For `E` recipient emails per month:

```text
listmonk software = US$0
Known server component H = US$12/month
SES Essentials component A(E) = (E / 1,000) × US$0.16
Known monthly subtotal R(E) = US$0 + H + A(E)
Known first-month subtotal = R(E), because no license purchase is required
```

The known subtotal is **not an exact all-in total**. The workload must fit the real server and the approved SES account/region quota. The source's configurable default throughput is not permission to exceed provider limits.

### Newsletter examples

Four campaigns per month, one to every unique subscribed contact, with each campaign on a separate day. Daily campaign peak is **1,000 / 5,000 / 10,000 / 50,000 recipients**, respectively. Obtain an adequate rolling 24-hour quota and use actual provider-approved pacing.

Our model sets concurrency=1 and message_rate=1, for at most one campaign recipient/second under the documented configuration formula. It does not use the fresh-install 10×10 setting as a performance claim. The largest 50,000-recipient campaign takes at least 50,000 seconds at that pace before overhead; no completion guarantee is inferred. Production access is required because even the smallest example exceeds the SES sandbox daily cap.

## Field problems

- **F04/F07/F08/F11:** a free self-hosted edition has no central customer checkout, timed trial or purchased credit pool. Those specific subfields are not applicable; they must not be rewritten as free hosting, unlimited sending or universal country access.
- **F09/F10/F12:** costs need software, a named server and sender plan. The result is a known subtotal, not a fixed all-in bill. SMTP connectivity matters to this setup; the named alternate port was checked.
- **F15/F17/F30:** global blocklisting, per-list unsubscribe, privacy wipe, bulk CSV and per-subscriber JSON have different scopes. A single export=yes field would hide meaningful migration and consent limits.
- **F21:** transactional triggering by an external application is not proof of a native sequence/workflow product. No unverified sequence-length scenarios are needed for the direct transactional API cost model.
- **F28/F39:** software maintainer provenance, website policies, an installation's data location and the selected providers' contracts cannot be collapsed into one hosted-service operator/region value.
- **F33/F34:** stable/beta names and GitHub flags need review. The docs' frontend/source-build path must not become a requirement to install a compiler for a prebuilt binary.
- **F37/F38:** resource-use claims and millions of sends do not demonstrate inbox placement. The official-only proof rule did not yield a qualifying independent controlled delivery study.
