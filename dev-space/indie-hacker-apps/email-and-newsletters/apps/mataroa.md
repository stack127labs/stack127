## Conflicts and unknowns

- **Policy and deletion code disagree on scope.** Methodology promises immediate primary-server deletion of all account-related information, plus 20-day backup erasure. In the inspected source, the subscriber model uses a nullable `SET_NULL` owner relation, and `UserDelete` deletes the user without explicit subscriber cleanup. This is an observed policy/source mismatch, not a live deletion test or proof that no additional production cleanup exists. Relevant sources: https://mataroa.blog/about/methodology/, https://raw.githubusercontent.com/mataroablog/mataroa/main/main/models.py and https://raw.githubusercontent.com/mataroablog/mataroa/main/main/views/general.py. A full newsletter-erasure claim needs clarification before publication.
- **Privacy covers less than the integration documentation.** Methodology presents Stripe as the exception to its third-party-sharing statement, names Hetzner/Scaleway infrastructure, and provides server/backup locations. README describes a Postmark inbound integration, and the notification source uses SMTP. Complete email-processing terms, log locations and a DPA were not established. Do not infer Finland/France-only email processing. Pages checked: https://mataroa.blog/about/methodology/, https://github.com/mataroablog/mataroa, https://raw.githubusercontent.com/mataroablog/mataroa/main/main/management/commands/processnotifications.py and https://mataroa.blog/guides/post-by-email/.
- **Large-audience pricing remains open.** The homepage’s 15,000-address limit is soft and says a future plan may be introduced. Neither Premium nor Free has a demonstrated 50,000-reader entitlement. Pricing, limits, Methodology, API and source were checked; no hard monthly email quota, overage tariff, sender approval deadline or recipient-country matrix was found. A free software licence and the operator’s transparency-page email bill are not customer tariffs.
- **Newsletter export is not proven by content export.** The public export page lists five content formats. API docs cover posts/comments/pages. The subscriber model and author list view expose email records, but no documented CSV audience route or consent/unsubscribe archive was established. The export-source file failed to fetch in both raw and GitHub routes. Sources checked: https://mataroa.blog/export/, https://mataroa.blog/api/docs/, https://raw.githubusercontent.com/mataroablog/mataroa/main/main/models.py, https://raw.githubusercontent.com/mataroablog/mataroa/main/main/views/general.py, https://raw.githubusercontent.com/mataroablog/mataroa/main/main/urls.py and attempted https://raw.githubusercontent.com/mataroablog/mataroa/main/main/views/export.py. Do not record subscriber export as “no” from that gap.
- **Hosted versus source version.** The public v1.5 release explicitly announces HTML newsletters and inline images; current sender code includes a text alternative. Older third-party claims of raw-text-only sending were leads, not evidence. The exact live hosted commit was not verified. The release listing rendered “03 Jan” without a year; the version and 2026 maintenance evidence are retained without guessing that release date. Sources checked: https://github.com/mataroablog/mataroa/releases, https://github.com/mataroablog/mataroa/commits/main/ and https://raw.githubusercontent.com/mataroablog/mataroa/main/main/management/commands/processnotifications.py.
- **Daily scheduling is not an immediate campaign sender.** README schedules notifications at 10am server time. Source chooses yesterday’s posts and active subscribers. Exact hosted timezone, service throughput, missed-day replay and provider retry deadlines were not established. Local unique send records do not prove exactly-once delivery. API, operations docs and sender code were inspected; no lifecycle engine, general SMTP relay or customer delivery webhook API was found.
- **Domains and branding have distinct meanings.** The custom-domain guide concerns one website domain and TLS. Source has a provider-configured mail From domain and editable blog footer. Own hosted sending/tracking-domain controls, exact email branding-removal support and authentication alignment remain unknown. Export docs mention redirects without the Premium/grandfathering condition present in source. Sources checked: https://mataroa.blog/guides/custom-domain/, https://mataroa.blog/export/, https://raw.githubusercontent.com/mataroablog/mataroa/main/main/models.py and https://raw.githubusercontent.com/mataroablog/mataroa/main/main/views/general.py.

Native 2FA, customer-team roles, email tracking disable switches, bounce/complaint thresholds and sender IP choices remain unestablished. Web analytics explicitly count bots/reloads; they are not human opens. Security reporting address: https://github.com/mataroablog/mataroa/blob/main/SECURITY.md. ## Field problems

- F07/F09 need separate audience limits, monthly sends and throughput. Mataroa publishes a soft audience threshold but no quantified email quota. The three smaller free-price examples therefore retain an `unclear` workload qualification.
- F12/F34 require two editions: hosted use includes website/email, while self-hosting needs a sender and server. The named external-provider example is a partial cost estimate, not Mataroa’s hosted bill or a capacity test.
- F13/F14/F16 must not mistake an author’s Premium renewal for reader monetisation. Native paid-reader functionality was not demonstrated.
- F15/F30 are more useful when content export, subscriber-list export, token unsubscribe, account deletion and backup deletion remain separate. The generic “all data” wording is too broad to settle newsletter completeness.
- F18/F24 separate website domains/TLS from email sender identity, domain authentication and tracking domains.
- F19/F21/F23 need version scope. Release/source evidence can explain behaviour without proving the exact hosted revision or a live retry guarantee.
- F28 needs an email-specific processor disclosure or DPA; a server location and a general sharing promise do not settle routing and processing regions.
