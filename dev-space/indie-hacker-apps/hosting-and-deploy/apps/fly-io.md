## Cost examples — our calculations

Calculation date: 2026-11-04. These are our calculations from the linked official inputs, not Fly.io's example totals. One commercial builder, one custom hostname, private source cloned locally, 20 builds × 5 minutes = 100 build minutes, no optional support, no reserved annual credits and no startup/trial credits. Domain registration and applicable taxes are outside the hosting figures. Shared IPv4 is sufficient for the HTTP workloads. No external CI runner is required by the selected local-source-to-remote-builder route.

Source inputs, all checked 2026-11-04:

- [Current resource tariff](https://docs.fly.io/about/pricing.md): iad/ewr Machine prices; 30-day/720-hour Machine month; USD 0.02/GB North American internet egress; same-region private traffic free; currently free builders/registry/pulls; first 10 ordinary certificates included; no separate HTTP request-count meter listed for these Machines.
- [Pricing page](https://fly.io/pricing/): the shared-cpu-1x/256MB table's embedded hourly rate is USD 0.0030474 in the iad default region. The visible hourly display rounds this to USD 0.0030 and the 30-day display to USD 2.19; embedded monthly value is USD 2.194128. Calculation uses the less-rounded published page data, not 730 × the rounded USD 0.0030 display. The same page advertises waiving invoices under USD 5, without complete eligibility terms.
- [Billing](https://docs.fly.io/about/billing.md): allocated Machine usage is per second; its 1GB example uses shared CPU with 1024MB configuration. [CPU allocation](https://docs.fly.io/machines/cpu-performance.md) shows why a shared vCPU cannot be equated with a full continuously available performance core.
- [Static deployment](https://docs.fly.io/languages-and-frameworks/static.md), [ordinary deployment](https://docs.fly.io/launch/deploy.md) and [domains](https://docs.fly.io/networking/custom-domain.md): static web server in an image; source-to-image path; one hostname with managed TLS. One Machine must be explicitly selected instead of the default redundant pair.
- [Managed Postgres pricing](https://docs.fly.io/postgres.md): Starter 2GB at USD 72/month, storage USD 0.28 per used GB per 30 days on current v2, prorating, same-region database traffic free. [Product page](https://fly.io/mpg.md) gives a 10GB starting capacity and rolling 10-day backup retention; [support documentation](https://docs.fly.io/about/support.md) explicitly states daily snapshots are included. Restoring creates another cluster.
- [Terms](https://fly.io/legal/terms-of-service.md): USD and taxes additional. No measured throughput or real deployment is implied by a calculated capacity price.

### A. Small commercial static site

Inputs: 100MB generated files packaged with a static web server; 1,000,000 HTTP requests; 100GB outbound; 100 build minutes; one hostname. Select one shared-cpu-1x/256MB Machine in iad, running 730 hours. No persistent volume, additional IP, external CDN or database is required for this design.

Formula:

- Compute: 730 h × USD 0.0030474/h = USD 2.224602.
- Internet egress: 100GB × USD 0.02/GB = USD 2.
- Builders, registry/pulls, one ordinary certificate, shared IPv4/IPv6: USD 0 under the current listed inclusions.
- Gross modeled hosting subtotal: USD 2.224602 + USD 2 = **USD 4.224602**, displayed **about USD 4.22 before tax**.

If the advertised under-USD-5 waiver applies to this organization's final invoice, the payable invoice could be USD 0. Complete waiver conditions are not established, so the gross estimate remains visible and this is not called an ongoing free plan. Additional apps/services in the same billing organization could put an invoice above the threshold. The app's traffic capacity and transient deployment resource use are unverified. Files use the deployed image/rootfs; a permanent extra volume is not added just to store a generated 100MB website.

### B. Small commercial app API

Inputs: 1,000,000 requests; 100ms processor work and 250ms elapsed per request; 256MiB working memory; 100GB outbound; 100 build minutes; same source/domain. Use one shared-cpu-1x with the documented 1GB/1024MB configuration, iad, 730 running hours.

The workload contains 100,000 seconds of processor work and 250,000 seconds of summed request elapsed time. These are workload descriptions, **not billing units** for this always-on Machine. No conversion from vCPU allocation into function execution pricing is made. The memory configuration meets the target only on the stated assumption that its MB notation represents binary memory units; literal 1GiB equivalence was not verified. The low shared-CPU baseline and burst policy also mean actual workload fit needs a deployment/load test.

Formula from the rounded published monthly rate:

- Compute estimate: USD 6.70 × 730/720 = USD 6.79305556.
- Egress: 100GB × USD 0.02/GB = USD 2.
- Listed required build/registry/TLS/shared-IP items: USD 0.
- Conditional modeled subtotal: **USD 8.79305556**, displayed **about USD 8.79 before tax**.

This is a conditional estimate, not an exact verified compliant-workload total. The tariff's rounded monthly 1GB quote limits precision. A larger allocation, extra live deployment Machine, worker, IPv4, fixed egress address or monitoring exporter would add charges. An always-started Machine has no stopped-rootfs period in this model, so no stopped-rootfs fee is added on top of its entire running time. A second retained standby is excluded explicitly.

### C. App plus persistent data

Use B's conditional application estimate plus Managed Postgres **Starter, 2GB**, in iad. Its advertised memory exceeds 1GiB without treating Basic's 1GB label as a proven binary quantity. Basic's USD 38 starting price is therefore not used as an unquestioned compliant database quote. Set initial storage capacity to at least 10GB. Daily snapshots and rolling 10-day backup retention cover the required daily/7-day policy without purchasing a separate backup tier. Put app and database in the same region: the 10GB/month app/database traffic adds USD 0 under the same-region rule.

Current v2 storage is based on use, whereas the workload specifies capacity. Define **S = average used database GB during the billed period**. For a transparent 730-hour illustration, normalize monthly plan and storage pricing to a 30-day/720-hour period. The storage rate explicitly uses this basis; applying the same basis to the plan fee is a calculation assumption, not a separately stated exact plan-hour tariff.

Formula:

- App B: approximately USD 8.79305556.
- Database Starter: USD 72 × 730/720 = USD 73.
- Used storage: S × USD 0.28 × 730/720.
- Included daily backups, HA, pooling and same-region traffic: no separate fee in the published plan.
- Conditional subtotal: **USD 81.79305556 + (USD 0.28388889 × S)** before tax.
- If S = 10GB throughout: USD 8.79305556 + USD 73 + USD 2.83888889 = **USD 84.63194445**, displayed **about USD 84.63 before tax**.

The 10GB used amount is our explicit illustration, not proof that a newly allocated 10GB database is fully used. The complete exact bill is not determinable from capacity alone, rounded Machine pricing, uncertain memory units and unspecified temporary deployment activity. B's capacity qualification remains. Do not double-charge separate self-managed database Machines/volumes or volume snapshots for an included managed cluster. A restore cluster kept alongside the source, cross-region placement or a self-managed database design would need another estimate.
