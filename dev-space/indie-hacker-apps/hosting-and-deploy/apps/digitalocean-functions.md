**Current status and notices:** DigitalOcean Functions is still publicly offered with Functions-specific get-started links and a documented first-namespace creation workflow. No official whole-product retirement or existing-customers-only notice was found in the [product](https://www.digitalocean.com/products/functions), [current pricing](https://www.digitalocean.com/pricing/functions), [namespace guide](https://docs.digitalocean.com/products/functions/how-to/create-namespaces/) or [release notes](https://docs.digitalocean.com/release-notes/functions/), checked **2026-11-05**. ## Cost examples: our calculations

Calculation date: **2026-11-05**. Region selected: **AMS3**, which appears in both the current availability table and namespace-creation guide. Currency: **USD**; [invoice help](https://docs.digitalocean.com/support/how-do-i-update-my-contact-and-company-details-on-my-invoice/) confirms USD billing. Published Functions pricing is not split by region. These are ordinary monthly-usage examples before buyer-specific tax, with no startup credit, annual discount or optional paid support.

Each example is independent. Assume the team's **90,000 GiB-second monthly allowance is unused elsewhere**. Standalone and App Platform functions share it. The allowance does not roll over and is not granted again for each namespace. Sources: [Functions pricing FAQ](https://www.digitalocean.com/pricing/functions) and [pricing docs](https://docs.digitalocean.com/products/functions/details/pricing/), checked 2026-11-05.

The common build input is **20 × 5 minutes = 100 minutes**. [Build docs](https://docs.digitalocean.com/products/functions/reference/build-process/) allow local builds for suitable runtimes. Our standalone illustration uses **Node.js 24 with pure JavaScript dependencies**, built locally from a private Git working repository. This is customer-managed work, not a claim of free hosted CI minutes; local hardware/electricity is outside the cloud invoice. [Node.js docs](https://docs.digitalocean.com/products/functions/reference/runtimes/node-js/) require remote builds for native dependencies.

**A single five-minute remote function build does not fit the documented two-minute cap.** App Platform Functions always uses remote building. Preserving the full five-minute input therefore needs a supported local-build workflow, or a changed build/artifact pipeline whose feasibility/cost must be verified. Do not silently substitute a two-minute build for the supplied five-minute workload. Sources: [limits](https://docs.digitalocean.com/products/functions/details/limits/) and build guide above, checked 2026-11-05.

### A. Small commercial static site

Inputs: **100 MB deployed files, 1,000,000 HTTP requests, 100 GB outbound, the common builds/private source, one custom domain**.

**Not applicable as a native standalone Functions static-host plan.** Files can be [included with function code](https://docs.digitalocean.com/products/functions/how-to/include-files/), but that does not provide the site deployment/domain/CDN workflow of a static host. A function-backed implementation must satisfy the **48 MB final-artifact limit** and **1 MB response limit**. The build guide allows a ZIP as the final artifact, so 100 MB of source assets is not automatically proof the compressed artifact exceeds the limit; per-file response sizes and compression are unspecified.

App Platform static sites are a different product, even when they call Functions. Their bill is not presented as a Functions total. A proxy or external object/static store would also need to be selected and priced.

For a hypothetical function-backed implementation using **512 MiB = 0.5 GiB**, let `d` be actual execution seconds per request and apply the [pricing FAQ's rounding rule](https://www.digitalocean.com/pricing/functions):

`billed seconds per call = max(0.1, ceil(d / 0.1) × 0.1)`

`Functions cost = max(1,000,000 × 0.5 × billed seconds − 90,000, 0) × USD 0.0000185`

This gives a formula, **not a completed A quote**. Runtime, delivery fit, custom-domain front end, standalone transfer, logs and any external storage are unresolved. The supplied monthly traffic total cannot determine execution time. All inputs/sources checked 2026-11-05.

### B. Small commercial app API

Inputs: **1,000,000 requests/month; 100 ms useful CPU work; 250 ms elapsed per request; 256 MiB application working memory; 100 GB outbound; the common builds/private source/custom domain**.

Select a **512 MiB** function to allow memory above the application working set for runtime overhead. This is a chosen capacity assumption, not the published minimum or a tested throughput guarantee. The [public pricing examples](https://www.digitalocean.com/pricing/functions) explicitly equate 512 MiB with 0.5 GiB.

Use 250 ms as the modeled execution duration. The current pricing FAQ rounds to the nearest **100 ms upward**, so:

`billed duration = ceil(250 / 100) × 100 ms = 300 ms = 0.3 seconds`

`usage = 1,000,000 × 0.5 GiB × 0.3 seconds = 150,000 GiB-seconds`

`paid usage = max(150,000 − 90,000, 0) = 60,000 GiB-seconds`

`Functions subtotal = 60,000 × USD 0.0000185 = USD 1.11/month`

There is **no separate request-count fee**. The 100 ms of useful CPU work is not substituted for elapsed execution time. This is a function model, so the schema's 730-hour/1-vCPU server model is not used. Actual billing can change with real initialization/execution behavior, runtime memory needs, other team usage and failed/retried requests.

The workload averages below the documented **600 invocations/minute** cap when spread over a month, but its unspecified bursts may not fit. No load test was performed. Source: [Functions limits](https://docs.digitalocean.com/products/functions/details/limits/), checked 2026-11-05.

The standalone local-build path has a generated HTTPS function URL. A native standalone custom-domain mapping/certificate workflow and an exact standalone outbound tariff were not established in the checked docs. **Do not call USD 1.11 the full public-app cost.** Let `P` be the selected custom-domain delivery/proxy service and certificates, `E` standalone transfer, and `L` any selected long-term log destination:

`B = USD 1.11 + P + E + L`

An App Platform Functions component is the documented integrated-domain alternative, but changes the deployment path and applies [App Platform bandwidth pricing](https://docs.digitalocean.com/platform/billing/bandwidth/). It also needs a build pipeline satisfying the Functions remote-build cap. A complete quote for that alternative was not established, so its base/transfer cost is not guessed.

For reference, App Platform excess transfer is **USD 0.02/GiB**, after its actual app/team allowance. The given **100 GB decimal** equals **100,000,000,000 / 1,073,741,824 = 93.1322574615… GiB**. If `A` is the applicable available allowance, its transfer formula is `max(93.1322574615… − A, 0) × USD 0.02`. The free static-only app's allowance must not automatically be assigned to a Functions-only app. Region/currency basis is AMS3/USD; sources checked 2026-11-05.

### C. App plus persistent data

Add **DigitalOcean Managed PostgreSQL Standard, single primary node, 1 GiB RAM/1 vCPU, with at least 10 GiB storage**, to B. That meets the requested **1 GiB RAM and 10 GB storage** capacity threshold; 10 GiB is larger than 10 GB. No standby/read-only node is selected. This is separately managed database capacity, not a database inside the function.

Two public sources differ:

- [PostgreSQL docs](https://docs.digitalocean.com/products/databases/postgresql/details/pricing/) say single-node plans begin at **USD 15/month**, 1 GiB RAM.
- The visible [managed database pricing table](https://www.digitalocean.com/pricing/managed-databases#postgresql) lists **USD 15.15/month** and **USD 0.02254/hour** for Standard 1 GiB/1 vCPU, alongside a **10 to 30 GiB storage range** and **USD 0.215/GiB-month** storage-increment wording.

These are published USD figures used for an AMS3 design, not a verified logged-in regional order. Keep the source units and the mismatch visible. The hourly and monthly displays are not multiplied by 730 and treated as identical. The exact storage inclusion/current checkout combination was not resolved.

[Daily PostgreSQL backups retained seven days](https://docs.digitalocean.com/products/databases/postgresql/how-to/restore-from-backups/) meet the stated recovery policy. Restoring creates a new primary cluster; destroying the database also destroys those backups. The [database pricing guide](https://docs.digitalocean.com/products/databases/postgresql/details/pricing/) says traffic to/from managed databases does not count against bandwidth billing transfer allowance, so the named **10 GB/month app-to-database flow** is not treated as arbitrary paid internet egress.

[Functions limits](https://docs.digitalocean.com/products/functions/details/limits/) explicitly say PostgreSQL connection pools are unsupported. The [App Platform networking limits](https://docs.digitalocean.com/products/app-platform/details/limits/) also exclude Functions from VPC and dedicated-egress-IP capabilities. Use a supported connection/authentication route and validate connection capacity; no private-network deployment was tested.

**Our conditional component sums**, excluding unresolved storage/bill details and delivery/log costs:

`USD 1.11 Functions + USD 15.00 documented database starting price = USD 16.11`

`USD 1.11 Functions + USD 15.15 visible table price = USD 16.26`

These are **two illustrative subtotals, not bounds for a complete C bill**. A complete total still needs the resolved database/storage quote, any additional backup billing, custom-domain front end, standalone transfer and chosen log service. App/code rollback does not restore database contents. All sources and calculations checked 2026-11-05.
