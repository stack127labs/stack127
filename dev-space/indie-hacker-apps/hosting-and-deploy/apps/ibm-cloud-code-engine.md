## Cost examples — our calculations

Calculation date: 2026-11-05. Region: **Dallas, US South (`us-south`)**. Currency: **USD**, using USA/USD entries of the [regional tariff](https://globalcatalog.cloud.ibm.com/api/v1/814fb158-af9c-4d3c-a06b-c7da42392845:us-south85303/pricing), effective 2026-11-01 and checked 2026-11-05. These are partial estimates before buyer-specific taxes. Each scenario is independent and assumes its account allowances are unused elsewhere: 27.8 vCPU-hours, 55.5 GB-hours and 0.1 million requests. Other projects and builds can consume the same allowances.

Common choices: one builder, normal usage billing, no introductory credit, no optional support, an existing custom domain, and a customer-maintained no-fee certificate. Domain registration is outside the hosting estimate. The [domain guide](https://cloud.ibm.com/docs/codeengine?topic=codeengine-domain-mappings) explains the TLS secret and certificate renewal work (checked 2026-11-05). Code Engine is not assumed to renew the customer's custom certificate automatically.

For the 20 builds of 5 minutes, the main model builds locally from a private Git working repository and pushes an image to private GitHub Container registry with credentials. This is **self-managed build work**, not free IBM build capacity or proof that any particular build finishes in five minutes. No paid Git automation is assumed. [Code Engine's local-source workflow](https://cloud.ibm.com/docs/codeengine?topic=codeengine-app-local-source-code) and [private-registry authentication](https://cloud.ibm.com/docs/codeengine?topic=codeengine-code-repositories) support these deployment paths; [GitHub's billing policy](https://docs.github.com/en/billing/concepts/product-billing/github-packages) currently makes container image storage and bandwidth free (all checked 2026-11-05). Local hardware/electricity is not priced. A paid builder or registry would add its own bill.

For comparison, choosing IBM's small managed builder instead adds 100 minutes of allocated 0.5 vCPU and 2 GB memory. At the Dallas rates, **our gross calculation before shared allowances** is:
`(100/60 × 0.5 × 0.1235) + (100/60 × 2 × 0.0128) = USD 0.145583333…`.
This assumes the supplied five minutes cover the full billed build run; source/image transfer or startup outside that interval adds usage. Source: [build sizes](https://cloud.ibm.com/docs/codeengine?topic=codeengine-plan-build) and [billing rules](https://cloud.ibm.com/docs/codeengine?topic=codeengine-pricing), checked 2026-11-05.

### A. Small commercial static site

Inputs: 100 MB deployed files, 1,000,000 external HTTP requests, 100 GB outbound, 20 five-minute local builds, a private source repository and one custom domain. Select a 0.125 vCPU/0.25 GB application, with minimum zero instances, serving files from the image. That allocation is listed in the [resource guide](https://cloud.ibm.com/docs/codeengine?topic=codeengine-mem-cpu-combo), checked 2026-11-05. The complete image must meet platform constraints; no deployment or load test was performed.

Let `H` be the sum of running instance-hours, including startup time. Request count and data size do not specify `H`; simultaneous instances also contribute. Using the live tariff:

`CPU = max(0.125H − 27.8, 0) × USD 0.1235`

`RAM = max(0.25H − 55.5, 0) × USD 0.0128`

`HTTP = max(1 − 0.1, 0) × USD 0.538 = USD 0.4842`

**Known request subtotal: USD 0.4842.** Complete cost is `CPU + RAM + 0.4842 + N100 + L`, where `N100` is the unresolved charge for the specified 100 GB outbound route and `L` is any selected production log/monitoring service. Runtime hours and a complete transfer tariff were not established, so **no exact hosting total** is published. Production logging is recommended separately by the [logging guide](https://cloud.ibm.com/docs/codeengine?topic=codeengine-logging), not assumed to be included free. All calculation sources checked 2026-11-05.

### B. Small commercial app API

Inputs: 1,000,000 requests, assumed 100 ms useful CPU work and 250 ms elapsed per request, 256 MiB working memory, 100 GB outbound, and the same builds/domain. Select the smallest documented app combination with at least 1 vCPU and 1 GiB RAM: **1 vCPU/2 GB**. Set minimum and maximum instances to one and model **730 running hours**, excluding extra rollout/startup time. Sources: [resource combinations](https://cloud.ibm.com/docs/codeengine?topic=codeengine-mem-cpu-combo), [scaling](https://cloud.ibm.com/docs/codeengine?topic=codeengine-app-scale) and [billing](https://cloud.ibm.com/docs/codeengine?topic=codeengine-pricing), checked 2026-11-05.

The capacity model uses **1,460 GB-hours**, even though the app's assumed working set is smaller. The useful-CPU and request-elapsed assumptions do not reduce charges on an allocated, always-running instance.

`CPU = (730 − 27.8) × USD 0.1235 = USD 86.7217`

`RAM = (730 × 2 − 55.5) × USD 0.0128 = USD 17.9776`

`HTTP = (1 − 0.1) × USD 0.538 = USD 0.4842`

**Known compute and request subtotal: USD 105.1835, or USD 105.18 rounded to cents.** The regional tariff is linked above. Full cost is `105.1835 + N100 + L + extra rollout/startup resource usage`. The local-build path has no IBM source-builder charge; the optional managed-builder calculation is separate.

This is not a complete hosting total or a performance guarantee. Actual capacity, image/build fit, external network charges, log usage and taxes remain unverified. A scale-to-zero app or managed function would have a different allocation/duration model; we do not substitute 100 ms of useful CPU work for that model.

### C. App plus persistent data

Use B, plus an **external IBM Cloud Databases for PostgreSQL Standard deployment with two data members**, each selected with **4 GB RAM and 10 GB disk**. That means **8 GB allocated RAM and 20 GB replicated physical disk**, representing 10 GB logical database storage. The [database pricing guide](https://cloud.ibm.com/docs/databases-for-postgresql?topic=databases-for-postgresql-pricing) explains member aggregation and backup charging (checked 2026-11-05). It contains inconsistent small-memory examples, so this calculation avoids depending on the smaller figure.

The guide states daily backups are retained **30 days by default**, satisfying at least seven days of retention, and includes backup storage equal to total purchased deployment disk. Our selection therefore has 20 GB included backup capacity. Actual retained backup size is unknown; a seven-day-only retention configuration was not established. Application rollback does not restore PostgreSQL data.

Let `Dpg` be the current Dallas/USD database quote for that configuration, `Bextra` any backup capacity beyond inclusion, and `Ndb` the charge for 10 GB/month app-to-database traffic over the selected route:

`C = USD 105.1835 + Dpg + Bextra + Ndb + N100 + L + extra rollout/startup usage`.

**No complete C total is published.** The database pricing guide/calculator, [catalog](https://cloud.ibm.com/catalog/services/databases-for-postgresql) and [public catalog discovery](https://globalcatalog.cloud.ibm.com/api/v1?q=name:databases-for-postgresql&complete=true) were checked on 2026-11-05, but a verified current Dallas quote for this exact configuration was not obtained. Unscoped illustrative database dollar figures are not treated as Dallas prices. Code Engine object-storage mounts are not used to self-host the database because their filesystem semantics are unsuitable.
