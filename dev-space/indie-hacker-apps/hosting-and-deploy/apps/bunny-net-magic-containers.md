Read the [volume behavior and failure rules](https://bunny.net/docs/magic-containers/persistent-volumes) before treating a single-instance database as protected storage.

## Cost examples — our calculations

Calculated on 2026-11-05; all linked inputs checked the same day. Select **one standard paid dynamic pod in Frankfurt**, one replica, no automatic regional expansion, one paying builder, no trial/startup credits or annual discount, and **730 running hours**. The standard runtime is the documented 8-CPU/32-GiB ceiling, billed on usage; it is not a fixed-price reservation of those resources. It exceeds the comparison's minimum capacity, but no deployment or performance test proves throughput. Source: [runtime/account limits](https://bunny.net/docs/magic-containers/limits).

Prices below retain the published **$** symbol. The checked bunny.net pricing/terms did not establish a definitive ISO currency code; no currency conversion or claim of identical checkout currencies is made. All amounts exclude tax, per [tax policy](https://bunny.net/docs/billing/sales-tax).

Use a **CDN endpoint**, Standard tier, with all 100 GB delivered in Europe/North America. The delivery component is **100 × $0.01 = $1**. This is the CDN bill, not a Magic Containers allowance. Magic Containers excludes CDN-routed bytes from its own egress meter, so the same response is not charged twice. We do not attach a separately billed Anycast IP. Sources: [Magic Containers prices](https://bunny.net/docs/magic-containers/pricing), [endpoint types](https://bunny.net/docs/magic-containers/endpoints), [CDN Standard prices](https://bunny.net/docs/cdn/pricing) and [CDN request-fee policy](https://bunny.net/pricing/).

One custom subdomain uses the endpoint Pull Zone's CNAME and free auto-renewing Let's Encrypt certificate. Domain registration is outside the estimate. No Optimizer, Edge Script, WebSocket connection plan, Shield upgrade or paid support is selected. Sources: [hostname setup](https://bunny.net/docs/cdn/custom-hostname) and [free managed TLS](https://bunny.net/docs/cdn/ssl-setup).

A separate external logging destination or longer retention would need its own price.

### Common compute formula and uncertainty

From [CPU/RAM metering](https://bunny.net/docs/magic-containers/pricing):

`CPU charge = consumed CPU-seconds × 0.02 / 3600`

`RAM charge = sum(hourly billed 64-MB blocks) × 0.0003125`

The second formula uses the page's stated block rate, not its inconsistent 512-MB worked example. Billable memory includes **variable system overhead**. The page does not fully define an intra-hour maximum/average sampling rule, so steady-memory arithmetic below is a labelled model, not an invoice prediction.

**Memory-unit assumption:** the nominal examples treat the source's 64-MB block as 64 MiB, consistent with its approximate sixteen-blocks-per-GB convention. That byte basis is not explicitly verified. If the block instead means exactly 64,000,000 bytes, 256 MiB needs five blocks and 1 GiB needs seventeen blocks before overhead, rather than four and sixteen. The general block formula remains valid; the numerical memory subtotals are conditional on the stated interpretation.

The account minimum is `max($1, applicable account usage)`, rather than an extra $1 for each container/zone. The selected CDN delivery alone reaches $1. Source: [account-wide minimum](https://bunny.net/docs/billing/add-funds). Retained volumes and IPs keep billing under [negative-balance rules](https://bunny.net/docs/billing/negative-balance).

### A. Small commercial static site

**Compatible in a serving container; exact compute unknown.** Put the 100 MB static files inside an HTTP-serving image, then expose a CDN endpoint. Deployed file size is not resident memory or CPU time. Cache hits may avoid origin work; the fixed workload supplies no cache-hit ratio, origin CPU duration or RAM footprint. Sources: [container/endpoints deployment](https://bunny.net/docs/magic-containers/deploy) and [ephemeral resource ceiling](https://bunny.net/docs/magic-containers/limits).

Let C_A be all billed CPU-seconds and B_A the sum of hourly billed memory blocks. Our monthly formula is:

`A = $1 CDN + C_A × 0.02 / 3600 + B_A × 0.0003125`

As a **billing floor illustration only**, a continuously resident one-block process for 730 hours would add:

`730 × 0.0003125 = $0.228125 RAM`

That gives **$1.228125 plus CPU**, before any extra memory blocks/overhead. This is not a claim that the chosen web server/site actually fits one block. There is no persistent-volume charge selected for files already in the image. Private repository, current GHCR image storage, local builds and selected managed certificate have the choices described above. **No complete A total is published.**

### C. App plus persistent data

Use a **self-managed PostgreSQL container in the same pod** as B, one region/replica, with a selected **10 GB persistent volume** and **at least 1 GiB additional database-memory allowance**. No public database endpoint/Anycast IP is needed. PostgreSQL and the app communicate over localhost; the fixed 10 GB/month app-to-database traffic does not leave the pod as external egress. Sources: [PostgreSQL deployment](https://bunny.net/docs/magic-containers/guides/postgresql) and [same-pod networking](https://bunny.net/docs/magic-containers/multi-container).

The operator owns PostgreSQL configuration, upgrades, credentials and backups. Multiple replicas would create independent databases with separate volumes, so do not autoscale this design as though it were a replicated managed database. Volume hardware failure can lose data. Sources: [single-instance database guidance](https://bunny.net/docs/magic-containers/guides/postgresql) and [volume failure/scaling behavior](https://bunny.net/docs/magic-containers/persistent-volumes).

Additional model costs:

- Database nominal resident memory: `16 blocks × 730 × 0.0003125 = $3.65`, before overhead.
- Live database volume: `10 GB × 0.10 = $1/month`.
- B plus those two lines: `2.468055… + 3.65 + 1 = $7.118055…`.
- Add actual database CPU, backup CPU, extra memory/overhead and deployment overlap. Their usage is unspecified by the fixed workload.

Configure a **daily logical dump with seven-day retention**, implemented by a scheduler/backup process the builder maintains. Store copies outside the volume, for example **Bunny Storage Standard/HDD, single Frankfurt region**, priced separately at $0.01/GB-month. PostgreSQL documents logical export/restore using pg_dump and psql/pg_restore; this is not an automatic Magic Containers backup. Sources: [PostgreSQL backup/restore](https://www.postgresql.org/docs/current/backup-dump.html), [Storage regions/pricing](https://bunny.net/docs/storage/pricing) and [Storage monthly pricing calculator](https://bunny.net/pricing/storage/).

- Retained backup storage: `7 × 10 × 0.01 = $0.70/month`.
- Magic Containers direct backup-upload egress from Europe: `30 × 10 × 0.01 = $3/month`.
- Storage API operations/egress: no separate fee under the selected Storage offer.
- Combined partial illustration: `7.118055… + 0.70 + 3 = $10.818055…`.

The 10-GB export size is **our assumption**, not derived from provisioned database capacity; compression, actual data, WAL, roles and temporary files can change it. Those thirty exports are an explicit monthly-backup assumption alongside the comparison's 730 running hours. If more copies overlap during rotation, retained storage rises. An alternative internal transfer exemption was not established, so the example uses the published direct-egress meter rather than assuming free cross-product transfer.

**No complete C total is published.** The formula still needs actual database/backup CPU, memory overhead and a tested backup/restore setup. No app release rollback restores database contents. The single-pod volume design can also have deployment downtime, per [volume-backed rolling updates](https://bunny.net/docs/magic-containers/rolling-updates).
