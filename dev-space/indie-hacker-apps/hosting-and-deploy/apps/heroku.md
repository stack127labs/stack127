### A. Small commercial static site

Inputs: 100MB deployed files, 1,000,000 HTTP requests, 100GB outgoing, 100 build minutes, one private source repository and one custom hostname. Formula for known line items:

- Maximum modeled single-dyno running time: 730 hours; 730 ≤ 1,000 pooled hours, leaving 270 hours for this account before other consumers.
- Eco subscription = USD 5, regardless of whether traffic causes it to sleep and use fewer hours.
- Ordinary builds = 100 minutes × USD 0 build charge = USD 0.
- Ordinary custom-domain ACM = included; no permanent external file store is required for immutable files packaged in the deployed artifact.
- **Known hosting subtotal = USD 5/month before tax. Full model = USD 5 + T_app(100GB). Complete exact total: unknown.**

For an always-on alternative, one Basic dyno has a USD 7 monthly compute ceiling. The 100GB traffic quantity is below the 2TB soft limit, but that limit is not sufficient evidence to set T_app to zero. No claim that the million-request load will meet a latency target on 0.5GB shared compute is made.

## Field problems

- **06/15 — CPU equivalence:** Cedar dynos use relative CPU share and performance bands; Fir uses vCPU counts with a Space fee and eligibility gate. The example must not turn 2x into two vCPUs or rank a Space dyno without its environment cost. GB is not silently renamed GiB.
- **07/15 — time basis:** prorated resource usage and monthly ceilings are not the same thing as an exact hourly tariff. The 730-hour scenario needs a calendar/provisioning window to become a precise invoice calculation. Eco's flat monthly pool must be treated separately.
- **11/15 — transfer evidence:** the public soft bandwidth limit does not by itself price traffic. The required formula can be shown, but an exact comparable total should remain unknown until a current authoritative transfer rule is found.
- **02/16/33 — availability of editions:** new Enterprise contracts are closed, but eligible credit-card Teams have a separate Space route. A simple “Enterprise required” label would conceal the current access distinction.
- **19/25/28 — framework features:** an ordinary Node server and streaming-capable router do not prove a shared persistent framework cache. Ephemeral app files and pipeline artifact promotion need to remain separate from saved user data and database recovery.
- **17/31 — backup scope:** physical protection, customer rollback and daily logical backups have different availability, retention and locations. “Backups included” needs a plan, backup type, enabled schedule and restore path.
- **35/36 — self-host fields:** not applicable to the hosted platform. Image/app maintenance remains user work, but there is no customer-installed Heroku control plane to size or license in this offer.
