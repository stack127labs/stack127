## Cost examples: our calculations

Calculated on 2026-11-05. All amounts below are EUR before tax for a Paris deployment (`fr-par`). Registry, Managed PostgreSQL, its block volume and its snapshots are separate products. No Functions or Serverless Jobs rates enter these calculations.

Common inputs: one commercial builder; normal monthly usage; no promotional credits, annual discount or optional support. Domain registration is excluded. The custom-domain/TLS workflow is documented in [the domain guide](https://www.scaleway.com/en/docs/serverless-containers/how-to/add-a-custom-domain-to-a-container/); [the FAQ](https://www.scaleway.com/en/docs/serverless-containers/faq/) confirms automatic certificate renewal and integrated invocation load balancing. Containers pricing lists CPU and RAM rather than separate domain, TLS or request tariffs. Because the product FAQ contradicts that metering description, the amounts are labelled known subtotals rather than guaranteed complete invoices.

For all three examples, build the private source repository locally, using the [documented Docker workflow](https://www.scaleway.com/en/docs/serverless-containers/how-to/build-push-container-image/). Twenty five-minute builds require `20 × 5 = 100 minutes` on the builder's own machine. No Scaleway build service is bought; that does not mean hosted CI is included or that local electricity/hardware is free. All required images, layers and retained releases are assumed to average **1 GB of private registry storage** during the month, in Paris. This is our additional storage assumption, not the specified size of the deployed site or an included quota. [Registry pricing](https://www.scaleway.com/en/pricing/containers/): `1 GB × €0.027/GB/month = €0.027/month`. Upload and same-region pulls are free. Larger retained image history raises this amount.

[Default logs/metrics](https://www.scaleway.com/en/docs/serverless-containers/how-to/monitor-container/) are free at the documented retention. [Containers ingress and egress](https://www.scaleway.com/en/docs/serverless-containers/faq/) are free, so the specified 100 GB outgoing traffic contributes €0 on the Containers side. No optional CDN, external gateway, paid support or paid observability retention is selected. These scope choices are not claims that those products are free.

### A. Small commercial static site

Inputs: 100 MB deployed static files, 1,000,000 requests, 100 GB outbound, 100 local build minutes, private source repository, one custom domain. Package the files in an HTTP-serving image. This is a running web server, not object/CDN-only static hosting.

For a deterministic capacity example, select one instance throughout 730 hours, minimum and maximum scale both 1, **70 mvCPU and 128 MB**. These CPU/memory values are used together in [Scaleway's billing example](https://www.scaleway.com/en/docs/serverless-containers/faq/). Its explicit memory convention is `128 MB = 0.125 GB`; that convention is preserved here. The storage limit and architecture restrictions remain applicable.

Our calculation, using [Paris rates and monthly allowances](https://www.scaleway.com/en/pricing/serverless/):

- Runtime: `730 × 3600 = 2,628,000 instance-seconds`.
- CPU: `0.070 × 2,628,000 = 183,960 vCPU-s`; `max(183,960 − 200,000, 0) × €0.00001 = €0`.
- Memory: `0.125 × 2,628,000 = 328,500 GB-s`; `max(328,500 − 400,000, 0) × €0.000002 = €0`.
- Known compute plus private image-storage subtotal: `€0 + €0.027 = €0.027/month`.

Assumptions: no other Containers consume these account allowances; 730 hours is total instance runtime, so any deployment overlap/startup usage must be included or added. We have not deployed or load-tested this very small allocation. Fitting 100 MB of files in the image does not prove that 128 MB RAM/70 mvCPU can deliver the requested traffic pattern. **This is an allocation-based subtotal, not a verified €0.027 production hosting quote.** Scaling above one instance or using paid CI changes it.

### B. Small commercial app API

Specified workload: 1,000,000 requests, 100 ms active processor work and 250 ms elapsed per request, 256 MiB working memory, 100 GB outbound, and the same builds/domain as A.

Use an always-available capacity example: **1000 mvCPU and 1024 MB**, one instance for 730 hours, min/max scale 1. The [official Next.js container tutorial](https://www.scaleway.com/en/docs/tutorials/hosting-nextjs-webapp-serverless-containers/) documents this valid CPU/RAM pair. Applying the FAQ's displayed memory convention gives 1 billing GB for 1024 displayed MB; the [v1 migration guide](https://www.scaleway.com/en/docs/serverless-containers/reference-content/v1-migration-guide/) identifies the older API memory unit as MiB. The allocation meets the comparison's 1-vCPU/1-GiB capacity floor. This is a chosen always-on model, not a claim that every API must buy that much capacity.

Our calculation:

- CPU: `max(1 × 2,628,000 − 200,000, 0) × €0.00001 = €24.28`.
- Memory: `max(1 × 2,628,000 − 400,000, 0) × €0.000002 = €4.456`.
- Compute subtotal: `€24.28 + €4.456 = €28.736/month`.
- Compute plus assumed private registry: `€28.736 + €0.027 = €28.763/month`.

These unrounded arithmetic results do not promise invoice precision. This model pays for provisioned runtime rather than converting 100 ms of processor work into a CPU entitlement. The specified work implies `1,000,000 × 0.1 = 100,000 processor-work seconds` and `1,000,000 × 0.25 = 250,000 summed elapsed-request seconds`; neither determines instance runtime when requests overlap, scaling occurs or warm capacity is retained. A scale-to-zero alternative therefore needs a traffic/concurrency pattern and clarified runtime accounting before an exact cost can be calculated.

Default monitoring, Containers transfer and integrated delivery follow the common assumptions. Account allowances must be unused elsewhere; A and B are independent comparisons, not simultaneous apps receiving duplicate free allowances. Workload throughput, latency, peak memory and uptime are untested.

### C. App plus persistent data

Keep B, then buy a **separate Managed PostgreSQL** instance in Paris. The [creation guide](https://www.scaleway.com/en/docs/managed-databases-for-postgresql-and-mysql/how-to/create-a-database/) supports a standalone configuration with selectable block volume capacity; [Block Storage documentation](https://www.scaleway.com/en/docs/block-storage/faq/) lists 5 GB to 15 TB capacity. Choose DB-DEV-S (2 vCPU, 2 GB) and 10 GB of Block Storage 5K. The [Paris database price table](https://www.scaleway.com/en/pricing/managed-databases/) lists €0.0156/hour for the main node, €0.0993/GB/month for that volume, and €0.03/GB/month for snapshots/backups.

[Database autobackups](https://www.scaleway.com/en/docs/managed-databases-for-postgresql-and-mysql/how-to/manage-backups/) default to once per day with seven-day retention. Block Storage uses snapshots. This meets the requested schedule if left enabled. It does not establish that all seven snapshots consume exactly 70 GB or that snapshots are included in the node fee.

Our calculation:

- Database main node: `730 × €0.0156 = €11.388`.
- Database block volume: `10 × €0.0993 = €0.993`.
- Known database node plus volume: `€11.388 + €0.993 = €12.381`.
- Let `S` be the billable average retained snapshot/backup GB during the month. Backup storage: `S × €0.03`.
- B plus database subtotal: `€28.763 + €12.381 + €0.03S = €41.144 + €0.03S/month`, before any unresolved database-side transfer charge.
- Illustrative storage sensitivity only: if `S = 70 GB`, snapshot storage is `70 × €0.03 = €2.10`, making the displayed subtotal €43.244. **70 GB is our assumption, not a documented snapshot consumption figure.**

Attach the app and database to a Private Network for the specified 10 GB/month app-to-database traffic. [Containers' network integration](https://www.scaleway.com/en/docs/serverless-containers/reference-content/containers-private-networks/) adds no attachment charge; the Containers side has free transfer. A database-side private-traffic tariff was not established in the [database pricing](https://www.scaleway.com/en/pricing/managed-databases/), [database FAQ](https://www.scaleway.com/en/docs/managed-databases-for-postgresql-and-mysql/faq/) or creation guide, so it is not silently made €0. No public gateway is selected for same-network connectivity. A complete C total remains unknown because snapshot billable size and that remaining network treatment are unverified.

Restoring from a snapshot can create another billed database instance, as the creation guide explains. Retained snapshots can survive instance deletion. Neither an application redeploy nor its 24-hour fallback restores PostgreSQL data.
