## Current status and lifecycle notices

**Active core product. No whole-product shutdown, sunset or acquisition notice was found in the checked official product, pricing, documentation and product-team updates.** Sources: [home](https://azure.microsoft.com/en-us/products/container-apps/), [price](https://azure.microsoft.com/en-us/pricing/details/container-apps/), [whatsnew](https://learn.microsoft.com/en-us/azure/container-apps/whats-new), [septupdate](https://github.com/microsoft/azure-container-apps/issues/1846). Checked 2026-11-05.

- **Service Connector Preview retired March 30, 2026.** Existing connections remain active; future connections need manual documentation/template setup. This does not retire Container Apps. [serviceconnect](https://github.com/microsoft/azure-container-apps/issues/1566). Checked 2026-11-05.
- **Functions on Container Apps V1 retires September 30, 2027.** The product-team notice says affected apps stop processing after that date; move to V2. Ordinary container apps are a different scope. [functionretire](https://github.com/microsoft/azure-container-apps/issues/1843). Checked 2026-11-05.
- **Inactive/legacy environment notices:** a June 25, 2026 announcement describes restorable archiving and Express migration for a notified subset. Generic environment docs separately describe automatic deletion after over 90 days under specified conditions. Do not promise universal indefinite retention or a universal migration deadline. [archive](https://github.com/microsoft/azure-container-apps/issues/1772), [environment](https://learn.microsoft.com/en-us/azure/container-apps/environment). Checked 2026-11-05.
- **Legacy logging support changed:** the HTTP Data Collector API's support ended September 14, 2026. Current migration guidance says TLS-compliant ingestion continues with critical security fixes only and directs eligible environments to Azure Monitor. Express has a documented exception. [logmigrate](https://learn.microsoft.com/en-us/azure/container-apps/migrate-logs-azure-monitor). Checked 2026-11-05.

Scope: ordinary Azure-hosted Container Apps with Consumption and Dedicated profiles, plus relevant distinctions for legacy Consumption-only environments, Flex Preview, Express and other variants. Separate Azure products retain their own bills and limits. The cost examples do not assume App Service resources, an included database, free Azure Container Registry, or paid logging by default.

### A. Small commercial static site

Workload: **100 MB files, 1,000,000 HTTP requests, 100 GB outbound, 100 build minutes, one private source repository and one custom domain**. Run a compatible static-file web server in a Linux amd64 image. Select **0.25 vCPU/0.5 GiB**, minReplicas=0; all running replicas are active-rate because the nonzero-minimum idle conditions do not apply. Memory, startup and serving duration must fit the actual implementation. Let **S** be the summed running seconds of all app replicas and relevant revisions during the month, including starts, scale-in waiting and deployment overlap. Source files/request/GB totals do not determine S.

| Hosting item | Our calculation, East US USD |
| --- | --- |
| Allocated CPU | max(0.25 × S − 180,000, 0) × USD 0.000024/vCPU-second |
| Allocated memory | max(0.5 × S − 360,000, 0) × USD 0.000003/GiB-second |
| External requests | max(1,000,000 − 2,000,000, 0) × USD 0.40/1,000,000 = USD 0 |

| Local builds/private source | 100 self-managed minutes; no selected paid hosted build service |
| **Selected hosting expression** | **USD 0.0000075 × max(S − 720,000, 0)** |

### B. Small commercial app API

Workload: **1,000,000 requests**, **100 ms useful CPU** and **250 ms elapsed time per request**, **256 MiB working memory**, **100 GB outbound**, same builds/domain. To follow the server resource rule, select **1 vCPU/2 GiB** for **730 hours**, min/max baseline replicas=1. This is the smallest documented Consumption combination with at least one vCPU; 1 vCPU/1 GiB is not an allowed combination. The assumed 256 MiB working set does not reduce billed memory. Source: [containers](https://learn.microsoft.com/en-us/azure/container-apps/containers), [scale](https://learn.microsoft.com/en-us/azure/container-apps/scale-app); checked 2026-11-05.

Our arithmetic:

- Useful CPU work: 1,000,000 × 0.100 seconds = **100,000 CPU-seconds**.
- Aggregate request elapsed time: 1,000,000 × 0.250 seconds = **250,000 request-seconds**.
- Baseline replica time: 730 × 3,600 = **2,628,000 seconds**.
- Allocated memory time: 2 GiB × 2,628,000 = **5,256,000 GiB-seconds**.

The first two numbers do not determine the active-rate duration. Concurrent requests overlap, starts are billed, and CPU/network activity can keep a replica active beyond request work. No equal-performance or measured-capacity claim is made.

Let **A** be active baseline replica-seconds and **I** idle-eligible baseline seconds, with A+I=2,628,000. Before grants, allocated compute is:

**A × (USD 0.000024 + 2 × USD 0.000003) + I × (USD 0.000003 + 2 × USD 0.000003) = USD 23.652 + A × USD 0.000021.**

Both active and idle memory have the same rate. Assuming the pooled grants are otherwise unused:

- Chargeable total CPU allocation is 2,628,000−180,000 = **2,448,000 vCPU-seconds**. Depending on active/idle usage, those units cost between **USD 7.344** at the idle rate and **USD 58.752** at the active rate.
- Chargeable memory is 5,256,000−360,000 = **4,896,000 GiB-seconds**, costing **USD 14.688**.
- Therefore the **baseline allocation envelope is USD 22.032–73.440**, or **USD 22.03–73.44 rounded to cents**. The lower envelope is a billing bound, not an assumption that an API handling requests is always idle.

**Fully active reference:** (2,628,000−180,000) × USD 0.000024 + (5,256,000−360,000) × USD 0.000003 = **USD 73.44**. Without any remaining resource grants, all-active baseline compute would be 2,628,000 × USD 0.000030 = **USD 78.84**. These are our calculations from [appapi](https://prices.azure.com/api/retail/prices?currencyCode=%27USD%27&$filter=serviceName%20eq%20%27Azure%20Container%20Apps%27%20and%20armRegionName%20eq%20%27eastus%27%20and%20priceType%20eq%20%27Consumption%27), [billing](https://learn.microsoft.com/en-us/azure/container-apps/billing) and [price](https://azure.microsoft.com/en-us/pricing/details/container-apps/); checked 2026-11-05.

The selected million external requests and 100 GB internet egress have no added charge under the shared allowances. The registry, builds, certificate and logging choices are as specified above. Additional replicas during a revision rollout have their own allocated seconds and are **outside this one-replica baseline envelope**. It is not an enforced spending cap or exact complete workload bill; actual active/idle duration, rollout overlap and application capacity remain unverified.

For a separate Dedicated comparison, a single **D4 node** has 4 vCPU/16 GiB: 730 × [(4 × USD 0.057077/vCPU-hour) + (16 × USD 0.004978/GiB-hour) + USD 0.10/environment-hour] = **USD 297.80788**, or **USD 297.81 rounded to cents**, East US USD. This includes one Dedicated management fee and no optional private-endpoint/maintenance/premium-ingress features. It is not the selected API plan or a per-app price; multiple apps can share the node, with some resources reserved for the platform.
