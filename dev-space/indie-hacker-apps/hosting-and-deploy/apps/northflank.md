### Shared inputs and missing quantities

- Build duration: 20 × 5 minutes = 100 minutes = 5/3 hours.
- Select the smallest priced build-capable allocation nf-compute-400-16, 4 vCPU/16 GiB, listed at $0.20/hour in the public plan API. Our allocation-rate illustration is $0.20 × 5/3 = $0.333333333333333. This assumes five minutes is the charged duration for each run, no retries and no additional charged setup/upload time.
- Runtime monthly figures are display equivalents, not an established cap. The pricing widget's own conversion uses 720 hours. B requires 730 allocated hours; copying $18/month as its compute charge would ignore those ten hours.
- API hourly prices use coarser rounding than the widget. For example, $2.70/720 = $0.00375/hour, while the public API displays $0.004/hour. Both price precisions remain visible where relevant.
- Stored build images cost $0.08/GB-month. Let I be the actual time-weighted retained image storage for an example. A's 100 MB deployed files does not supply its container base layers, image history, retention or billable GB-months.
- Logs/metrics cost $0.20/GB above the first 10 GB/month. Let L be aggregate billable observability volume for the example's team; C combines app and database under that allowance.
- Backup storage costs $0.08/GB-month. Let B_C be native-dump GB-months under C's daily/seven-day policy. Logical database size does not determine compressed export size.
- Let X_C be C's charge for 10 GB app-to-database traffic. A private connection is supported, but its precise billing exemption/rate was not established, so X_C is not silently set to zero.
- Preserve original units. RAM specs define MiB/GiB; the main persistent-disk rate uses GiB-month. Transfer, images, backups and observability use GB labels; their byte definitions are not silently normalized.
