## Cost examples: our calculations

Calculated 2026-11-04. One paying builder, public commercial product, private personal source repository, existing custom domain, monthly Pro, no trial/startup credits or annual discount, no support package. Existing domain registration excluded. USD before applicable tax; tax rate depends on billing address. Plan/credit: https://vercel.com/docs/plans/pro-plan ; tax: https://vercel.com/docs/pricing/taxes . All calculation sources checked 2026-11-04.

Select paid Pro, explicitly enable lowest Flat Rate CDN tier, and select Basic build machine instead of new-team Elastic default. Basic has 2 vCPUs/8 GB/32 GB and costs $0.007 per elapsed build minute. A/B/C use ordinary application delivery, with no media-download service, paid Static IPs, image optimization, optional analytics, Plus telemetry or custom multi-service deployment. Native Git integration needs no separate build runner. GitHub Free is a documented supported provider; a source-provider plan with private repo access remains the builder's responsibility: https://vercel.com/docs/git . Capacity and actual performance are untested.

Let `U` be usage eligible for credit, `X` separate subscription/add-on charges, and `T` applicable tax. Base model `bill = $20 + max(0,U − $20) + X + T`. Do not subtract the credit from the platform fee. Paid seats, external DB subscription and other separately billed services are outside this usage pool. The $20 credit resets/expires, without rollover: https://vercel.com/docs/plans/pro-plan .

### A. Small commercial static site

Fixed inputs: 100 MB deployed assets; 1M HTTP requests; 100 GB outbound/month; 20 builds × five minutes; private repo; one custom domain. Select static output, no runtime Functions or origin proxy. Commercial policy requires Pro: https://vercel.com/docs/limits/fair-use-guidelines .

- Delivery/request charge: $0 extra within enabled included tier of 1M requests/1 TB. Count is exactly the request boundary: redirects, preview visits or other team traffic would add to it. Sources: https://vercel.com/docs/pricing/flat-rate-cdn ; https://vercel.com/docs/manage-cdn-usage .
- Builds: `20 × ceil(5) × $0.007 = $0.70`. Preview and production builds are not assumed to have separate free pools. Sources: https://vercel.com/docs/pricing ; https://vercel.com/docs/builds/managing-builds .
- Retained deployment storage is mandatory to account for: `S_A × $0.10/GB-month`, with `S_A` obtained from daily maximum retained output. In a chosen bounded illustration, retain at most 20 outputs, each 100 MB, plus no old deployments. Explicit decimal illustration `100 MB = 0.1 GB` gives an upper bound `20 × 0.1 = 2 GB`, hence at most `$0.20/month` if retained the whole month. This is a conservative added storage assumption, not Vercel's verified byte-unit definition or a claim of exact deduplication. Source: https://vercel.com/docs/deployment-storage .
- Certificate: automatic ordinary certificate; no paid custom-certificate option selected. Source: https://vercel.com/docs/domains/working-with-ssl .
- Formula: `U_A = 0.70 + 0.10×S_A`; bounded illustration `U_A ≤ $0.90`, covered by $20 credit. Conditional result **$20/month before tax** for this selected configuration. Full invoice depends on retained history and unrequested team activity. Original workload alone lacks retention and ingress shape, so the bounded result is not a universal total.

If Flat Rate is disabled, iad1 on-demand illustration for the stated outbound/request quantities is `100×$0.15 + 1×$2 = $17` before build/storage; other delivery regions vary. This is an alternative pricing mode, not an extra $17 added to the Flat Rate illustration. Source: https://vercel.com/docs/pricing/regional-pricing/iad1 . New-team Elastic example at constant four assigned cores would make the same builds `100×4×$0.0035 = $1.40`; actual Elastic assignment varies. Never silently quote Basic while leaving project on Elastic.

### B. Small commercial API

Fixed inputs: 1M requests, 100 ms active CPU work/request, 250 ms elapsed/request, 256 MiB working memory, 100 GB outbound, same builds/repo/domain. Select Node Fluid Functions, iad1, standard 2 GB/1 vCPU allocation. This is function billing; do not impose an unrelated 730-hour server allocation. Sources: https://vercel.com/docs/functions/configuring-functions/memory ; https://vercel.com/docs/functions/usage-and-pricing .

- Let `I_B` be actual billed instance seconds, including supported instance reuse/concurrency behavior. Provisioned memory formula `2 GB × I_B/3600 × $0.0106`. In an explicit nonoverlapping-request illustration `I_B = 1M×0.250 = 250,000`, so memory `138.888888... GB-hours × 0.0106 = $1.472222...`. Multiple concurrent requests can share memory; startup/occupancy and rounding remain unresolved, so request-elapsed sum is not asserted to be actual billed lifetime. Source: https://vercel.com/docs/functions/usage-and-pricing .
- Invocations: `1M/1M × $0.60 = $0.60`, following explicit pricing prose despite N/A summary cell. Same source above. Failed/retried calls would add usage.

If the stated 100 GB is the full origin-to-CDN response bytes and inbound requests are additionally `R_B` GB, component is `(100+R_B)×$0.06`. The 100 GB outbound component alone is `$6`; request bodies/headers are not silently zeroed. Sources: https://vercel.com/docs/manage-cdn-usage ; https://vercel.com/docs/pricing/regional-pricing/iad1 .
- CDN delivery/request usage fits selected Flat Rate tier under A's no-extra-traffic assumptions. Basic builds $0.70; deployment and Functions Storage add `0.10×(S_B+Q_B)`, where each is its own billed GB-month metric. Function bundle size/retention not specified. Source: https://vercel.com/docs/deployment-storage .

For the nonoverlapping instance illustration and only the stated 100 GB origin response component, known usage is `$3.555555... + $1.472222... + $0.60 + $6 + $0.70 = $12.327777...`. ### C. API plus persistent data

Fixed additional inputs: one Postgres with at least 1 GiB memory and 10 GB storage; daily backups retained seven days; 10 GB/month app/DB traffic. Select **direct Neon Launch** as external dependency, one root branch, 0.5 CU fixed compute, same-region deployment where available, scale-to-zero disabled for a conservative 730-hour database illustration. This is not a Vercel-managed database or guaranteed Marketplace invoice quote. Marketplace/provider distinction: https://vercel.com/docs/storage .

- Neon 0.5 CU supplies approximately 2 GB RAM and uses shared compute. This avoids calling vendor 1 GB at 0.25 CU equal to the required 1 GiB. Memory quantity exceeds 1 GiB under decimal or binary GB interpretation; throughput untested. Source: https://neon.com/docs/manage/computes .
- Database compute: `.5 CU × 730 h × $0.106/CU-hour = $38.69`. Native Postgres storage at exactly 10 billed GB-months: `10×$0.35 = $3.50`. Compute plus database storage `$42.19`. Source: https://neon.com/pricing . Paid plan can disable scale-to-zero: https://neon.com/docs/introduction/compute-lifecycle .
- Configure daily snapshots and seven-day retention. Schedule defaults off, and scheduled snapshot billing is first full snapshot plus subsequent incremental delta bytes, at `$0.09/GB-month`. Let `K` be actual billed retained snapshot GB-months: backup component `0.09×K`. Do not assume seven full 10 GB copies or free backups. Source: https://neon.com/docs/guides/backup-restore .
- Optional point-in-time history is distinct from daily snapshots. If retained, add `$0.20×H`, where `H` is billable changed-data GB-months in selected history window. Neither the required ten GB data size nor ten GB app/DB transfer supplies `H`. Source: https://neon.com/pricing .
- Neon Launch's 500 GB/project/month public-transfer allowance covers at most ten GB specified traffic absent unrelated usage; additional egress `$0.10/GB`. Vercel-side external DB traffic treatment and extra app memory/CPU during DB waits must be checked in actual usage. It is not the same meter as edge-to-function HTTP transfer. Sources: https://neon.com/pricing ; https://vercel.com/docs/manage-cdn-usage ; https://vercel.com/docs/functions/usage-and-pricing .
- Formula: `Vercel_bill_C + $38.69 + $3.50 + 0.09×K + 0.20×H + any_extra_provider_transfer_or_add-ons + applicable_tax`. With conditional Vercel hosting subtotal $20, known hosting/database compute/storage components sum to **$62.19 before snapshots/history/tax**. This is not a complete total. Backup churn, actual compute occupancy, external transfer classification and optional history prevent an exact comparable invoice.

The daily seven-day schedule is supported by the chosen provider, but still must be enabled. Restoring a Vercel deployment does not restore Neon data, reverse migrations or undo external actions. Plan a separate database restore. No claim of cross-provider restoration has been tested.
