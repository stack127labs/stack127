# Tencent Cloud Serverless Cloud Function

**Status and lifecycle:** SCF remains a public international offer. From **January 1, 2027 at 00:00 UTC+8**, Tencent stops new creation of Node.js 6.10/8.9 functions, Custom Runtime functions, Serverless applications, image-generation AI applications, Agent applications and K8s-hosted functions. Existing resources may continue operating; other SCF functions/features are outside this adjustment. See the [international announcement](https://intl.cloud.tencent.com/announce/detail/101561), checked 2026-11-05. This is a feature-creation retirement, not a whole-SCF shutdown.

### C. App plus persistent data

**Dependency: TencentDB for PostgreSQL, not part of SCF.** Select a **cloud-disk High Availability primary, one core/2 GiB, at least 20 GB disk**. The main international calculator and official indexed copy were also tried. The billing guide advises logging in for accurate prices, which was outside this research's rules. Therefore database instance and disk unit prices remain **check_failed**, not zero or assumed unpublished. No Jakarta/large-instance worked example is substituted.

For a coherent 30-day calendar-month example, the database runs **720 hours**. The app itself remains invocation-billed as in B. Let q1, q2 and q3 be the unknown Singapore USD/hour database instance rates for the published usage-duration tiers, and d be its unknown USD/GB-hour cloud-disk rate:

`DB instance + disk = 96 × q1 + 264 × q2 + 360 × q3 + 20 × 720 × d`

The tier boundaries are first 96 hours, then hours above 96 through 360, then the remainder, per [PostgreSQL pay-as-you-go billing](https://indonesia.tencentcloud.com/document/product/409/39560). This formula does not treat a primary/standby pair as two independently quoted nodes; the actual product quote must define its instance rate.

Set automatic daily physical full backup and **seven-day retention**, with real-time incremental backups as documented in [backup guide](https://indonesia.tencentcloud.com/document/product/409/34628). Cloud-disk backup allowance is `20 × 200% = 40 GB` for data and log backups combined. Excess backup storage in Singapore uses the outside-mainland rate:

`Backup excess = 0.00004118 × sum(max(combined backup GB in each hour − 40, 0))`
