## Cost examples: our calculation

Calculation date **2026-11-05**. These are our calculations, not copied vendor example totals. One paying builder and a commercial product, one custom domain, normal monthly subscription, no trial/startup credit, annual discount or optional support. The three scenarios are alternatives; C already includes B.

**Buyer/currency assumption:** use the advertised **EU EUR price**. Terms say currency follows buyer country, and non-EU checkout amounts are not published. **Starter EUR 9.99/month excludes VAT**. Domain registration is external and excluded; no currency conversion or estimated tax rate applied. Final checkout amount is the plan price plus applicable tax. The consumer withdrawal policy is not treated as a free trial for a commercial buyer.

Input sources, all checked 2026-11-05:

- [Plan prices](https://pethost.dev/#pricing), [shared machine model](https://pethost.dev/about/) and [billing/traffic terms](https://pethost.dev/terms/): Starter **2 vCPU, 3 GB project memory, 30 GB project SSD, EUR 9.99/month**; system reserve outside displayed project allocation; no metered requests, project, DB or traffic fees.
- [Compose deployment](https://pethost.dev/docs/deploy-docker-compose/), [public API model](https://pethost.dev/docs/api/) and [CLI](https://pethost.dev/docs/cli/): native source/image builds run on the VM; private GitHub repositories have explicit representation/access; named volumes persist; three prior source versions and image/build cache share disk.
- [Domain and SSL guide](https://pethost.dev/docs/custom-domain/): custom domain with automatic certificates/renewal, no added domain/certificate fee. Registration remains with buyer.
- [Postgres product](https://pethost.dev/postgres/) and [database/backup methods](https://pethost.dev/docs/api/): in-pod/on-machine database with no extra fee; nightly off-machine encrypted volume snapshots held 14 days, while machine backups enabled. Postgres page demonstrates a container memory limit of **1024m**; API sizes use bytes.
- [Retention](https://pethost.dev/privacy/) separates 30-day request logs, seven-day container output, project backups and longer account backup retention.

**Billing/time basis:** this is a fixed monthly subscription, not CPU-hour billing. The requested 730 hours are a capacity/always-on assumption. A normal 31-day billing period contains **31 × 24 = 744 hours**, so running for 730 hours within that period does not require a second monthly charge. That is our explicit timing assumption, not a Pethost hourly tariff. A different start/end that crosses a renewal can change payment timing; no fictitious 730-hour price conversion is applied.

### A. Small commercial static site

Inputs: **100 MB deployed files**, **1,000,000 HTTP requests/month**, **100 GB outbound**, **20 × 5 = 100 build minutes**, one private source repository and one custom domain.

Candidate: **Starter**. Use a Dockerfile/Compose static web server, or the documented generated static-site workflow. The Eleventy example builds source and serves output through Caddy; a generic static site can use its own image. Pethost builds on the VM, so working source/dependencies/build layers/images, not only the 100 MB deployed output, must fit the shared disk/memory.

| 100 GB outbound | Included, terms' throughput rule applies | EUR 0 extra |

| Named/static files, ordinary backup, request logs | Within machine/feature allocation | EUR 0 extra |

**Our hosting calculation: EUR 9.99/month excluding VAT.** Conditional on build/runtime/artifacts fitting Starter and the buyer granting the necessary GitHub access. No separately paid build provider, gateway or CDN is required by this route. Traffic is included at up to 1 Gbit/s, subject to the trailing-24-hour 100 Mbit/s average reduction rule. No million-request benchmark or universal build-memory fit claimed.

### B. Small commercial app API

Inputs: **1,000,000 × 0.1 = 100,000 CPU-seconds**; **1,000,000 × 0.25 = 250,000 elapsed request-seconds**; assumed **256 MiB working memory**; at least **1 vCPU/1 GiB** server capacity for **730 hours**; 100 GB outbound and A's private repo/builds/domain.

Candidate: **Starter, 2 vCPU/3 GB/30 GB**, the smallest published plan. It exceeds 1 GiB even if the advertised GB is interpreted as decimal; the source's GB label is not silently renamed GiB. Nothing sleeps. Its shared physical vCPU is a capacity label, not a proof of equal speed with another provider.

Formula: **EUR 9.99 machine + EUR 0 request/CPU-second overage + EUR 0 transfer overage + EUR 0 separate builds/logs/domain/SSL = EUR 9.99/month before VAT**, under the stated billing-period assumption. CPU work and elapsed times describe the workload, not the pricing meter. Actual concurrency, latency and sustained throughput are untested.

Keep sufficient memory/disk for source builds and retained images/logs; a busy builder shares the VM. A project that needs more capacity can fail or slow down without creating an automatic metered overage. Existing-VM upgrade behavior is not promised from the larger plan cards alone.

### C. App plus persistent data

Inputs: all of B plus **PostgreSQL with at least 1 GiB memory/10 GB data**, **nightly backups retained at least seven days**, and **10 GB/month app-to-database traffic**.

Candidate: **the same Starter machine**, app plus an explicitly configured PostgreSQL Compose service and named data volume. Native one-click Postgres is also included; its exact offered memory sizes are discoverable from machine metadata, which was not queried here. The following is **our explicit sizing allocation**, not a claim that native DB and app get separate provider reservations:

- Budget **1 GiB for the app and 1 GiB for PostgreSQL** inside the VM. For a customer Compose service, set the PostgreSQL container's memory limit accordingly; Pethost accepts ordinary Compose memory limits and its own Postgres example uses 1024m.
- **2 × 1 GiB = 2,147,483,648 bytes**, below even a decimal **3 GB = 3,000,000,000 bytes**. This is our unit calculation. The remainder covers other project/build work; source says the system's own reserve is outside the displayed project allocation. A memory limit is a cap, so avoid overcommitting other services.
- Budget **10 GB of the 30 GB project disk** for database data. Remaining capacity must cover app/source, image layers, previous versions, logs and working space. No independent 10 GB expandable DB disk is being purchased.
- App and DB share the machine's two vCPUs. This is our resource allowance, not dedicated physical CPU for each process.
- Named volume in nightly encrypted backups, retained **14 days**, covers the requested minimum seven-day daily recovery points when backups actually succeed and remain enabled. Check backup health; terms do not guarantee recovery.
- Use private linked/Compose service networking for **10 GB internal transfer**, with **EUR 0 extra** traffic charge.

Formula: **EUR 9.99 machine + EUR 0 additional PostgreSQL service + EUR 0 separate 10 GB disk within allowance + EUR 0 included snapshots + EUR 0 local 10 GB traffic = EUR 9.99/month before VAT**.

**Our conditional C hosting calculation: EUR 9.99/month excluding VAT.** The custom-Compose database route leaves database image upgrades/tuning to the builder; Pethost operates the VM/deployment/snapshot service. The included one-click database simplifies setup but remains colocated and capacity-sharing.

The nightly snapshot is taken from a running volume. Pethost describes Postgres recovery as like restart after a power cut. It is **not a continuous point-in-time recovery or application-consistent transaction backup guarantee**. A native dump for pg_restore is a different export path. Restoring an existing project stops services and replaces chosen volumes; ordinary code rollback preserves current volumes and does not reverse a schema change. No HA replica/failover or contractual data-loss or restore-time guarantee added to this example.
