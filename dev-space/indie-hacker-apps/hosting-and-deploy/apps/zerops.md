## Cost examples — our calculation

Calculation date: 2026-11-05. Inputs below are ours from fields.md. All tariff and feature sources were checked 2026-11-05. These are allocation estimates, not deployed benchmarks or exact invoices.

Use one paying builder, a lawful commercial product, a private source repository, one custom domain, monthly billing, no credits/annual discount and no optional support. Region: EU Central/prg1, an active documented origin. The published table gives no regional resource-price difference. Domain registration is excluded. Use the published USD prices, excluding taxes/fees; actual VAT depends on buyer circumstances. The US$10 minimum top-up is a deposit, not a mandatory recurring US$10 fee. Sources: https://docs.zerops.io/billing/pricing; https://docs.zerops.io/billing/overview; https://docs.google.com/document/d/e/2PACX-1vShf30OdwdQDQgasDJIx39jpcC9KJ5bMQVM2POUrGN0CIN0X60TTpeDv6XqoW9w64JcmKhjJ5A_Q7--/pub; https://status.zerops.io/.

### A. Small commercial static site

Inputs: 100 MB deployed files, 1,000,000 HTTP requests/month, 100 GB outbound, 20 builds × 5 minutes = **100 minutes = 1⅔ hours**, private source, custom domain. Choose one Static/Nginx service with 1 shared core, 0.25 GB RAM and 1 GB disk for 730 hours. The source permits serving the frontend build output directly. The 100-GB egress and 100-minute build workload fit the included project quotas when no other project use consumes them. No optional object store, paid log destination or advanced observability stack is selected. Sources: https://docs.zerops.io/static/overview; https://docs.zerops.io/features/pipeline; https://docs.zerops.io/billing/pricing; https://docs.zerops.io/references/networking/public-access.

**Our calculation:**

- 30-day service resources = 1 × US$0.60 + (0.25 / 0.25) × US$0.75 + (1 / 0.5) × US$0.05 = **US$1.45**.
- 730-hour resources = US$1.45 × 73/72 = **US$1.4701388889**.
- Included egress/builds, core, routing, certificates and ordinary project logger add **US$0 incremental** within the documented allowances.
- Selected IPv4 subscription = **US$3**.
- Allocation estimate = **US$4.4701388889 before tax**, approximately **US$4.47** rounded to two decimals.
- Same selected resource configuration with Serious = approximately **US$14.47**, before tax; free-address variant is US$3 less.

This is a selected small configuration, not an assurance it sustains the request mix without scaling. Static disk is the service's runtime disk, not an independently priced 100-MB CDN bucket. The homepage's 0.125-GB global minimum could make a smaller selection cheaper; this example chooses 0.25 GB explicitly. Private code can be built by authorized integration or uploaded with CLI; any existing source-host subscription is outside Zerops' hosting fee.

### C. App plus persistent data

Inputs: B plus one PostgreSQL database with at least 1 GiB memory and 10 GB disk; daily backups retained seven days; 10 GB/month app/database traffic. Select PostgreSQL single mode with **1 shared core, 1.125 published GB RAM and 10 GB disk**, on the same project, separately from the app allocation. This fits the documented customizable resource model; it has no HA redundancy. HA mode needs three database nodes and is the provider's recommended production arrangement. **Our calculation:**

- 30-day database resources = US$0.60 + (1.125 / 0.25) × US$0.75 + (10 / 0.5) × US$0.05 = **US$4.975**.
- Database resources over 730 hours = US$4.975 × 73/72 = **US$5.0440972222**.
- B plus database = US$7.1315972222 + US$5.0440972222 = **US$12.1756944444 base subtotal before tax**, approximately **US$12.18**.
- Complete C = base subtotal + actual backup overage + any billed 10-GB database transfer + tax. **Complete exact total: unknown.**

Set daily retention to seven, weekly/monthly minimums to zero and no extra protected/manual backups for the example; defaults otherwise retain four weekly and three monthly backups as well. PostgreSQL backups are compressed ZIP/custom-format dumps. Ten GB of allocated disk does not establish ten GB per backup, and the billing table lacks an explicit backup-overage time basis/rounding rule. Sources: https://docs.zerops.io/features/backup; https://docs.zerops.io/postgresql/how-to/manage; https://docs.zerops.io/billing/pricing.

Let Q be measured retained backup GB. The published overage **quantity formula**, before unspecified charge-period/rounding behavior, is max(Q − 5, 0) / 5 × US$0.50. For illustration only, seven assumed 10-GB full backups give Q = 7 × 10 = 70 GB, hence (70 − 5)/5 × US$0.50 = **US$6.50 per quoted overage charge unit**. This is our sensitivity calculation, not a measured monthly backup fee or an assumed compression ratio.

Same-project private traffic is documented; pricing defines charged egress as traffic out of the project. Treating the 10 GB internal flow as unmetered is a reasonable inference, but no explicit universal exemption was found in the checked billing/network terms, so it is not used to certify an exact total. If it were billed at the generic excess rate, the arithmetic would be 10 × US$0.02 = **US$0.20**; that is a conditional sensitivity, not an asserted fee. Sources: https://docs.zerops.io/references/networking/internal-access; https://docs.zerops.io/billing/pricing; https://docs.zerops.io/billing/overview; https://docs.google.com/document/d/e/2PACX-1vShf30OdwdQDQgasDJIx39jpcC9KJ5bMQVM2POUrGN0CIN0X60TTpeDv6XqoW9w64JcmKhjJ5A_Q7--/pub.

A database dump restore and a code rollback are distinct. Code rollback also restores earlier environment variables; neither recreates database contents as of that code version. No deployment, backup download or restore test was performed.
