### B. Small commercial app API

**Inputs:** 1,000,000 requests; 100 ms active processor work and 250 ms elapsed/request; 256 MiB working memory; 100 GB outbound; the same 100 build minutes, private source and one domain.

**Runtime fit: unverified.** HTTP server deployment is supported, but the checked operational docs do not publish a per-instance guaranteed RAM allocation, maximum heap, CPU allocation or a full request-limit table. The product's “unbounded” execution-time claim is insufficient to verify the workload. A server's 1-vCPU/1-GiB/730-hour rule is not applied to this Wasm hosting model.

**Active CPU calculation:**

- 1,000,000 × 100 ms = **100,000 seconds** active CPU.
- 100,000 ÷ 3,600 = **27.777777… active CPU hours**.
- Included CPU: **6 hours**.
- Excess CPU = (27.777777… − 6) × US$0.10 = **US$2.177777…**.
- Pro base plus this CPU component = **US$12.177777…/month**, or **US$12.18 rounded to cents**, before unknown memory/storage charges and tax.

**Memory illustration, not verified metering:** total request elapsed time = 1,000,000 × 0.250 s = 250,000 seconds. If only that request time at exactly 256 MiB were billed, 0.25 GiB × 250,000 ÷ 3,600 = **17.361111… GiB-hours**. If the vendor's GB means decimal GB, the corresponding byte conversion is 256 × 1,048,576 ÷ 1,000,000,000 × 250,000 ÷ 3,600 = **18.641351111… GB-hours**. Either is below the table's numeric 400 GB-hour allowance, but neither proves the bill: Wasmer calls the meter **provisioned memory**, and the working set, live idle instances, allocation rounding and runtime overhead can differ.

**Formula — our calculation:**

`B = US$10 + US$2.177777… + US$0.01 × max(actual billed provisioned-memory GB-hours − 400, 0) + actual package/volume storage charges + any compulsory unverified entitlement + applicable tax`.

Specified requests, 100 GB bandwidth, 100 build minutes, one app/domain remain within the listed allowances. No separate gateway/IP or paid log product is added without evidence; Pro lists one dedicated IP and two-week logs. Package size/retained history is not supplied for B. No extra mandatory log-drain fee was established. **Known base/CPU and listed included-meter subtotal: US$12.177777…; complete compatible total remains unknown.** [Pricing](https://wasmer.io/pricing), [runtime model](https://docs.wasmer.io/edge/architecture/), [idle/scaling caveats](https://docs.wasmer.io/edge/faq); checked 2026-11-05.

### C. App plus persistent data

**Inputs:** all of B plus PostgreSQL with ≥1 GiB RAM and 10 GB storage, daily backups retained seven days, and 10 GB/month app-to-database traffic.

**Selected dependency:** Wasmer's **native managed PostgreSQL**, in Roubaix or Beauharnois. Unlike an older Wasm PostgreSQL package, the current service is managed, persists across deployments and pins the app to the database region. No external database is silently substituted. [Database docs](https://docs.wasmer.io/edge/learn/databases), [September release](https://wasmer.io/posts/postgres-cronjobs-email-wasmer-edge); checked 2026-11-05.

**Compatibility/price blockers:**

- No published database memory allocation proves **≥1 GiB RAM**.
- No named 10 GB capacity plan, hard capacity limit or database size/proration algorithm was established. The price table supplies **100 MB total included, then US$0.01/MB**, but not an explicit MB-month period.
- Automatic database backups are retained **at least 14 days**, exceeding the requested seven-day retention horizon. The database page does not specify daily frequency/RPO, while the generic Pro backup line is not explicitly scoped to databases. The volume backup schedule is not substituted for a database schedule.
- The exact accounting of the extra **10 GB app/database traffic** is unpublished. Same-region placement is not proof of zero-cost traffic.
- B's app-resource fit and memory billing are still unresolved.

**Storage arithmetic only — our calculation:** if 10 GB is decimal, 10 GB × 1,000 MB/GB = **10,000 MB**. Subtract the stated 100 MB allowance: 9,900 MB. Then **9,900 × US$0.01 = US$99 per the unconfirmed storage billing interval**. This is **not** asserted to be US$99/month or a complete database price; binary units, used/reserved capacity, overhead, pooling and period need confirmation.
