## Cost examples: our calculation

Calculated **2026-11-05**, in **EUR**. One paying commercial builder, an otherwise unused plan, one private GitHub repository, an existing custom domain, ordinary monthly billing, no credits, annual discounts or optional support. Domain registration remains outside hosting.

Source prices: **Starter EUR 10/month net; Pro EUR 20/month net**. The vendor publishes EU consumer examples of EUR 12.30 and EUR 24.60 with 23% VAT, and reverse charge for a valid EU business VAT ID. Other buyer/location tax treatment comes from checkout; no universal VAT assumption is made. Sources: [pricing](https://eurobase.dev/pricing), [plans](https://eurobase.dev/docs/plans) and [billing](https://eurobase.dev/legal/billing); checked 2026-11-05.

Private GitHub builds are native after installing the GitHub App; no external CI subscription is required by that route. New GitLab/Forgejo integration is also documented, but the comparisons use GitHub. Plan quotas are shared across projects, so any other projects would reduce the headroom used here.

### A. Small commercial static site

Inputs: 100 MB deployed files, 1,000,000 HTTP requests/month, 100 GB outbound, **20 × 5 = 100 build minutes**, one private repository and one custom domain.

A plain HTML site can publish as-is without a build or server. To preserve the specified native build workload, consider a **static-only Vite/Worker-assets build** on Starter. Assume the 100 MB output is divided into at most 20,000 files, none above 25 MiB, and requests serve static assets without executing application code. A site needing server rendering or large individual assets needs a separate fit check.

Starter includes 250 build minutes, five concurrent builds, 100 deployments/day, 2 GiB stored artifacts and ten advertised custom domains. Spread the twenty builds within those day/concurrency limits. Application requests and response traffic have no separate plan allowance. Asset responses that do not start a Worker use no Worker CPU. Included plan logs have a 1 GiB/month cap; actual log bytes are unspecified.

Build admission also uses a reservation estimate. After earlier five-minute builds, a subsequent estimate is **5 × 1.25 = 6.25 minutes**. Starter's 250-minute budget covers this sequence. Free's 100 minutes cannot safely be treated as twenty exact five-minute builds: after nineteen completed builds only five minutes remain, below the 6.25-minute estimate needed to start the twentieth.

Artifact assumption: if twenty retained outputs are each exactly 100 decimal MB, their file payload is **20 × 100,000,000 = 2,000,000,000 bytes**, below **2 GiB = 2,147,483,648 bytes**, before other release metadata/bundle overhead. Additional releases or larger artifacts can require cleanup; no unlimited rollback-history allowance is assumed.

Formula: **1 × EUR 10 = EUR 10/month net list-price hosting estimate**. Under the vendor's stated 23% consumer example: **EUR 10 × 1.23 = EUR 12.30/month**. A valid EU business reverse-charge invoice is quoted by the vendor without that VAT addition.

Native builds, static hosting, ordinary app delivery, routing, HTTPS and included observability are within the plan. No mandatory paid gateway/IP/certificate charge was identified. This estimate is conditional on the stated file/build/artifact/log fit; it is not a throughput test or a claim that the Free plan legally bans commerce.

Sources: [static guide](https://eurobase.dev/docs/guides/static-site), [container/plain-static distinctions](https://eurobase.dev/docs/containers), [Worker build/assets limits](https://eurobase.dev/docs/workers), [plan/admission limits](https://eurobase.dev/docs/plans) and [private repository workflow](https://eurobase.dev/docs/getting-started); checked 2026-11-05.

### B. Small commercial app API

Inputs: 1,000,000 requests × 0.100 CPU-seconds = **100,000 CPU-seconds**, or **100,000,000 CPU milliseconds**. Aggregate elapsed request time: 1,000,000 × 0.250 seconds = **250,000 request-seconds**. Assumed working memory is 256 MiB; the server comparison separately requires at least **1 vCPU and 1 GiB allocation for 730 hours**, plus A's builds/domain and 100 GB outbound.

**Container/server comparison:** the smallest listed qualifying size is euro-xlarge, 1 vCPU/2 GB, on Starter or Pro. Starter's **720 active-hour** allowance is below **730 hours**. Pro has 1,600 active hours, but all container sizes scale to zero and no supported minimum-one/always-on switch was found.

The CPU/memory meter definition also prevents a precise reserved-server cost. If allocated memory were counted for the whole period, **2 GB × 730 × 3,600 = 5,256,000 GB-s**, above Pro's **1,440,000 GB-s**. If CPU allocation rather than actual work were counted, one allocated CPU over 730 hours would exceed Pro's 160 CPU-hours. Public docs do not settle those container meter bases. These are conditional capacity checks, not assertions about actual measured usage.

Therefore **no complete compatible 730-hour server total is established**. Pro's EUR 20/month subscription is a candidate fee, not proof that this reserved-server workload is supplied.

**Request-mode alternatives, also our calculation:**

- For a supported Worker API, the assumed **100,000,000 ms CPU** exactly equals Pro's monthly Worker budget; Starter has only 30,000,000 ms. This leaves no CPU headroom for additional measured work. Worker JS heap is only 128 MiB; the workload's 256 MiB working memory cannot automatically be equated with a compatible heap/buffer layout. A Pro Worker implementation therefore remains unverified.
- For an HTTP Function, if the charged memory allocation were exactly the assumed working memory, **256 MiB = 0.25 GiB**, so **0.25 × 250,000 = 62,500 GiB-seconds**. Under decimal GB conversion, **0.268435456 GB × 250,000 = 67,108.864 GB-s**. Either exceeds Starter's 50,000 GB-s and is below Pro's 100,000 GB-s. One million invocations fit Pro's two-million allowance.
- That is not an actual Function bill: its charged memory class, rounding and full execution limits were not published. A fixed 1 GB allocation, for example, would consume **250,000 GB-s**, above Pro's quota. Working memory must not silently replace the platform's charged allocation.

Formula for either candidate Pro subscription: **1 × EUR 20 = EUR 20/month net**, or **EUR 20 × 1.23 = EUR 24.60** under the published consumer example. **No complete B workload total or guaranteed compatibility is claimed.** The runtime/charged-allocation questions must be resolved first; no invented overage charge makes an exceeded quota usable.

Sources: [plans](https://eurobase.dev/docs/plans), [containers](https://eurobase.dev/docs/containers), [Worker limits/accounting](https://eurobase.dev/docs/workers), [Function offer](https://eurobase.dev/products/functions), [usage product](https://eurobase.dev/products/usage) and [billing](https://eurobase.dev/legal/billing); checked 2026-11-05.

### C. App plus persistent data

Inputs: B plus one PostgreSQL database with at least 1 GiB memory and 10 GB storage, daily backup retained seven days, and 10 GB/month app-to-database traffic.

Native PostgreSQL is **not available**; the roadmap lists it as planned. Containers have no persistent disks, and D1-compatible SQLite does not satisfy a PostgreSQL workload. An external database is required.

The vendor documents **Supabase in an EU region** as one external PostgreSQL option. This identifies the dependency; its compute tier, 10 GB disk, backup entitlement and transfer bill have **not been priced or assumed included** in Eurobase Cloud. A Worker must use its HTTPS Data API; a container can use an IPv4-capable pooler/native driver. The Eurobase guide says its apps run in Paris and recommends a nearby database region. A public connection is not an included private-network connection.

Known host candidate remains the conditional **EUR 20/month net Pro fee** discussed in B, not a complete verified B total. Formula:

**C = verified API-host cost + external PostgreSQL cost + required daily-backup/restore storage and operations + external transfer charges + applicable taxes.**

Several required terms are unknown, including the API runtime fit, so **no exact C total or artificial lower-price ranking is published**. The 10 GB app/database traffic stays a separate dependency; app response-traffic inclusion does not make another vendor's egress free. Native Eurobase terms give no standard backup guarantee. A code rollback does not reverse database schema/data.

Sources: [database status](https://eurobase.dev/docs/about), [roadmap](https://eurobase.dev/roadmap), [persistent disk/external service limits](https://eurobase.dev/docs/guides/migrate-from-render), [documented external integration](https://eurobase.dev/docs/supabase), [SQLite behavior](https://eurobase.dev/docs/workers) and [standard guarantees](https://eurobase.dev/legal/terms); checked 2026-11-05.

## Conflicts and unknowns

- **Product identity:** sources at eurobase.dev are used throughout. Search results for eurobase.app describe another same-name backend product; none of that product's database tiers, licence, prices or claims are used here. No acquisition/rename relationship is established.
- **No unresolved current-page contradiction found:** current guides consistently limit Dockerfile builds, persistent disks, background jobs and previews. Older indexed marketing/beta redirects and stale “previews” wording are not treated as newer than current readable docs. A web-cache failure was recovered by direct public reads rather than marked unpublished.
- **Compute billing and API fit:** read [plans](https://eurobase.dev/docs/plans), [containers](https://eurobase.dev/docs/containers), [Workers](https://eurobase.dev/docs/workers), [Functions](https://eurobase.dev/products/functions), [usage](https://eurobase.dev/products/usage) and [billing](https://eurobase.dev/legal/billing). Included budgets are explicit; per-unit overage rates, Function charged allocation/rounding and container CPU/memory meter basis are not. Worker heap constraints and container scale-to-zero must not be hidden by quoting a monthly base price.
- **Required Free-card check:** [pricing](https://eurobase.dev/pricing), [getting started](https://eurobase.dev/docs/getting-started) and [billing](https://eurobase.dev/legal/billing) did not explicitly answer whether a card is required for Free. The anonymous [signup page](https://eurobase.dev/signup) yielded only its title without interacting with the client-rendered form. Card eligibility remains unclear; no signup was attempted.
