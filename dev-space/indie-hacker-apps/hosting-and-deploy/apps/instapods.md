## Cost examples: our calculation

Calculation date **2026-11-05**. These are our calculations from public source prices. One builder, a commercial public product, one custom domain, normal monthly billing, no annual discount, no starter credit and no optional support or AI coding subscription. Domain registration is external and excluded. Currency is **USD**, explicit in the public pricing page's structured data. Tax inclusion is not published; the figures below preserve displayed list prices without inventing VAT or currency conversion.

Sources for inputs, all checked 2026-11-05:

- [Plan pricing](https://instapods.com/pricing/): Launch USD 3/month, 1 vCPU/512 MB/10 GB; Build USD 7, 2 vCPU/2 GB/25 GB; Grow USD 15, 2 vCPU/4 GB/50 GB. No separate requests, bandwidth, seats or in-pod database charge; SSL included.
- [Billing](https://docs.instapods.com/dashboard/billing.md) and [daily proration](https://instapods.com/pricing/): plan price divided across calendar-month days, billed for days the pod exists, including stopped pods. Invoice timing and cancellation conflict with [terms](https://instapods.com/terms/); neither source gives precise part-day rounding.
- [Private Git/build flow](https://docs.instapods.com/guides/git-deployment.md), [deployment operations](https://docs.instapods.com/guides/operations.md), [on-pod builds](https://docs.instapods.com/presets/go.md) and [build memory handling](https://docs.instapods.com/support/troubleshooting.md): private source, dependency installation and on-pod build/restart; no separate build-minute bill. Build CPU/memory availability is not a proof that a particular project fits.
- [Custom domain/SSL](https://docs.instapods.com/dashboard/custom-domains.md): one requested domain fits five-domain cap; automatic certificate renewal.
- [PostgreSQL](https://docs.instapods.com/services/postgresql.md) and [colocated services](https://docs.instapods.com/services/overview.md): PostgreSQL runs alongside app in the same pod, with no independent memory reservation. Version descriptions disagree.
- [Backup scope/schedule/retention](https://docs.instapods.com/dashboard/backups.md): default daily backups include detected database dumps; retention is a saved-copy count, 1/5/10/15/30 by plan.

**Day-based billing formula:** for a pod with monthly price P, **charge = sum over calendar-month/plan segments of (P × n ÷ D)**, where D is the days in that calendar month and n the billable days on that plan in that segment. D and dates matter. The sources do not state the partial-day rounding/time zone, so an exact 730-hour invoice cannot be calculated from hours alone. One complete billing month on an unchanged plan gives **P × D ÷ D = P**. The term “monthly” is not silently converted to a universal P/730 hourly rate.

### A. Small commercial static site

Inputs: **100 MB** deployed files; **1,000,000 requests/month**; **100 GB outbound/month**; **20 builds × 5 minutes = 100 build minutes**; one private repository; one custom domain.

Candidate: one **Launch pod, USD 3/month**, serving static files with nginx or a suitable custom source workflow. The 100 MB payload fits the listed 10 GB disk before accounting for source, dependencies, OS and artifacts. No database is required. Private repository access uses the documented Git connection/token; ordinary Git builds have no separately priced minute meter.

Full-month line items:

| Component | Our calculation | Displayed-price result |
| --- | --- | --- |
| Launch pod | 1 × USD 3 | USD 3 |
| 1,000,000 requests | Included, no request meter | USD 0 extra |
| 100 GB outbound | Included, subject to fair use | USD 0 extra |
| 100 native build minutes | On-pod workload, no separate build fee | USD 0 extra |
| Persistent files, ordinary backup, one domain/SSL | Within selected pod allocation and included features | USD 0 extra |

**Our full-month hosting calculation: USD 3.** This is conditional on the actual build/runtime fitting Launch. Static preset itself does not install a frontend toolchain by default; select/configure the right workflow or build output, and move up a tier if the build cannot fit. No build-memory size, duration ceiling or million-request throughput guarantee was published/tested. External image CI is not needed for this candidate and is not silently included. Tax treatment remains unestablished.

### B. Small commercial app API

Inputs: 1,000,000 × 0.1 CPU-second = **100,000 CPU-seconds**; 1,000,000 × 0.25 elapsed seconds = **250,000 request-seconds**; assumed app working memory **256 MiB**; server requirement at least **1 vCPU/1 GiB for 730 hours**; **100 GB outbound**, plus A's private repo/builds/domain.

Choose **Build**, the smallest published tier safely exceeding 1 GiB: **2 vCPU/2 GB RAM/25 GB disk, USD 7/month**. Launch has only 512 MB and fails the nominal minimum. Preserve the vendor's GB label; the 2 GB tier is above 1 GiB without relabeling it as 2 GiB.

Full-month formula: **USD 7 pod + USD 0 extra requests + USD 0 extra outbound + USD 0 native build-minute fee + USD 0 extra one-domain/SSL = USD 7** at displayed prices. Memory/processor arithmetic describes our inputs; InstaPods bills the pod, not these CPU-seconds. CPU sharing and untested throughput prevent an equal-performance claim.

For **exactly 730 hours**, apply the calendar-day formula above. **USD 7 is the full-month hosting quote, not a verified exact 730-hour charge.** Start date, partial-day rounding and tax are not resolved. The pod stays charged during idle or stopped time.

### C. App plus persistent data

Inputs: all of B plus PostgreSQL with at least **1 GiB memory and 10 GB data storage**, daily backups retained seven days, and **10 GB/month app-to-database traffic**.

Candidate: **Grow, USD 15/month**, **2 vCPU/4 GB RAM/50 GB disk**, with native PostgreSQL inside the app pod. Build has only five saved backups and cannot meet seven daily recovery points using its included automatic retention. Grow permits ten saved backups and a daily schedule; select a keep-last count sufficient for at least seven daily points, and avoid manual snapshots evicting needed daily copies.

**Our resource-sizing allowance:** budget at least **1 GiB for the application and 1 GiB for PostgreSQL**, with remaining pod memory for system services/builds and overhead. Allow **10 GB for PostgreSQL** within the shared 50 GB disk, leaving the remainder for OS, source, uploads and artifacts. These are our sizing assumptions, not vendor-reserved slices. CPU/memory/disk are shared; the provider does not sell this as an independently allocated 1 GiB database service.

Full-month formula: **USD 15 Grow + USD 0 separate PostgreSQL + USD 0 local 10 GB transfer + USD 0 separate included scheduled backups + USD 0 extra requests/outbound/build meter/domain/SSL = USD 15** at displayed prices.

**Our conditional full-month hosting calculation: USD 15.** Actual allocation/backup completion and seven-day coverage must be verified on the deployed app. The backup policy guarantees a maximum count, not an immutable calendar-day window: failed backups, manual copies and stopped pods affect recovery points. No PITR or contractual restore deadline is published. Exact 730-hour billing and taxes remain unresolved as in B.

A code rollback does not undo database migrations. Backups include database dumps and app data; they exclude OS/packages and selected dependency/build directories. A **10 GB database is not proven to compress below the 2 GB backup-import limit**: native restores of existing backups are distinct from re-uploading an archive; use the documented native dump/file-transfer route when an imported archive cannot fit.
