## Cost examples: our calculations

These are our calculations, checked 2026-11-07. CapRover’s core software subtotal is $0/month. The full bill cannot be priced from CapRover sources because the customer chooses and pays for the app server, domain, registry, and backup destination. The static-site and API examples assume one commercial builder and monthly operation. No provider rate is assumed or converted.

### A. Small commercial static site

Inputs: 100 MB deployed files; 1,000,000 HTTP requests and 100 GB outbound per month; 20 builds of 5 minutes; one private Git repository; one custom domain.

- CapRover core: `$0/month`.
- HTTPS certificates: CapRover uses Let’s Encrypt; CapRover certificate subtotal is `$0` based on the published offer. Server, domain registration, traffic, and optional CI/registry charges are external and unpriced here.
- Formula: `full monthly total = $0 CapRover core + server/provider monthly charge + 100 GB provider egress + domain fee (if purchased) + any external CI/registry charges`.
- Result: exact total unknown; CapRover does not publish those external prices or a delivery allowance.

### B. Small commercial app API

Inputs: stateless HTTP app; 1,000,000 requests/month; assumed 100 ms active processor work and 250 ms total elapsed time per request; assumed 256 MiB working memory; 100 GB outbound; 20 five-minute builds; one private repository; one custom domain. Comparison capacity assumption: at least 1 vCPU and 1 GiB RAM for 730 hours. CapRover itself needs at least 1 GiB RAM and 5 GiB free disk on the standard install, so the server must leave room for the control plane and app; these minimums do not demonstrate workload fit.

- CapRover core: `$0/month`.
- Formula: `full monthly total = $0 core + server price for 730 hours and enough capacity for CapRover plus the app + 100 GB provider egress + domain + optional registry/CI`.
- Result: exact total unknown; server capacity price, provider egress, and domain are not CapRover prices.

### C. App plus persistent data

Inputs: workload B plus Postgres with at least 1 GiB memory and 10 GB storage; daily backup retained for 7 days; 10 GB/month app-to-database traffic.

- CapRover core: `$0/month`; Postgres is a customer-managed app, not a managed database plan.
- Formula: `full monthly total = $0 core + server resources for CapRover, API and Postgres + persistent disk + provider egress + separate database backup storage/operations + domain + optional registry/CI`.
- Result: exact total unknown; CapRover’s configuration backup excludes app volumes and database data, and the docs publish no server, storage, egress, or backup rates.

## Field problems

- CapRover is a self-hosted control plane, not a server seller. Compute, storage, bandwidth, region, tax, server uptime, and provider-level spend controls are external facts; they cannot be priced or marked zero from CapRover’s own pages.
- CapRover Pro is a paid subscription feature set despite there being no hosted application plan. Its subscription amount and legal checkout terms are not published in the docs checked, so those price details are `not_published` rather than `not_applicable`.
- The licence’s custom appendix qualifies the Apache 2.0 text. The file records the wording and GitHub history dates, and avoids making a legal determination about how it applies to a particular fork.
- The 37 fields were all attempted. `not_applicable` is used only for tax/refund terms on the zero-cost core; provider and Pro billing details are recorded separately.
