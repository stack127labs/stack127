## Lifecycle and access notices

**Active public Express Mode offer. No Express Mode shutdown, sunset or acquisition notice found in the official offer, current setup/API documentation, feature notices and lifecycle checks.** Express Mode is a deployment capability of Amazon ECS, using customer-account Fargate/ALB/CloudWatch resources. It is not another independent hosting provider. [current offer and pricing](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/express-service-overview.html), [new-service setup](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/express-service-create-full.html), [create API](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_CreateExpressGatewayService.html), [AWS lifecycle overview](https://docs.aws.amazon.com/general/latest/gr/service-lifecycle.html); checked **2026-11-05**.

**Related access changes:** AWS App Runner stopped accepting new customers **April 30, 2026** and recommends ECS Express Mode; existing App Runner services continue. AWS Copilot CLI support ended **June 12, 2026**, and its migration notice points to Express Mode/CDK. Neither notice says Express Mode is closing or that App Runner source builds/default URLs automatically become Express features. [App Runner notice](https://aws.amazon.com/apprunner/), [Copilot end-of-support/migration notice](https://aws.amazon.com/blogs/containers/announcing-the-end-of-support-for-the-aws-copilot-cli/); checked **2026-11-05**.

**Current feature and documentation caveats:** custom task-definition support was announced **July 1, 2026**. Current API and walkthrough/resource docs disagree on compute and health-path defaults; the update API also describes rolling deployment where the mode guides specify canary. The file preserves those differences and passes explicit resources/health settings in calculations. [custom-definition announcement](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-ecs-express-mode-custom-task-def/), [resource defaults](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/express-service-work.html), [create API](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_CreateExpressGatewayService.html), [update API](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_UpdateExpressGatewayService.html), [update guide](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/express-service-update-full.html); checked **2026-11-05**.

## Field problems

- Express Mode is a **deployment/management mode**, so its own fee must be separated from each resource it creates. Copying a whole Fargate feature list would obscure its HTTPS/ALB/scaling/canary additions and its Main-container requirements.
- Default settings differ between API documentation and walkthroughs. A price estimate should pass CPU/memory/health settings explicitly and show which defaults were overridden.
- ALB sharing changes average cost across several apps in the **same account/network**, not the first app's bill or a price shared with unrelated customers.
- Automatic scaling and canary deployment add resource lifetimes. Monthly traffic and build minutes do not determine those hours or ALB capacity billing.
- The custom-domain flow is manual ALB/certificate/DNS configuration, while the generated regional URL is automatic. They should not share one unchecked “custom domains included” value.
- “All underlying resources are accessible” does not make every Express setting mutable through its API, and direct edits can conflict with later coordinated updates.
- C's network path cannot inherit a hand-pinned same-AZ assumption: Express manages multi-subnet placement/rebalancing. Backup retention also does not determine retained bytes.
- No `apps.md` row error found. Its **Active** status and “same product family; compare as a deployment mode” qualification are accurate. The App Runner notice supports discovery/access context, not a claim that Express is App Runner under a new name.
