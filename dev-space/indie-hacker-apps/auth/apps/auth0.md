## Field problems

- F11 to F13 depend on a dynamic calculator. A static scrape does not establish all price bands or B2B add-ons. Keep an explicit extraction-failed state and allow follow-up from official public calculator data.
- F20 should distinguish anonymous sessions from anonymous stored accounts, and distinguish Classic Login email links from Universal Login support.
- F23 combines availability, billing bucket and enforcement. The official sources disagree on factor buckets; store these separately.
- F31 can grow into a long language catalogue. The full locale-code list is recorded separately; language availability is not a measured accessibility score. Right-to-left rendering has a separate Early Access gate.
- F35 does not apply to the managed auth server. Client-library installation is a separate concern.
- F48 needs a per-SDK version. There is no single installed Auth0 server version for a hosted-service user.
- F50 is evidence metadata, not a product capability. Requiring an external proof URL for our own research method is awkward; individual factual rows have their own official proof.
- Broad fields contain confirmed and unknown subparts. Counts below show both unique field rollups and evidence-row states; they must not be read as a completeness score.
