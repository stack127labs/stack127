## Cost examples — our calculation

All scenarios below are ours. There is no accessible current public numeric OTPless country/channel rate card in the sources checked. The billing unit itself must be settled in the quote. A logged-in user, a completed authentication, a sent message, an attempted request, an active session and a monthly user are not interchangeable.

For consumer baselines, choose documented Google social login to meet the email/password-or-social input. Password authentication is marked forthcoming in https://otpless.com/docs/knowledge-base/signup-signin-configuration. Two days returning is fixed by fields.md; the calculation's extra assumption is one social authentication on each day. Persistent sessions could reduce re-authentication, so this is not a claim that every implementation must send two requests.

For the separate phone examples, use **India destination / SMS OTP** only, two checks per user/month, one message per check, 100% completion, no fallback/retry/SNA/WhatsApp. Define r_IN_SMS as the quoted all-in per-check rate for this exact one-SMS path. If the quote separates an authentication fee from message delivery, replace r with those components without double counting. If the quote instead uses MAU/bundle units, use that definition and retain the event inputs; the symbolic per-check formula is then not the applicable contract formula.
