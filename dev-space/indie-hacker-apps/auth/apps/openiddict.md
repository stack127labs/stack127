## Conflicts and unknowns

- **Homepage host minimum conflict:** [Project homepage](https://openiddict.com/) advertises **ASP.NET Core 2.1+ / ASP.NET 4.6.1+**. The current [host integration guide](https://documentation.openiddict.com/integrations/aspnet-core) and [released 7.8.0 README](https://raw.githubusercontent.com/openiddict/openiddict-core/7.8.0/README.md) instead state **2.3+ / 4.6.2+**. The [published package manifest](https://api.nuget.org/v3-flatcontainer/openiddict.server/7.8.0/openiddict.server.nuspec) and [released target settings](https://raw.githubusercontent.com/openiddict/openiddict-core/7.8.0/Directory.Build.props) supply the version-specific dependency evidence. Both published values remain visible; the older homepage is not the installation authority.
- **Native target conflict:** [Operating-system guide](https://documentation.openiddict.com/integrations/operating-systems) still lists **net9.0** and **net10.0** mobile/Apple targets. The [7.7 release notice](https://api.github.com/repos/openiddict/openiddict-core/releases/tags/7.7.0) explicitly removes the net9.0 Android/iOS/Mac Catalyst/macOS targets, and [7.8.0 package metadata](https://api.nuget.org/v3-flatcontainer/openiddict.client.systemintegration/7.8.0/openiddict.client.systemintegration.nuspec) publishes only the net10.0 variants for those platforms. The guide also labels an OS list **OpenIddict 7.2** and gives different macOS minima in its list and platform paragraph. Current package assets are recorded; a definitive current minimum OS matrix is not invented from mixed-age wording.
- **Pruning wording conflict:** [Quartz guide](https://documentation.openiddict.com/integrations/quartz) broadly describes deletion of records older than 14 days, while [authorization guide](https://documentation.openiddict.com/configuration/authorization-storage) says permanent grants are never removed. Released [EF Core token pruning](https://raw.githubusercontent.com/openiddict/openiddict-core/7.8.0/src/OpenIddict.EntityFrameworkCore/Stores/OpenIddictEntityFrameworkCoreTokenStore.cs) filters by age plus expired/invalid state or invalid authorization; [authorization pruning](https://raw.githubusercontent.com/openiddict/openiddict-core/7.8.0/src/OpenIddict.EntityFrameworkCore/Stores/OpenIddictEntityFrameworkCoreAuthorizationStore.cs) requires no associated tokens and an invalid or ad-hoc grant. Thus valid unexpired tokens are not removed merely for age, and an eligible invalid permanent grant can be pruned. The released predicates clarify actual behavior; the prose is not a universal retention promise.
- **Stable versus preview cleanup:** [8.0 preview 5](https://api.github.com/repos/openiddict/openiddict-core/releases/tags/8.0.0-preview.5) replaces Quartz with a Core background worker and introduces different automatic-pruning defaults. ## Field problems

- **This is a protocol framework, not a membership product.** F02/F20–F24/F27–F29/F37–F41 must identify the surrounding account system rather than copy its features into OpenIddict.
- **Keep three roles separate.** Client, server and validation have different persistence, host and token requirements. Generic OAuth/OIDC support does not make a SAML server, SCIM endpoint or local user store.
- **Hosted billing and availability fields do not apply.** No MAU tariff, vendor trial, dashboard-seat quota, managed region menu or hosted uptime SLA exists for embedded core. Optional sponsorship/components are recorded under their actual terms.
- **Client applications are not customer organizations.** Protocol permissions/scopes and authorization grants do not provide invitations, tenant membership or business-role isolation. Core alone does not meet the business baseline.
- **Revocation and deletion are not single switches.** Storage, token format, API status checks, local user cookies, remote provider state, app records and backups must be considered separately.
- **Stable/preview and source/prose boundaries matter.** Three conflicting rows preserve stale minimum-runtime/native-target wording and overbroad pruning descriptions. 8.0 automatic cleanup is not a 7.8 default.
- **UI and passkey fields need the correct owner.** Core does not ship account screens or WebAuthn credentials. Native OS protocol integration is not native passkey enrollment, and localized client metadata is not a translated account UI catalogue.
- **Support has different units and eligibility.** Monthly sponsor prices, annual ticket/review counts, previous-major windows, hobby restrictions, reply guarantees and cancellation-benefit rules are kept separate from software rights.
