## Conflicts and unknowns

- **Lifecycle/version:** Official site/project/README, GitHub/PyPI, funding/support and official-domain ending/acquisition searches were checked first. No whole-project shutdown or acquisition notice found. Product card says 1.9.1; package/release/changelog say 1.9.4. Current release evidence takes priority. JOSE deprecation and future SAML/async-provider goals do not change the status of the current OAuth/OIDC package.
- **Private maintainer names:** This file uses “an individual maintainer” and does not reproduce the private licensor's name, copyright-holder name, personal contact address or contributor names. Company/project names remain. Public checkout shows a company supplier label; commercial license identifies an individual licensor. No assumption about corporate ownership, sole-trader country or the applicable purchaser-specific contract is made.
- **Community versus commercial terms:** Read BSD licence, licence guide, release/current COMMERCIAL-LICENSE, pricing, both public checkout pages and the directly linked Polar buyer terms. BSD explicitly allows open/closed-source projects. Alternative commercial text has personal/nontransferable rights, derivative-distribution restrictions, as-is/no-support/no-refund provisions and no obligation to fix defects; pricing advertises direct/quicker support and Pro consultation. Public sources do not resolve which additional agreed support terms override that text for a buyer. No legal enforceability opinion or purchase was made.
- **Annual pricing/tax conditions:** Pricing displays Plus $1,000/year and Pro $2,000/year. Checkout initially displayed $1,180 including $180 tax and $2,360 including $360 tax, respectively. No buyer address or country was entered/established. Polar terms tie taxes to address/nexus; the displayed totals are observations, not universal/country-specific rates. No annual charge is silently divided by twelve. Public checkout establishes recurring billing until cancellation, while supplier licence rights have separate conditions.
- **Private benefits unresolved:** Current/tagged funding docs advertise private repos, private PyPI and early security fixes; the linked /pypi page returns 404. Current pricing/checkout and supplier terms do not specify how to access those benefits. Their current entitlement/availability stays unclear. This is not proof of a private-service shutdown, and a private login was not attempted. All public protocol features remain available under BSD according to current pricing.
- **Supported-version policy conflict:** The v1.9.4 bundled SECURITY.md lists 1.7.x and 1.6.x supported, whereas current main/GitHub policy lists only 1.9.x and marks <1.9 unsupported. Current policy is used for present support scope, with the older release-file statement retained. The file does not invent an LTS/end-date or promise backports to those older branches.
- **Security-report timing conflict:** Stable docs say response in 24 hours, confirmation in 2 days, fix in 1 week after confirmation and a later source publication sequence. Current main removes numeric targets and describes private reporting, confirmation, release and advisory publication without those deadlines. Those old timing claims are not presented as a binding paid response/uptime SLA.
- **Security advisory text lag:** Read recent ID-JAG mapping/scope, form_post redirect, nonce and empty-HMAC-key advisories plus current release/source. Some advisory bodies/metadata still say no patch even where current metadata/release/code record a fix. The empty-key guard rejects absent key material in 1.9.4; the nonce parser takes expected nonce from the app, not a token-controlled bypass flag. These are inspected code facts, not an executed exploit/audit or a guarantee of complete security.
- **ID-JAG custom hook duty:** Current implementation stores verified claims on request.id_jag_claims but still calls the app's authenticate_user hook. New reference code looks up issuer plus subject; tenant-aware mappings need corresponding tenant context. Existing sub-only callbacks are not automatically rewritten by upgrading a package. This optional draft grant is not a general customer organization/invitation service.
- **Account and provider scope:** Read generic web/HTTP client guides, each framework integration, server/consent/grant examples and full release inventory. Authlib returns protocol tokens/profile and supplies extension points; app must create/load users, verify local credentials, establish sessions and enforce roles. Google/GitHub have documented recipes. Other providers need their own config/identity handling, with no blanket native/device support promise. A separate OTP project is not built-in MFA enrollment/recovery; no WebAuthn account module was found.
- **Tokens, expiry and logout:** Read bearer defaults, refresh grant, SQLAlchemy helpers, state/cache integration, revocation/introspection and RP logout implementation guides. Default server lifetimes differ by grant; 1-hour fallback is not every token's lifetime. Refresh issuance/rotation/expiry and code expiry/deletion need app hooks. Temporary state/cache settings are not a complete login-session retention policy. RP logout, local logout, token revocation and account deletion are different operations.
- **Organizations/provisioning/costs:** Read source inventory, protocol/funding lists, client/code/token models and client-registration/management docs. OAuth clients are apps, not customer organizations or employee directory records. No bundled SCIM or current SAML implementation. Both fixed business baselines are unsupported by Authlib alone. Consumer examples show $0 component licence fees with unspecified full operating/provider costs; paid support does not make those missing account/business features appear.
