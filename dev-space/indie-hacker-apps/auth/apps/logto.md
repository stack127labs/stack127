## Cost examples — our calculation

These six records use fields.md's returning-user and business inputs. An exact bill cannot be obtained from MAU alone because Cloud counts access tokens issued. The values below are our calculations for explicit sub-scenarios, not a universal per-user price curve or a vendor quote.

Consumer sub-scenario: one ordinary production app, one builder console seat, existing email/password accounts, exactly two fresh sign-ins per user during one full comparison month, one opaque access token issued per sign-in. No extra refreshes, resource tokens, M2M or token exchanges. Thus T = 2 × MAU. Use Free only while both MAU ≤ 50,000 and T ≤ 50,000; otherwise Pro costs $24 + $0.08 × ((T − 50,000)/100), with zero excess charge if T is below 50,000. All overage examples here use exact 100-token blocks; the invoice rule for a partial block was not found.

Business sub-scenario: one Logto production tenant, 10/100 customer organizations, 100 members each, one/10 incoming SAML connectors, membership/invitations/organization roles and no SCIM. Two fresh sign-ins per user, each followed by one organization-token request, gives T = 4 × MAU. Membership, roles and connector setup are completed before the comparison month; the feature is available, but no actual invitation-send count or extra Management API token issuance is assumed during the steady-state month. The Organizations bundle supplies organization roles, so the separate tenant-wide RBAC bundle is not compulsory for this sub-scenario. Additional app API-resource permissions would change the chosen feature set and may add tokens.

Standard Logto Cloud email is documented as free with no daily usage limit, subject to per-recipient send throttles. No unavoidable Cloud per-email tariff is added. Self-hosting needs your own sender if email is used. Every $0 OSS figure is software license cost only; add servers/PostgreSQL, optional Redis/storage, email/SMS, backups, monitoring and operations. Product hosting, staff time, taxes and optional paid security/branding/admin features are excluded. A software charge of $0 is not a $0 operating total.

## Conflicts and unknowns

- **Cloud billing is token-based:** read the full [pricing table/FAQ](https://logto.io/pricing) and [billing guide](https://docs.logto.io/logto-cloud/billing-and-pricing). The free plan has both a 50k-MAU cap and 50k access-token allowance. Repeated sign-ins, org/API authorization, refreshes, M2M and exchanges can add tokens. The prescribed user return pattern does not determine those counts. All six cost rows therefore show an explicit sub-scenario and retain an unknown unrestricted total.
- **API-resource worked example:** both rate tables publish $4 per extra resource, while billing example 2 multiplies by $8 and reports $58.67. This inconsistency is inside the current billing guide; it does not affect our examples, which need no extra API resources.
- **Current Node.js requirement:** [OSS setup](https://docs.logto.io/logto-oss/get-started-with-oss) and [upgrade guide](https://docs.logto.io/logto-oss/upgrading-oss-version) say ^26.0.0; the [v1.45.0 package](https://raw.githubusercontent.com/logto-io/logto/v1.45.0/package.json) declares ^22.14.0. - **Self-host license reporting:** [license documentation](https://docs.logto.io/logto-oss/self-hosted-license) says only key, deployment ID and version leave the instance, and specifically says no user counts. [Subscription terms §10.2](https://logto.io/terms/self-hosted) describe aggregate MAU/token/tenant reporting and an opt-out. ## Field problems

- **F08/F12/F13:** MAU is a free-plan eligibility cap, while token issuance is the paid usage meter. A monthly visit or returning user is not a fixed number of access tokens. Our sub-scenarios name the sign-in/organization exchanges and expose extra issuance as a variable.
- **F11:** $0.08 per 100 extra tokens does not establish rounding of an incomplete block. Fixed examples use exact blocks. Prorated transition invoices also differ from a steady full-month charge.
- **F14–F16/F26:** builder tenants, customer organizations, incoming enterprise connectors, outgoing SAML apps and builder Console SSO are different units. Organization roles do not automatically need the separate global RBAC bundle.
- **F04/F10/F35/F48:** free MPL core, MIT SDKs and commercial self-host features need separate records. Self-hosted Pro is early access and annually prepaid, with a 50k-MAU limit; its month-equivalent price is not a monthly cancellation option. Unversioned runtime guidance differs from the selected release.
- **F22/F25/F33:** web passkeys, browser-based mobile SDKs, native social handoffs, app-local sessions, central SSO sessions and grants have separate behaviors. Broad yes/no support and logout labels would hide material limits.
- **F27/F29:** native organization APIs and hosted account pages do not mean a ready-made customer organization-admin dashboard or an arbitrary headless signup form. Product screens and backend permission checks still need integration.
- **F39/F41–F43/F46:** public hash export exists, but not every credential/export format is established. Dev user cleanup, controller account retention, production identity deletion, audit retention and backups have different scopes. Public SOC2 claims and unreadable reports remain distinct.
