## Field problems

- **F01/F02/F03:** External ID is broader than customer authentication. Keep external customer tenants, workforce guests and legacy Azure AD B2C separate; their methods, pricing, lifecycle and contracts are not interchangeable.
- **F08/F12/F16:** a builder seat can become a billed active user. The fixed seat count alone does not settle monthly authentication activity. The two explicit cost sub-scenarios preserve that difference.
- **F11:** an API can expose multiple SKU/meter names. The cheaper Core meter is not enough to establish a new Basic customer's entitlement; the product page and meter identity must be matched.
- **F13/F14/F27:** groups/app roles, customer invitations and whole customer organizations are separate capabilities. Source conflict about invitation eligibility should not become an unsupported or fully packaged organization verdict.
- **F15/F28:** distinguish outbound SCIM from inbound per-customer provisioning, and standard mode from HSC mode. A service capability does not by itself settle licensing/fees.
- **F17/F18/F19/F45:** user allowance, SMS attempts, email sending, extension throughput and money caps use different units. Public rate evidence should not imply unlimited delivery or request capacity.
- **F22/F23/F29/F33:** passkey price is only one part of support: custom domain, previous MFA, account type, browser and native UI/fallback restrictions matter.
- **F39–F43/F46/F47:** profile export, credential portability, soft delete, contract retention, final purge, service-location scope and SLA applicability need separate evidence. A general Entra or B2C policy is not automatically this customer offer's policy.
- **apps.md row:** no error found. Its name, official URL, active status and warning to avoid substituting Azure AD B2C match the researched scope. No index/field/notes file was edited.
