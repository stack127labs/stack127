## Conflicts and unknowns

- **No unresolved conflicting price/edition claims established.** Devise core has one checked MIT code offer; optional gems are independent projects. Their version/dependency differences are recorded, rather than merged into a fictitious paid plan.
- **Generator defaults matter:** Confirmable, Lockable, Timeoutable, Trackable and Omniauthable ship in core but are not enabled by the default model generator. Source inventory, generated module list and schema generator were read before assigning defaults. Their configuration values apply only where the module is enabled.
- **Old docs and current code:** The wiki contains historical Rails API, guest, migration and token examples. The token page explicitly marks its examples out of date. The API guide reports gaps, and the current README also warns about API-only compatibility. These establish boundaries and patterns, not a validated Devise 5 native client or ready production guest/legacy migration implementation.
- **Plugin versions and requirements:** RubyGems metadata, released docs and relevant gemspecs were read. devise-two-factor 6.4.1 requires Rails 7.2 to below 8.2, higher than core's floor; its docs warn against leaving DatabaseAuthenticatable enabled alongside its replacement and against automatic sign-in after password reset. Passkey backend helpers leave browser code and recovery/UI work to the app. Invitation email support is separate from customer organization roles and isolation.
- **SSO roles and costs:** Read core OmniAuth integration plus plugin-owned SAML/OIDC docs and package metadata. They are client/service-provider roles, with separate dependencies and trust configuration. They do not establish a Devise OIDC/SAML identity-provider server, SCIM service, organization dashboard or completed business baseline.
- **Sessions/revocation:** Read core serialization, bcrypt comparison/salt, remember cookie helper, idle-timeout hook, active-account hook and sign-out helper. All-scopes logout refers to the current Warden session, not every device. Expiring remember credentials and changing a password have different effects; there is no core device-session inventory or refresh-token family.
- **Costs and messages:** MIT grants no-charge code use. Read DatabaseAuthenticatable, default generator modules, notification delivery, reset/confirmation/lock flows and email configuration. Password sign-in has no mandatory email per login. Fixed returning-user counts do not tell us message sends, hosting size or total bill. Both business baselines need additions and remain unsupported by core alone.
- **SCIM unknown:** Complete 5.0.4 source inventory, module list, extension index and OmniAuth guide did not establish a bundled SCIM implementation or a maintained turnkey Devise SCIM integration. No claim that unrelated Rails SCIM libraries cannot be integrated.
- **Accessibility and native clients unknown:** Read account templates, core README/UI/I18n and API compatibility/token guides, source inventory and contribution docs. No product-specific conformance report or supplied native/mobile SDK compatibility matrix found. HTML labels and a working browser route do not establish those facts.
- **Operations/capacity unknown:** Read installation/schema, package prerequisites, changelog, CI and contribution guidance. No universal CPU/RAM/requests-per-second sizing or complete Devise-specific restore runbook found. Operation and backup design follow the real app and its storage.
- **Privacy, deletion and export:** MIT governs code use; there is no Devise-hosted identity account to close or runtime processing region. Read app-owned schema, sensitive-attribute serialization, bcrypt/pepper, provider mapping and extension credential models. Export/import requires operator tooling and target compatibility; profile JSON hides hashes by default. User deletion calls the app model and cannot establish retention for associated records, logs, mail providers or backups.
- **Assurance and maintenance unknown:** README, contribution, rendered security policy and published advisories did not yield an independent audit/certificate or numeric Devise branch LTS/backport deadline. The security page reports no SECURITY.md, while README supplies a private reporting address. Neither source implies no security reporting process. The gem's old runtime minimum is not a promise those runtimes still receive upstream fixes.
- **Support unknown:** Checked README help/reporting, contribution guide, MIT terms and security policy. No official paid-support price, guaranteed response/fix hours or 24/7 commitment found. No external consultant is treated as a Devise plan.
- **Retrieval repairs:** The guessed generic migration template path returned 404; actual Active Record generator/template paths were read. Wiki Extensions/I18n are Textile, not Markdown; their .textile sources were read. The package is devise-security, not devise_security; corrected official metadata and release docs were read. An unused devise-webauthn main-branch URL returned 404; the passkey finding instead uses the successfully read released devise-passkeys project. Initial sandbox DNS access failed; authorized public source reads succeeded through the approved read-only path. No supporting table URL remains failed.
- **Private people:** Author/copyright/maintainer personal names from metadata/source were not copied. Company/project names and exact evidence URLs are retained; no country or ownership is inferred from usernames.
