## Field problems

- **Library fields versus hosted fields:** F06–F08, F10–F11, F15–F16, F18–F19 and F47 have no Symfony Security SaaS plan value. They are not_applicable with scope evidence. They were not left unclear after searching irrelevant Symfony commercial-service pricing.
- **Core, plugin and preview must stay separate:** F20–F26, F29, F32 and F34 distinguish released core, optional provider/factor/account-flow bundles and 8.2 development features. Dependency compatibility is not evidence that a plugin is installed, enabled or covered by the core security policy.
- **Authorization is not customer organization management:** F14/F27 require application tenant models, memberships and invitations. Multiple firewalls, roles and voters do not by themselves meet the fixed organization/SAML scenarios.
- **Generic token formats do not establish SSO roles:** A custom SAML-formatted bearer handler is not a native SAML service-provider login. Existing OIDC token validation is not a browser OIDC client or identity provider. F26 names the direction and release boundary.
- **A scaffold is not a finished auth product:** Maker commands generate application code/templates; user management, recovery, mobile token storage, account linking and deletion remain partly or wholly application work. Claims are tied to the layer that actually supplies them.
- **Retention and rate units differ:** Link lifetimes, reset expiry, resend throttles, session cookie/server TTL, remember-me age, failed-login windows and log rotation settings are recorded separately. None is a universal retention or capacity promise.
- **Source contradictions are useful data:** The PHP patch-level requirement and GitHub beta flag deserve conflicting rows instead of an invented reconciliation. No apps.md row error was identified.
