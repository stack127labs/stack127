**Security/upgrade notice:** Read the [project advisory list](https://github.com/pallets-eco/flask-security/security/advisories) and current fixes. [GHSA-ccgp-pv8r-95wm](https://github.com/pallets-eco/flask-security/security/advisories/GHSA-ccgp-pv8r-95wm) names **5.8.3 / 5.9.1+** as patched for an open redirect. The [5.9.2 source/release history](https://raw.githubusercontent.com/pallets-eco/flask-security/5.9.2/CHANGES.rst) includes these fixes. This is maintenance evidence, not a claim that the app/dependency stack has no vulnerabilities. Checked date: **2026-11-05**.

**Behavior/maturity notice:** [5.9.0 changed](https://raw.githubusercontent.com/pallets-eco/flask-security/5.9.2/CHANGES.rst) authentication-token default lifetime from **never expire to 15 minutes**, made default logout **POST**, added optional refresh tokens and new database model requirements. The [5.9.2 feature docs](https://raw.githubusercontent.com/pallets-eco/flask-security/5.9.2/docs/features.rst) still label **WebAuthn/passkeys Beta**. Legacy PASSWORDLESS remains implemented but is being replaced by unified signin. Checked date: **2026-11-05**.

The package now uses libpass behind passlib imports, and the guide warns against installing both distributions together. Old minimum/config/examples must not be treated as current production defaults.
- **Passkey scope:** Read WebAuthn guide/config, complete utility/endpoint code, browser JS and credential models. First/secondary use, multiple credentials, backup metadata and user-hint/discoverability behavior exist. Default first-factor attachment is CROSS_PLATFORM and UV is preferred rather than universally required. The wrapper checks actual verification when deciding whether to satisfy multi-factor. - **Factors and recovery:** Read TOTP/unified/two-factor/recovery code and model/config docs. MFA feature and forced enrollment default off; delivery configuration is separate from an enabled-method list. TOTP secret encryption needs app keys; persistence hooks for last-used counters have no default storage. Recovery codes are one-use but unencrypted unless separate Fernet keys are configured, and no TTL is enforced by default. Code windows, freshness, remembered second-factor cookies, attempt limits and recovery-code expiry are different controls.
- **Tokens and revocation:** Read token generation/parsing, refresh implementation/tracker model, logout views, core loaders and datastore reset APIs. Authentication tokens are signed app tokens, not proof of an OIDC issuer. Refresh defaults off and needs schema/rotation tracking; revoking refresh does not universally revoke every earlier authentication token. Password changes rotate session identity, but a separate token identity can preserve token access until it is separately reset. The actual operator must choose/restore keys and maintain any cleanup schedule.
- **Social/SSO boundaries:** Read bundled Google/GitHub providers, OAuth glue and current Authlib Flask/OIDC client docs. Bundled social paths find an already registered local user using an allowed identity field; they do not create new social accounts. Other providers need configuration and identity callbacks; default provider mappings are email-based. This is not a provider-subject link/unlink inventory, SAML SP/IdP, SCIM directory or managed customer organization product.
- **Organizations and costs:** Read full source inventory, User/Role/credential/refresh model specification, feature docs and complete account OpenAPI routes.
