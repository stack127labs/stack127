## Conflicts and unknowns

- **Core lifecycle:** Read live npm metadata, core repository metadata, latest commit, README and changelog. The current release is 0.7.0 from 2023, the latest default-branch commit is from 2024, and the repo is not archived. An open issue asking about maintenance had no maintainer assurance in the comments retrieved; user questions/comments are not used as product proof. No official retirement/acquisition notice or formal future maintenance promise was established.
- **Renamed SAML package:** Registry metadata explicitly deprecates unscoped passport-saml. Current scoped package is 5.1.1, with a September 28, 2026 changelog. Older Passport directory snippets can still name the unscoped package. The maintained strategy's own installation instructions are used. This rename does not rename Passport.js.
- **Published versus repository behavior:** Current package metadata establishes release versions and dates. Source READMEs/implementation files establish the checked repository behavior. No install/test proved every optional strategy works with core 0.7.0, every Express release or every provider's current production policy. The library declares a historical Node engine floor; this is distinct from an actively maintained runtime support promise.
- **Passkeys:** Read the WebAuthn strategy README, implementation, session challenge store and npm release metadata. Public-key authentication/registration callbacks and origin/challenge/RP checks are established. A full conditional-autofill, native mobile, synced-passkey, fallback/recovery and domain-migration matrix was not found. User verification/counter policy requires app integration rather than assuming every device flow is automatically enforced.
- **MFA and lifecycle:** Read TOTP README/package docs, core request/session code and signup/password/email tutorials. TOTP verification is a real plugin capability, but enrollment, requiring the factor on protected routes, lost-device recovery, reset, address changes and account deletion remain app code. Magic-link first-factor login is not counted as a second factor.
- **Social and account linking:** Read selected Google, Facebook, GitHub2, Apple and Microsoft strategy docs/repositories plus delegated-authorization docs. The five documented integrations are separate packages, not built-ins. No exhaustive compatibility/licensing/maintenance review of the hundreds of listed strategies was attempted. Provider account eligibility, app review and third-party fees were not guessed. Apple MIT finding uses package.json because no root license file was present; Microsoft's initial LICENSE lookup was repaired to the actual License file.
- **Sessions:** Read core sessions/login/logout docs, sessionmanager, request helpers and session strategy; read express-session's own README for store/cookie behavior. Current-session logout/regeneration is established. The app owns expiry, distributed session stores, device lists, broad revocation and external-token lifecycle. Core session middleware passing a request onward does not itself guard a protected resource.
- **Organizations and business protocols:** Read core purpose/schema boundaries, scoped SAML README/MultiSamlStrategy, OIDC strategy and token-auth docs. Incoming SAML SP and OIDC client flows are implemented through plugins. Neither supplies a customer-workspace invitation/role model or a SCIM directory server. A configurable multi-IdP strategy is not a complete multitenant SaaS feature.
- **Migration and deletion:** Read local verification/signup sample, example database schema, session serializer/deserializer and linking docs. Application access to its own database makes profile/credential extraction an app/database task, but no universal export/import schema, cross-provider credential conversion or passkey-domain migration guarantee follows. Logout does not delete user records or revoke all upstream grants.
- **Operations and support:** Read core README/package, contributing guide, issue/PR templates, repository file tree and session-store production warning. Universal hardware/user capacity guidance, core LTS/version support matrix and guaranteed patch/security-response deadline were not found. Selected TOTP/WebAuthn, magic-link and SAML packages have different dated releases; one package's update date is not transferred to another.
- **Hosted fields:** No hosted price, member-meter, billing-country, trial/card, region, DPA/subprocessor, vendor audit retention, status SLA or paid support contract was sought for the local library. Those fields are inapplicable, not failed searches. Any chosen hosting, email, identity or session-storage service needs its own commercial/privacy review.
