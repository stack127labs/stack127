## Cost examples — our calculation

These are comparisons of Memberstack authentication/membership charges, not total website running costs. Currency is USD under terms section 5.2. All examples use monthly billing, one production app and one developer owner, with no eligibility discounts, annual commitment, taxes, SMS or optional security add-ons.

The requested users registered before the month and each return on at least two days. Memberstack counts **all Live accounts**, so this pattern alone is insufficient. The explicit consumer sub-scenario is **exactly N total Live accounts, with no additional inactive accounts**, all on free member plans and with **USD 0 membership revenue**, using email/password or Google. Therefore the Memberstack membership transaction charge is zero. A larger stored population can require a different subscription even at the same monthly activity.

Excluded: website/Webflow/WordPress hosting, custom backend/database, domain registration, developer work, external automation and any independently chosen email service. Built-in welcome mail is explicitly at no extra charge; no exact transactional send quota or overage rate was found. There is no recurring mandatory message volume in the returning-password/social-login baseline, so no invented per-email charge is added. Stripe processing is not triggered by zero-revenue membership in these consumer examples.

The business rows retain every required input, including customer SAML; they are unsupported rather than priced as a weaker membership-only substitute.

## Conflicts and unknowns

- **Exactly 1,000 members:** Pricing says Basic includes up to 1,000 while its FAQ and terms section 5.10 say automatic upgrade occurs at 100% of usage. Both pricing and terms were read, and the help-centre capacity and billing/member-limit search results were checked. The next published tier is USD 49/month; exact transition proration and whether a stable exactly-1,000 population can stay at USD 29 were not reconciled. No boundary of 1,001 is invented.
- **Above 10,000:** Pricing's Business/Established “10,000+” does not supply a volume ladder. The capacity article explicitly says contact sales above 10,000. Its Established-pricing link redirects to a read-only Airtable quote form with no retrieved public rate. No form was submitted; 50,000/100,000 remain quote-dependent.
- **Trial and refund language:** Unlimited-duration test access and a first-30-days unconditional refund appear on pricing. General terms default Evaluation Services to 30 days and describe refunds as discretionary after service-quality evaluation. The exact relationship between an ordinary test account and legally defined Evaluation Services is not explained. Both wordings are preserved.
- **Customer business identity:** The custom SSO explanation explicitly rejects incoming external identity providers; the setup guide describes Memberstack as an outgoing OIDC provider. Team Accounts offer invitations and owner/member administration, but do not repair the required customer-SAML gap. SCIM search returned no relevant articles.
- **Passkeys, app-user MFA and other methods:** Checked complete DOM authentication reference, passwordless guide, pricing, social/SSO documentation and public help-centre passkey/MFA searches. No native passkey or customer second-factor/recovery implementation was established. The dedicated TOTP guide protects builders' dashboard accounts. It is not counted as end-user MFA. No supported email-link, phone/SMS, anonymous or wallet sign-in implementation was established.
- **Credential migration:** Checked members/plans export, Admin member actions/schema, CSV import and hash search. Profile and plan extraction is documented; current password-hash/OAuth-credential export and a general external-hash compatibility list are not. An old Memberstack 1.0 hash column is not current 2.0 portability proof.
- **Retention and geography:** Read privacy policy, DPA including Appendix A, TIA, security overview, account/member deletion and both log guides. US customer-data storage is stated; named cloud regions, selectable EU residency, full backup/log geography and universal numerical purge periods were not found. Two-week access-log retention does not establish retention for all event types. Deleted-member backups are expressly unavailable for recovery.
- **Security and capacity:** Checked security overview, CAPTCHA/disposable-email guides, password reset, token verification, current authentication docs and Admin/REST rate limits. Published Admin throughput is not a login capacity guarantee. Exact managed login/passwordless throttle windows, compromised-password screening and numerical endpoint limits remain unestablished.
- **Assurance retrieval:** The subprocessor URL linked by privacy policy returned HTTP 403 in a direct fetch, and web access also failed. No list was reconstructed from indirect claims. The security overview links a SOC 2 report, but report type, observation period and auditor were not verified from the report itself.
- **Other bounded gaps:** Pricing, developer auth/UI docs, builder admin/multiple-site guides, logging docs, status page, support article and terms did not yield exhaustive customer-country eligibility, builder/project/domain quotas, a full transactional send schedule, accessibility assessment, audit export/retention tiers, formal SDK support windows or numerical SLA credits. Public package metadata gave current versions and MIT declarations; its Admin repository URL and attempted LICENSE returned 404. Missing public evidence is recorded as not_published; the inaccessible subprocessor list is check_failed.

## Field problems

- F08/F12 require stored-member sub-scenarios. Monthly activity cannot be substituted for Memberstack's Live account count.
- F14/F27 must distinguish customer Team Accounts, paid member plans, developer admins and subscription tiers. These are not interchangeable organization/seat units.
- F15/F26 must name federation direction. “Custom SSO” here cannot be compared with an incoming enterprise SAML connection.
- F22/F23 must distinguish first-factor email OTP, verified-email links and builder dashboard MFA. They do not establish passkeys or customer MFA.
- F25 needs separate token lifetime, browser persistence and server revocation evidence. The inactivity-duration UI is not a complete token security specification.
- F35 is not applicable to the documented standard hosted offer. An advanced custom-API-domain configuration mentions enterprise/self-hosted deployments but supplies no public self-host edition or installation evidence.
- F39/F40 must separate profile CSV portability, old 1.0 migration and current credential portability. A generic “export supported” answer would be misleading.
- F43 assurance scope cannot be inferred from a SOC 2 label; the current subprocessor list remained inaccessible.
- F50 uses the owner's six permitted evidence states. Calculations keep those states and are explicitly labelled as our calculation.
