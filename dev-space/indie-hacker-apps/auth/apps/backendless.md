# Backendless

**Shutdown, sunset and acquisition check (2026-11-05):** No official notice of a whole-platform shutdown or completed acquisition was found in the checked site, pricing, terms and official support statement. Backendless staff said on 2025-07-07 that the platform was actively maintained and there were no shutdown plans. The public Cloud/Pro offers remain available. This is dated vendor evidence, not a promise about future operation; signup was not tested. Checked 2026-11-05.

**Historical plan sunsets:** Cloud 9 ended 2023-08-01; Springboard ended 2024-01-01; Cloud 99 was phased out 2024-05-01, with automatic Scale Variable transition described for May 2. Cloud Enterprise is no longer a current plan; its security features moved to an Enterprise Security Function Pack. The 2023 notice said Springboard apps that did not choose another plan would be blocked and deleted after 30 days. These are plan retirements, not a shutdown of native User Service. ## Cost examples: our calculation

All six examples follow fields.md’s registered-before-the-month, at-least-two-return-days pattern. Backendless bills all app API activity and applies stored-record/feature limits. The user counts alone do not settle peak requests/minute, busy hours, inactive accounts or non-auth requests.

For a useful controlled sub-scenario, assume exactly two password logins per person in a 30-day cycle, one billed API request per login, and no other API requests. Spread the calls evenly and keep each person’s calls on different days. Store exactly the stated number of Users records, with no additional inactive users. This is a deliberately stated calculation input, not a forecast of normal app behavior or an observed capacity result.

- 30 days ×24 hours ×60 minutes = 43,200 minute windows.
- With an even schedule, peak minute requests can be no more than ceiling(2×users ÷43,200).
- At 1,000 and 10,000 stored users, Free fits the current 15,000-object Users-table limit. The schedules also stay below both 50 requests/minute and the old 1,000/day cap, whose current enforcement is not established.
- At 50,000 and 100,000 users, Free’s Users-table record cap is exceeded. Scale tier 1 permits the modeled request rate, and both record counts fit its 100,000-objects-per-table limit. Scale Fixed base is $15/30-day cycle with no overages under this schedule; Scale Variable is $0.50×30=$15.
- These are conditional totals for the restricted sub-scenario. A larger peak, more users stored, other API activity or required packs changes the result. No annual discount is silently used. Password login does not inherently send email at every login; verification/reset messages need separate delivery inputs.

## Conflicts and unknowns

The linked 2023 introduction lists 10 tables, 10 realtime connections and 1,000 requests/day. The different table/connection values are historical-versus-current differences, not silently blended. The current card’s omission of a daily cap does not prove it was removed, so that narrow point remains unclear. All cost sub-scenarios stay within both published daily/burst constraints where Free is selected. Sources: <https://backendless.com/pricing/backendless-cloud/>, <https://backendless.com/introducing-scale-plan/>, <https://backendless.com/terms-of-service/>. Checked 2026-11-05.

## Field problems

- F08/F12: Peak-per-minute/day/hour billing cannot be converted from a user count without explicit traffic assumptions. Keep sub-scenario results separate from the unresolved general total.
- F09/F18: Public introductory articles retain older limits. A missing daily cap on a current table does not prove its removal. The current rate card and older notice must stay distinguishable.

- F35/F39/F48: Proprietary free Core server license and ISC client metadata have different scope. Current Pro docs, older EULA and repository development/release versions must not be collapsed into one license or version.
- F41–F43/F46–F49: Legal deletion promises, backup mechanics, Console change logs, app-user events, monitoring and response SLAs need separate evidence. No invented retention, accessibility score or measured uptime is added.
