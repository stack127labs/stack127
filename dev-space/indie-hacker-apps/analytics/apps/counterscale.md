## Cost examples — our calculation

Checked 2026-11-05. Inputs: [Worker pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Worker limits](https://developers.cloudflare.com/workers/platform/limits/), [Analytics Engine pricing](https://developers.cloudflare.com/analytics/analytics-engine/pricing/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/) and the source [pageview flow](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/tracker/src/lib/track.ts) / [request functions](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/tracker/src/lib/request.ts). These are analytics infrastructure estimates, not a price for hosting the website being measured.

Assumptions: one site, one dashboard operator, 30 days, bundled browser npm tracker, pageviews only, no other account workloads, and no duplicate manual pageview calls. Bundling is explicitly documented in the [README](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/README.md). It avoids assuming every script-load URL is free: default assets may be served directly, while the [custom script route](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/routes/$script.ts) can invoke Worker code.

Each pageview normally makes one `/cache` request followed by one `/collect` request. The collector writes one Analytics Engine data point. For an explicit request budget, allow another 100 dynamic Worker invocations each day for dashboard/other activity. This is our chosen workload allowance, not a measured dashboard request count. SQL read queries are a separate input.

`tracking requests/month = 2 × monthly pageviews`

`modeled Worker requests/month = 2 × pageviews + (100 × 30)`

`peak modeled requests/day = 2 × ceil(pageviews ÷ 30) + 100`

The ceiling gives the highest day in a near-even integer distribution. Real traffic can spike; a monthly total cannot guarantee compliance with a daily cap.

| Pageviews/month | Tracking requests/month | Modeled Worker requests/month | Highest modeled day | Software + Free Worker request subtotal |
| --- | --- | --- | --- | --- |
| 10,000 | 20,000 | 23,000 | 768 | USD 0, conditional on the other limits |
| 100,000 | 200,000 | 203,000 | 6,768 | USD 0, conditional on the other limits |
| 1,000,000 | 2,000,000 | 2,003,000 | 66,768 | USD 0, conditional on the other limits |

All modeled days are below the Workers Free 100,000/day request cap. This subtotal is **not an exact all-in hosting bill**. Free execution must also fit the CPU/memory/runtime limits; Analytics Engine needs query/write headroom; the default archive consumes R2 resources. None was measured. Other sites in the same Cloudflare account consume shared allowances.

For a paid Workers Standard scenario:

`Worker charge = USD 5 + USD 0.30 × max(0, requests - 10,000,000) ÷ 1,000,000 + USD 0.02 × max(0, CPU_ms - 30,000,000) ÷ 1,000,000`

If total monthly CPU is independently specified as at most 30 million ms, each modeled workload has a USD 5/month Worker charge. This is an explicit CPU condition, not an assumed per-pageview performance measurement.

`complete infrastructure total = Worker charge + currently billed Analytics Engine charge + R2 storage/operations + any other selected services/taxes`

The current Analytics Engine page says usage is **not yet billed**. Its announced future rates are retained in F11, not added as a current bill. Read-query and write limits remain relevant. For R2 Standard, storage/operations cost can be zero within its free allowances, but archive size and operations are not known from pageviews alone. Use the provider's rounding rules when calculating any paid R2 usage; do not silently convert Arrow rows to bytes.

The project homepage's 50,000 pageviews/day and README's hypothetical 100,000 hits/day are not equivalent guarantees. The current browser implementation's two tracking requests explain why the 100,000 Worker-request cap cannot simply become 100,000 browser pageviews. Script delivery, dashboard traffic, CPU and archiving can lower practical headroom further.

No generic product-event, native-MAU, recorded-session or MRR cost is calculated. The documented tracker records pageviews; those other units cannot be converted without inventing a workload.

## Conflicts and unknowns

- **Retention:** the [homepage](https://counterscale.dev/) says data is retained only 90 days. The [README](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/README.md) says long-term R2 storage is enabled by default, and the [scheduled worker](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/workers/app.ts) / [Arrow writer](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/workers/lib/arrow.ts) implement it. The [dashboard source](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/routes/dashboard.tsx) still queries a 90-day window. Keep live report history separate from retained archive copies.
- **Provider retention units:** [Cloudflare](https://developers.cloudflare.com/analytics/analytics-engine/limits/) says three months, while Counterscale uses 90 days. Those are not silently converted into identical calendar durations.
- **Free traffic claims:** the homepage says 50,000 pageviews/day; the README says the provider free tier could hypothetically support 100,000 hits/day. [Tracking/request source](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/tracker/src/lib/track.ts) / [request source](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/tracker/src/lib/request.ts) shows two tracking calls per browser pageview. These claims have different units and conditions; neither is an independently tested capacity figure.
- **Current versus future pricing:** [Analytics Engine pricing](https://developers.cloudflare.com/analytics/analytics-engine/pricing/) explicitly states usage is not currently billed, even while publishing future usage rates. The record preserves both. Workers and R2 can still generate charges.
- **Privacy does not mean no browser state:** [cache handling](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/routes/cache.tsx) and [visitor logic](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/analytics/collect.ts) use HTTP revalidation state to count first/second/third-plus visits per day. The written [schema](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/analytics/schema.ts) includes raw user-agent text. No cookies/fingerprinting is not a promise that no identifying content can enter URLs, campaigns or provider logs.
- **Sessions:** a [schema comment](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/analytics/schema.ts) describes a 30-minute session counter, but the [actual collector](https://raw.githubusercontent.com/benvinegar/counterscale/v3.4.1/packages/server/app/analytics/collect.ts) writes that column as zero and calls it dead. Direct reads of [privacy](https://counterscale.dev/privacy) and [terms](https://counterscale.dev/terms) returned homepage content; initial web retrieval failed for those paths. They were not treated as legal documents. The [MIT license](https://raw.githubusercontent.com/benvinegar/counterscale/main/LICENSE) governs software, and the self-hoster's [Cloudflare terms](https://www.cloudflare.com/terms/), [privacy policy](https://www.cloudflare.com/privacypolicy/) and [DPA](https://www.cloudflare.com/cloudflare-customer-dpa/) govern infrastructure relationships.
- **Ownership:** the project and license were checked; no separate legal operator/company country was established. Sponsor wording is not proof of ownership. In line with the research rule, no private person's name or address is recorded as operator.
- **Unknowns searched:** homepage, release README, dashboard/report/collector/tracker/cache/archive source and Cloudflare policies were checked for a managed edition, complete country list, per-user permissions, replay/native SDKs, goals/funnels, revenue metrics, consent exemptions/CMP/DNT/GPC behavior, region/backup map, erasure endpoints, native CSV/API contracts, historical imports, bot/staff filtering and versioned script weight. Missing mentions stay unknown.
- **Archive limits:** daily Arrow output is grouped data, potentially affected by source sampling. No native dashboard restore/import path or application archive-expiry rule was established. Disabling storage prevents future extraction; it is not evidence existing files are deleted.
- **Access/retrieval:** the official demo initially failed web retrieval but was readable by direct HTTP, which exposed report headings. Several combined tool outputs were too long and were re-read in smaller groups or bounded legal excerpts. These recovered reads are not counted as failed fact checks. No account, browser automation, tracker execution, resource deployment or website crawl was used.
- **Lifecycle:** shutdown/sunset/acquisition searches were followed into the official site, source and release metadata. No applicable notice was found. Other public deployments and similarly named businesses were not used as proof.

## Field problems

- F06/F30: “self-hosted” means deployed in your own Cloudflare account. An arbitrary VPS install, self-run database and cloud-account deployment are different operating models.
- F08–F13: pageviews produce multiple requests and one data point; queries, CPU and archives are separate. Daily free caps cannot be replaced with a simple monthly price-per-pageview.
- F21/F22: cookie-free does not mean stateless. HTTP cache-based recognition needs its own explanation; the project does not publish a complete jurisdiction-specific consent determination.
- F23/F24: ownership of the account does not establish exclusive local storage or no processor access. No full analytics residency/backup map was found.
- F25/F26/F27: 90-day dashboard, three-month provider history, R2 archive lifetime, portable daily rollups and an import workflow are separate facts.
- F16/F28: stale schema comments cannot establish a live session metric, and adaptive sampling prevents an unconditional unsampled-count label.
- F32: the default snippet is distinctive, but custom domains, configured script names, bundles and server-only tracking make C appropriate. Detection has not been validated.
- No clear `apps.md` row error found. Active availability, self-hosted Cloudflare scope, web reporting/hosting overlap and class C fit the evidence. Its unknown operator is not replaced with an inferred company.
