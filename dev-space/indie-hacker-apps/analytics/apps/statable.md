## Cost examples: our calculation

Inputs checked 2026-11-05: https://statable.com/pricing; https://statable.com/docs/billing/plans/; https://statable.com/docs/settings/tracking-features/. One site, one owner user, ordinary domain outside the free suffix rules. USD before applicable VAT/tax. Annual prices are explicitly published totals, not calculated by applying one flat 20% reduction.

For pageview-only cases, assume no manual/tagged events and no billable automatic outbound/download events. Nano or a suitable Custom build can implement that capture scope; the default Standard build records additional interactions. These scenarios are stated workloads, not an assumed universal ratio between traffic and events.

Disabling a feature stops future events and does not remove usage already recorded this month. No visitor-to-event, active-user or revenue ratio was invented.

Eligible .edu/.github.io/.gitlab.io sites have a separate $0 Free Access path with unlimited traffic, required visible widget/attribution and the documented sharing/member/import restrictions. It is not a free private commercial-domain plan. ## Conflicts and unknowns

**Retention after expiry is inconsistent.** Privacy section 8, DPA section 8 and the cancellation docs retain analytics while the account exists, explicitly without automatic deletion on subscription lapse. Terms section 19 allows an export request for 30 days after subscription expiration/termination and says data may then be deleted. The long-term history promise is therefore not treated as an unconditional contractual guarantee. Sources: https://statable.com/privacy; https://statable.com/dpa; https://statable.com/docs/billing/upgrade-and-change/; https://statable.com/terms.

**Returning-visitor wording is inconsistent.** The lightweight page's Lite build lists returning-visitor recognition. The Unique Visitors reference says returning visitors are unavailable because there is no cross-day identity; privacy and current tracking docs describe daily/site-specific hashing rather than a persistent mode. No separate returning-user implementation or lifetime is established. Both wordings remain recorded. Sources: https://statable.com/lightweight-web-analytics; https://statable.com/docs/basics/unique-visitors/; https://statable.com/privacy; https://statable.com/docs/settings/tracking-features/.

Other distinctions have explicit scope rather than a proven contradiction:

- Some price tables still say pageviews, but the live FAQ and billing guide explicitly define allowance as pageviews plus custom events. They also name automatic outbound/download events and exclude engagement. The explicit definition is used for calculations. Sources: https://statable.com/pricing; https://statable.com/docs/billing/plans/.
- Broad full-feature language does not describe every hobby condition. Hobby sites have mandatory widget tracking, no members/import, and public dashboards while the account is free. A paid account can hide a hobby dashboard; trial access is not paid access for that toggle. Sources: https://statable.com/docs/billing/plans/; https://statable.com/docs/settings/members/; https://statable.com/docs/migrate/from-google-analytics-4/; https://statable.com/docs/settings/public-dashboard/.
- The trial is 30 days from first non-FreeAccess site, followed by a separate 30-day recording grace with closed reports. It is not 60 days of freely readable reports. Paid cancellation goes straight to stopped collection at the end of the paid term; qualifying hobby sites continue. Sources: https://statable.com/docs/billing/plans/; https://statable.com/docs/billing/upgrade-and-change/.
- Security says analytics can be exported at any time, but the current API/CLI and dashboard docs establish aggregate report output, no raw visitor/session endpoint and no bulk archive/CSV endpoint. Dashboard bulk export is on the roadmap. A raw-data download route is not inferred from the broad wording. Sources: https://statable.com/security; https://statable.com/docs/developers/stats-api/overview/; https://statable.com/docs/cli/; https://statable.com/docs/dashboard/reports/.
- API keys may have destructive site-management rights, while the hosted MCP surface has no delete tool. Both expose aggregates, not individual records. Customer-chosen assistants/models act for the controller, rather than becoming Statable subprocessors. Sources: https://statable.com/docs/developers/stats-api/authentication/; https://statable.com/docs/integrations/mcp/; https://statable.com/dpa.
- Working-system deletion is immediate; encrypted backup expiry is within 14 days. These are compatible stages. Source: https://statable.com/privacy; https://statable.com/dpa; https://statable.com/docs/account/delete-account/.
- Default privacy guards coexist with intentional browser opt-out storage and separate dashboard authentication cookies. Owner-supplied properties/paths can contain personal information despite minimized defaults. Sources: https://statable.com/docs/getting-started/privacy/; https://statable.com/privacy; https://statable.com/docs/events/custom-properties/.

- **Interface languages:** docs/feature overview and WordPress guide. A complete dashboard-language matrix was not found.

## Field problems

- F08/F12: an older pageview label can hide event costs. Explicit meter definitions and a mixed workload are needed. Annual prices vary in effective discount and should be copied, not generated from a flat percentage.
- F09/F11/F14: per-site hobby eligibility, owner-account paid status, seat quotas and full-feature marketing overlap. Separate restrictions are necessary.
- F10/F25: trial, grace, paid cancellation, contractual export windows and account deletion are different states. The retention conflict needs vendor clarification.
- F16/F21: daily identities and user-supplied properties do not establish a built-in persistent profile. Returning-user marketing wording remains unresolved.
- F17/F18/F19: funnels, mobile browsers and purchase events are not evidence of replay, native SDKs or subscription accounting.
- F20/F24: disabling the plugin tag does not necessarily stop embedded widget capture. A pageview before-send hook is not a global redaction hook for custom events.
- F23: Netherlands visitor storage, worldwide CDN transit, account/billing transfers and controller-connected AI clients need distinct scope.
- F26: aggregate CSV via CLI, retained raw data and raw bulk portability are different capabilities. Dynamic API limits cannot be filled from sample headers.
- F27/F28: imported GA active-user/duration/bounce definitions differ from native daily visitor/session rules; filter compatibility can hide imported days. A continuous chart is not identical measurement.
- F29: Standard/Nano/Custom terminology and Lite/Full marketing labels differ. Widget bundles have a different footprint; claims were not measured.
- F30/F32: the WordPress connector is not self-hosted analytics. Default numeric script paths and widget tags need separate proposed detector signals. No crawl/validation was run.
