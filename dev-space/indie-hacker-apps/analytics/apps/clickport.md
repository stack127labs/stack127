## Conflicts and unknowns

1. **Custom-event allowance:** billing excludes custom events, including clickport.track(), from pageview usage; custom-event docs say they count like a pageview. Both were read: https://clickport.io/docs/billing; https://clickport.io/docs/custom-events. Pageview-only examples remain calculable, but an event-heavy workload needs clarification.
2. **Unpaid trial:** billing says collection keeps running behind a locked dashboard, with settings/export access; terms say collection stops. No source was silently preferred: https://clickport.io/docs/billing; https://clickport.io/terms.
3. **Identifier secret:** the privacy policy describes a stable server secret with a daily date input; the privacy overview describes 24-hour salt rotation with destruction after an overlap. Both support daily identifier changes, but the secret lifetime differs: https://clickport.io/privacy; https://clickport.io/docs/privacy-overview.
4. **Session grouping:** the sessions guide describes a tab-scoped stored session ID, while the privacy policy and privacy overview's technical note say the cp_sid marker no longer groups visitors. The overview itself retains both kinds of wording: https://clickport.io/docs/sessions; https://clickport.io/privacy; https://clickport.io/docs/privacy-overview.
5. **Erasure:** privacy/security promise immediate deletion; terms allow 60 days; the DPA says 30 days and no retained copies; the deletion guide requires a human confirmation step and describes backup and billing exceptions. These may involve different stages, but the pages do not reconcile their unqualified promises: https://clickport.io/privacy; https://clickport.io/security; https://clickport.io/terms; https://clickport.io/dpa; https://clickport.io/docs/delete-account. The one-business-day target is an initial reply, not a completion guarantee.
6. **IP handling needs scope:** the overview's broad discard/no-IP language cannot describe every operational record. Privacy, security and DPA explicitly retain raw IP in restricted operational logs, with request bodies possible in event-recovery logs. The table records analytics-store exclusion and operational processing separately: https://clickport.io/docs/privacy-overview; https://clickport.io/privacy; https://clickport.io/security; https://clickport.io/dpa.
7. **Script-size baselines:** under 5 KB for all modules and approximately 2 KB are compatible claims, but the docs do not establish identical builds. No measured size or performance result is claimed: https://clickport.io/docs/script-configuration; https://clickport.io/docs/privacy-overview.

For missing facts, the table records the exact pages tried. In particular:

- Lifecycle/old names: official-site lifecycle search, homepage, about and status pages. No notice found; the status page was not used to calculate uptime.
- Dashboard languages: visitor-language docs, installation and about. Visitor language reporting is not an interface-language list.
- Country/sanctions eligibility: terms, billing and DPA. Hosting in Germany and a Paddle checkout do not prove every country is eligible.
- Self-host/private edition: installation, about and terms. A first-party proxy or a custom contract does not establish a downloadable analytics backend.
- Custom-volume price and refunds: billing, security and terms. The custom contact route is public; an exact quote and universal refund window are not.
- Seat caps: team and billing docs. Role support does not establish unlimited users.
- Heatmaps/native mobile: homepage, sessions, script configuration, installation and API. Event timelines and mobile web visits do not establish recordings or maintained native SDKs.
- Full subscription-finance metrics: ecommerce, Stripe and Paddle integration guides. Those explain payment attribution rather than a complete MRR/churn/tax ledger.
- Exact hourly-backup retention: security, DPA and account-deletion guide. About 30 days is documented for daily backups, not every backup class.
- Standalone public demo: home, about and status. Product previews and the no-card trial are available, but an independent no-account interactive dashboard was not established.

## Field problems

- F08/F12: the pageview meter is usable, but conflicting custom-event metering prevents a trustworthy combined pageview/event estimate. No pageview-to-event or user-to-event conversion was invented.
- F16/F21: daily visitors, tab sessions and cp_sid have inconsistent implementation descriptions. Recording separate assertions is more useful than a single anonymous-identity label.
- F17/F18: a session timeline is explicitly not replay, and a mobile website/server HTTP API is not a native SDK. Unsupported product claims were not inferred from nearby features.
- F19: payment attribution overlaps revenue analytics, but does not establish a complete recurring-revenue product. Payment-source and currency facts were recorded without adding unrequested financial detail.
- F24/F25: erasure requests, actual deletion, backups, invoices, cancellation and unpaid trials require separate scopes. One retention number would hide material differences.
- F29: published compressed-size claims lack a common version/build baseline; no measurement was attempted.
- F32: the row's E class describes the default public snippet. It cannot measure server-only AI/revenue connections, every proxy or actual adoption. No detection validation or crawl was run.
- No field change is proposed. All 33 groups were attempted; optional unknowns were left explicit.
