## Conflicts and unknowns

- **Event metadata limits conflict inside one guide.** Its Limits section caps metadata at 20 pairs, while Example 3 says there is no limit to the number of metadata fields. The same guide also distinguishes string metadata from numeric metric interpretation elsewhere. No unlimited-field promise is made. Source: https://docs.pirsch.io/advanced/events (2026-11-04).
- **CSV history scope is unclear.** Privacy docs say CSV export covers the last 12 months; the dedicated export guide has a period selector without an explicit maximum. Neither unlimited retention nor API access proves an unrestricted CSV lookback. Larger/custom/raw exports are offered by request, and raw access is listed under Enterprise; exact eligibility and fees for other plans were not established. Sources: https://docs.pirsch.io/privacy ; https://docs.pirsch.io/get-started/export ; https://pirsch.io/pricing (2026-11-04).
- **Some DPA backup details could not be checked.** The readable DPA names a backup strategy and German processing locations, but its final technical annex did not provide readable extracted text. Attempts to retrieve annex screenshots failed with “Cache miss.” A separate backup location and maximum survival/deletion period remain unverified. Source: https://pirsch.io/static/files/Data%20Processing%20Agreement%20-%20Pirsch%20Analytics.pdf (2026-11-04).
- **Sampling and weight claims have dates.** The last explicit sampling announcement examined is 28 October 2023: dashboard results above 10m unique visitors sampled, with an approximately 1% accuracy effect claimed by the vendor. The less-than-4-kB compressed pa.js claim is dated 11 April 2024. Neither is a new measurement of the November 2026 product. Current features, API docs, troubleshooting, news and changelog were checked; no new universal no-sampling guarantee or versioned current payload measurement was established. Sources: https://pirsch.io/news ; https://pirsch.io/features ; https://docs.pirsch.io/api-sdks/api-v1 ; https://docs.pirsch.io/changelog (2026-11-04).
- **Google import wording is partly stale.** The importer guide opens with GA3/Universal Analytics but also discusses GA4 limitations. Changelog 2.7.0 explicitly added GA4 import in August 2024, so the opening is not used to deny GA4 support. Daily aggregate/filter/export restrictions remain documented. Sources: https://docs.pirsch.io/get-started/ga-import ; https://docs.pirsch.io/changelog (2026-11-04).
- **Current and future versions differ.** Platform changelog 2.14.22 is separate from the public core's master module v7. Platform v3 is announced for 21 November 2026; API v2 docs say work in progress. Proposed v3 reporting and permissions are not assigned to current subscriptions. Sources: https://docs.pirsch.io/changelog ; https://pirsch.io/news ; https://raw.githubusercontent.com/pirsch-analytics/pirsch/master/go.mod ; https://docs.pirsch.io/api-sdks/api (2026-11-04).
- **No complete account eligibility list found.** Checked terms, registration/privacy and payment docs. Both consumer/business use is allowed, but a complete buyer-country list and universal minimum age were not established.
- **No persistent product identity or native mobile matrix found.** Checked default visitor hashing, event/tag docs, statistics, API v1 and SDK list. A mobile mention in session-extension docs does not establish maintained iOS/Android clients, offline queues or native feature parity. Daily site hashes and anonymous role tags are not a cross-day account/person model.
- **No recorder or subscription ledger specification found.** Checked all features, session statistics, SDK/API docs and custom goal metrics. Replay/heatmap quotas, masking/retention, automatic billing-source MRR/churn, refund/tax accounting and currency reconciliation were not established.
- **No fixed post-cancellation history/export grace found.** Checked Billing, Terms, privacy policy and readable DPA return/delete obligations. The billing guide explains trial collection stops, account deletion and balance handling, but gives no complete dated erasure timeline. The terms' consumer withdrawal rights are separate from the ordinary no-refund billing policy.
- **No complete full-product self-host requirement or public raw-export tariff found.** Checked the Enterprise offer, self-host FAQ, core README/module/license, export guide and API. Core dependencies do not establish a full on-premises CPU/RAM/storage minimum or operations split.
- **German visitor hosting has a specific scope.** The analytics DPA lists Hetzner processing in Nuremberg/Falkenstein. The service policy separately lists contact, email, CAPTCHA, payment and accounting providers, including US-based entities. No all-data/all-processing-is-Germany claim is inferred.
