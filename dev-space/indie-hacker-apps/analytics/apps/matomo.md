## Conflicts and unknowns

- **User ID linkage is inconsistent in one FAQ.** The login section says `enable_userid_overwrites_visitorid = 1` groups pre/post-login activity but prevents cross-device tracking; the multi-device section says shared User IDs merge concurrent visits by default and disabling that setting separates devices. The JavaScript guide confirms cross-device User ID support and logout reset, but does not resolve every default in the FAQ. Preserve the conflict; do not promise anonymous-history backfill. Sources: https://matomo.org/faq/general/how-are-requests-with-a-user-id-tracked/ ; https://developer.matomo.org/guides/tracking-javascript-guide (2026-11-04).
- **WordPress premium price scope needs clarification.** The public price list distinguishes WordPress from On-Premise. The WordPress-linked replay page still displays an On-Premise-style user/hit allowance, while the marketplace FAQ describes site-based WordPress licenses. The 99EUR list value therefore lacks a fully established WordPress tier here. Sources: https://matomo.org/pricing.php ; https://plugins.matomo.org/HeatmapSessionRecording?wp=1 ; https://shop.matomo.org/faq/ (2026-11-04).
- **No complete Cloud country eligibility list found.** Checked the Cloud terms, Cloud privacy policy, pricing and trial prerequisites. A supported payment response or server location does not answer account eligibility.
- **No guaranteed monetary hard stop found.** Checked Cloud overage terms, the calculator and Manage Hits usage. The docs provide monitoring, exclusions and disabling collection; they do not establish a universal spend ceiling.
- **No complete native parity matrix found.** Checked official client docs, Android/Apple READMEs and replay docs. Official SDK availability does not establish maintained support for every wrapper, all OS minimums or native replay.
- **Company-level product reporting and subscription accounting remain unestablished.** Checked User ID, cohorts, ecommerce reports, tracking/reporting APIs and the server ecommerce guide. Custom fields and revenue events are not proof of an MRR ledger, automatic currency reconciliation or group-level analytics.
- **No fixed universal Cloud API rate or separate egress tariff found.** Checked the Cloud API terms, Reporting API and raw-export guide. Excessive-use suspension and resource limits still apply.
- **No comparable full tracker-size figure found.** Checked the JavaScript API reference, plugin tracker-merging setup and both native READMEs. No tracker was downloaded for measurement.
- **Apparent edition differences are kept separate.** Unlimited Community hits/users and software-level website scalability do not override paid bundle or Cloud quotas. The 24-month Cloud raw history, permanent aggregate reports, three-month recordings and 30/60-day termination deletion stages describe different datasets/states. The trial FAQ's “within a few days” is operational wording, not a contractual post-trial retention promise.
- **Current support pages agree.** The Team and Business bundle pages both advertise a 12-hour response with 24/5 coverage. Their promise is distinct from Cloud's best-effort contractual support; no older response-time figure was carried over.
