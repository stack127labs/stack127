## Field problems

- F08–F14 compare a bundled site platform, optional AI tools and a separately contracted recording app. They need different meters and plan scopes. Core Analytics being included does not make every traffic workload or replay plan free.
- F11 uses overlapping names: Analytics Pro is AI analysis; recording Pro is a recording allowance; older Business VIP wording does not map cleanly to current website plans.
- F16 needs a distinction between standard commerce funnels, recent session timelines and arbitrary product-event funnels. Wix explicitly lists custom sales funnels as unavailable.
- F17's “heatmap” can mean a time-of-day report grid, not a browser click/scroll map. TWIPLA's broader suite cannot be assumed to be included in its separate Wix recording integration.
- F18 separates mobile dashboard viewing, Wix member/native app activity reports and a general SDK for independent apps.
- F19 needs report definitions beside every revenue figure. Order dates, invoice issue dates, payment dates, refunds, subscription receipts and normalized MRR are different measures. The Data API page also describes “Total orders” using monetary wording; this apparent definition problem was not silently corrected or used in calculations. Source: https://dev.wix.com/docs/api-reference/business-management/analytics/data/introduction.
- F21–F22 need to separate platform-essential cookies, consented traffic data, server-derived Sales/People data and separate recording privacy modes. Corporate GPC rights do not establish a universal site-Analytics opt-out implementation.
- F25's dashboard history, API lookback, recording retention, recent activity and legally retained copies cannot share one retention value.
- F26 needs interface-specific permissions and limits. A 5,000-row CSV limit and a semantic API default page size of 50 are not sampling rates or lifetime storage caps.
