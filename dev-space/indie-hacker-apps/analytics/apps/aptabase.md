## Cost examples — our calculations

These are tariff calculations from the [current pricing page](https://aptabase.com/pricing), checked 2026-11-05. They are not vendor quotes. Each scenario assumes one app, one account holder, one region, no other events sharing the account, and monthly billing. Seat and pooling rules are not publicly established. Prices are USD; tax treatment is not published, so an exact tax-inclusive checkout total cannot be given. The permanent Free offer is subject to the pricing-versus-trial terms conflict recorded above.

Formula: total monthly analytics events = the explicit event workload. Select the smallest published monthly allowance that covers that total; do not multiply by a fabricated per-event price. Cloud analytics collection pauses at the limit rather than adding overage fees.

| Scenario | Inputs and formula | Our calculation |
| --- | --- | --- |
| Product analytics: 100,000 events/month | 100,000 ≤ 200,000-event allowance | USD 10/month |
| Product analytics: 1,000,000 events/month | 1,000,000 ≤ 1,000,000-event allowance | USD 20/month |
| Product analytics: 10,000,000 events/month | 10,000,000 ≤ 10,000,000-event allowance | USD 140/month |
| Native app: 1,000 monthly active users, explicit 20-event scenario | 1,000 × 20 = 20,000 events/month | USD 0/month under advertised Free allowance |
| Native app: 10,000 monthly active users, explicit 20-event scenario | 10,000 × 20 = 200,000 events/month | USD 10/month |
| Native app: 100,000 monthly active users, explicit 20-event scenario | 100,000 × 20 = 2,000,000 events/month | USD 40/month |
| Web: 10,000 pageviews/month, conditional manual event scenario | Exactly one manually sent page_view event per pageview, no other calls: 10,000 × 1 = 10,000 events | USD 0/month under advertised Free allowance |
| Web: 100,000 pageviews/month, same scenario | 100,000 × 1 = 100,000 events; select 200,000-event allowance | USD 10/month |
| Web: 1,000,000 pageviews/month, same scenario | 1,000,000 × 1 = 1,000,000 events | USD 20/month |

The 20-event mobile scenario is an assumption for this directory, not an observed usage ratio. Aptabase does not provide distinct MAU reporting under its stated identity model; the [about page](https://aptabase.com/about.md) explains the limit. More or fewer event calls change the price.

The web scenario is possible because the [web SDK guide](https://raw.githubusercontent.com/aptabase/aptabase-js/main/packages/web/README.md) permits manual events on websites. It is not automatic pageview reporting or a claim of equivalent referrer/UTM reports. Full page reloads start new sessions. Without the explicit one-call-per-pageview assumption, pageviews alone are not comparable to this event tariff.

Self-hosted: the [server README](https://raw.githubusercontent.com/aptabase/aptabase/main/README.md) states the software can be used free; the [AGPL licence](https://raw.githubusercontent.com/aptabase/aptabase/main/LICENSE) applies. Total operating cost = software licence fee (USD 0) + server/storage/network/backup/email costs + operator maintenance. The [Compose recipe](https://raw.githubusercontent.com/aptabase/self-hosting/main/docker-compose.yml) supplies the dependencies but no costed resource minimums. Hosting and total cost at the workloads above therefore cannot be calculated exactly; no USD 0 managed-service comparison is made. Cloud event allowances/prices are not applied to self-hosting.

No replay-session tariff is established for the event-timeline product, and no MRR-based tariff is published. The replay and revenue workload tables therefore do not apply. Optional error reporting has a separately described quota in the [Swift guide](https://raw.githubusercontent.com/aptabase/aptabase-swift/main/README.md); public numeric limits/prices were not established, so the event-only totals do not claim to price an error-monitoring workload.

## Conflicts and unknowns

- **Free versus trial:** [pricing](https://aptabase.com/pricing) advertises a 20,000-event Free allowance and pay-when-you-grow entry. [Terms §4](https://aptabase.com/legal/terms) instead describe an unspecified trial followed by mandatory payment, account freezing and possible cancellation after 60 frozen days. Both are retained; no signup was used to resolve actual account behavior. The terms allow annual cycles, but no annual price was found on pricing.
- **Anonymisation wording:** [about](https://aptabase.com/about.md) says full anonymisation and no pseudonymisation; the [privacy policy](https://aptabase.com/legal/privacy) and [DPA Annex II](https://aptabase.com/legal/dpa) explicitly describe a pseudonymous daily IP/UA-derived identifier. The DPA also describes personal-data processing and processor obligations. The marketing no-banner/compliance claims remain vendor claims, not a legal verdict. Current self-host source additionally caches per-session user hashes for 48 hours; see [DailyUserHasher](https://raw.githubusercontent.com/aptabase/aptabase/main/src/Features/Privacy/DailyUserHasher.cs). No hosted behavior or anonymity property was independently tested.
- **Deletion:** the [privacy policy](https://aptabase.com/legal/privacy) says individual end-user records cannot be identified for deletion. [DPA clause 7](https://aptabase.com/legal/dpa) qualifies rights/assistance where extra information enables identification. App/account deletion is separately documented. A no-data-subject-rights conclusion would overstate the sources.
- **SDK version drift:** [site docs](https://aptabase.com/docs.md) show Kotlin 0.0.8; the [Kotlin README](https://raw.githubusercontent.com/aptabase/aptabase-kotlin/main/README.md) uses 0.1.0. Site docs also restrict property values to strings/numbers, whereas [current JS documentation](https://raw.githubusercontent.com/aptabase/aptabase-js/main/llms.txt) and [web source](https://raw.githubusercontent.com/aptabase/aptabase-js/main/packages/web/src/index.ts) accept booleans. Use platform-specific guidance rather than assuming all SDKs have identical types.
- **Hosting scope:** Cloud DPA lists Tinybird/AWS, while the self-host recipe uses PostgreSQL/ClickHouse. Cloud regional storage, managed updates, five-year retention and contractual deletion promises are not automatically guarantees for an operator-run installation.
- **No ownership transaction notice found:** searched official-site acquisition/shutdown/sunset references and read home, about, current terms/privacy, server README and repository metadata. Technov Solutions SRL is the current legal operator; an older corporate copyright holder in SDK licence files does not establish an acquisition date or chain.
- **Billing gaps:** searched pricing, its FAQ, docs and subscriptions/trial/refund terms for taxes, annual tariffs, exact trial duration, allowance pooling, cross-region billing, seats, custom cap controls, Debug billing treatment and numeric error-report quotas. These remain not published in the pages checked. Error-report retry guidance is not an event-delivery SLA.
- **Feature and data-quality gaps:** searched docs/about, web and native SDK guides, build modes, the ingestion guide and the docs-linked MCP feature list for account analytics, cohort/path builders, billing connectors, imports, sampling, bots and internal-IP filtering. None was established. Manual purchase or page_view events do not establish native revenue or marketing acquisition reports.
- **Retention and operational gaps:** read privacy, DPA annexes, terms, self-host README/Compose and public settings source for backup geography/purge, per-type retention, cancellation access windows, minimum resources, supported releases and maintenance commitments. No precise answer was established for those gaps. The latest-release API returned HTTP 404, which does not prove absence of all tags/distribution paths.
- **Public API/demo gaps:** docs advertise CSV export and no public query API. The [docs-linked MCP README](https://raw.githubusercontent.com/aptabase/aptabase-mcp/main/README.md) calls itself unofficial and relies on private, cookie-authenticated dashboard endpoints; it is not a supported public query API. Export source is experimental. Home/about/docs did not establish a public no-login interactive demo or complete dashboard language list. No signup, login or endpoint execution was used to fill these gaps.

## Field problems

- **F12/F15/F18:** this is event-based app analytics. A pageview or MAU cannot be priced directly without an explicit scenario. Marketing reports and long-term distinct-user metrics must not be assumed from a web/native SDK.
- **F17:** Session Timeline means an ordered event list. Treating it as session replay would produce misleading recording prices and masking fields.
- **F21/F22:** generic “anonymous,” “no identifiers” and “no cookies” wording needs platform and lifetime detail. The server derives a daily identifier; the extension persists a session ID; account login cookies belong to the developer dashboard. A no-cookie claim is not a legal consent finding.
- **F26/F30:** hosted pricing commitments, self-host source capabilities and an unofficial docs-linked integration are different evidence scopes. Source-level Parquet support or settings are recorded without promising hosted deployment parity.
- **F32/apps.md:** the row is marked active with detection class N. Active status fits the current offer. N is appropriate for native-only use, but a product-wide N misses the browser SDK's conditional signals; propose C for browser deployments and N for native/server-only use. The region/market note is Unknown; the research now separates Romanian operator registration from EU/US analytics storage. No list file was edited.
