- The M/Monit manual PDF is too large for direct extraction by the research browser. Its indexed official manual text shows events set to never delete and analytics set to delete after three years by default. The manual version is 4.3.4 according to the documentation index.
- The setup FAQ suggests SSD storage for SQLite and offers a processor-thread rule of thumb, but neither product publishes a numerical minimum CPU, memory or disk requirement for a defined fleet size.

## Field problems

- Core fields C01–C27, uptime fields U01–U05 and self-host fields H01–H03 were attempted. Monit supports remote service checks, so uptime fields apply even though checks run from the user's own Monit host rather than a vendor probe network.
- Error grouping/source maps/replay, log ingestion and search, APM tracing, hosted status pages, and inbound cron-heartbeat fields do not match Monit's documented product. Program checks can use a cron-like schedule, but Monit is not a missed-job ping receiver.
- M/Monit is paid, but self-hosted. Hosted billing fields were not marked not applicable; unknown plan or quota behavior is recorded as not_published or check_failed.
- The standard M/Monit price selector failed to expose its numeric value, so cost examples use only the published Enterprise amount and label the arithmetic as our calculation.
- No private person's name is included. The operator is named as Tildeslash Ltd., and individual maintainers are not identified.
