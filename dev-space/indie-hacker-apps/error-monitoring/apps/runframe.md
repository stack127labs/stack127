## Conflicts and unknowns

- **Private status pages:** Product pages advertise private pages, while the terms describe public-facing status pages. The public status API is explicitly read-only for public pages. Private-page terms, plan coverage, and access controls remain unresolved.
- **Custom domain on Free:** The homepage says status pages can use a custom domain without extra cost. The plan table lists domain counts on Growth and Scale, but does not expose a Free allowance. I did not assume Free includes a domain.
- **Pricing matrix:** Some plan checkmarks are missing from readable page text. I used explicit summaries and numeric limits only. Push, RSS, maintenance, and some incident feature gates remain unresolved by plan.
- **Scale overages:** Pricing names fair use for subscriber delivery, phone/SMS, API, MCP, and managed AI, but gives no exact fair-use threshold or overage rate.
- **Status page history:** The public page includes uptime bars and an incident API, but its visible history duration is not stated. Workspace retention periods should not be substituted for page-history retention.
- **News and releases:** The official blog is active, with its newest listed article dated 2026-05-31. I found no separate newsroom or changelog in the footer, docs, legal index, or site search; direct `/newsroom`, `/news`, and `/changelog` paths did not return readable pages. The blog's OpsGenie shutdown material concerns OpsGenie, not Runframe.
- **Source check:** Reviewed Runframe pricing, terms, privacy, security, legal/company details, product pages, the docs index, setup guide, incident/on-call/escalation/postmortem guides, integration guides, relevant API references, status page, and blog. No account or test alert was used.
