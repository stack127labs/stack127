## Cost examples

These are **our calculation, estimated**, not quotes. The software's zero license component has no invoice currency. GitHub platform examples keep **USD**; no exchange rate or tax percentage is invented. Domain registration, external email/SMS, paid GitHub plans, private-repository overages, owned-runner hosting, backups and labor are not silently included as zero.

### Fixed one-minute uptime workload

Inputs: **5, 25 or 100 HTTP endpoints**, 60-second interval, one origin, 30 days, one builder, email alerts and one own-domain status page.

`evaluations = endpoints × 30 × 24 × 60 = endpoints × 43,200`

| Endpoints | Required one-origin evaluations/month | Required three-origin evaluations/month | Comparable recurring cost |
| --- | ---: | ---: | --- |
| 5 | 5 × 43,200 = **216,000** | 216,000 × 3 = **648,000** | **Unsupported at the documented one-minute frequency** |
| 25 | 25 × 43,200 = **1,080,000** | 1,080,000 × 3 = **3,240,000** | **Unsupported at the documented one-minute frequency** |
| 100 | 100 × 43,200 = **4,320,000** | 4,320,000 × 3 = **12,960,000** | **Unsupported at the documented one-minute frequency** |

Upptime documents a **five-minute minimum** for scheduled workflows. Buying platform compute or choosing an owned runner does not establish a supported one-minute configuration. External repeated dispatches or a custom persistent loop are not priced as the documented product. The matching workload therefore does not receive a misleading “free” total.

### Partial fit: five-minute uptime

This changes the interval to **300 seconds**, preserving endpoint counts, email alerts, one page and an own domain. It is a separate partial comparison.

`scheduled evaluations/endpoint = 30 × 24 × 60 ÷ 5 = 8,640`

| Endpoints | Nominal evaluations/month, one origin | Software license component | Qualifying public standard-runner compute component | Full recurring total |
| --- | ---: | ---: | ---: | --- |
| 5 | 5 × 8,640 = **43,200** | **0** | **$0 USD** | **Unknown** |
| 25 | 25 × 8,640 = **216,000** | **0** | **$0 USD** | **Unknown** |
| 100 | 100 × 8,640 = **864,000** | **0** | **$0 USD** | **Unknown** |

The zero compute component assumes a **public repository and standard GitHub-hosted Linux runner**, not a larger runner. GitHub's applicable account, repository, API and Pages rules remain. A domain and an email sender/provider must be chosen; Upptime supplies integrations rather than published delivery credits. GitHub terms and Pages limits also apply to business use. A commercial MIT grant is not a waiver of the platform's hosting restrictions.

**Workflow runs are not endpoint evaluations.** One uptime workflow iterates the configured sites. A 30-day five-minute schedule requests **8,640 uptime workflow runs**, with separate response-time, summary, graph, website and update jobs. Billable compute depends on their duration and account usage. Sequential checks, network latency, queues and retries change actual work; scheduled GitHub jobs can be delayed or dropped.

For persistent down/degraded results, the monitor performs up to **three health evaluations** per scheduled site check, separated by two- and ten-second waits. Local HTTP has another inner transient-error loop allowing three total curl attempts. In an all-transient-failure path, up to **3 × 3 = 9 HTTP attempts** can occur per scheduled evaluation; normal successful checks do not automatically cost nine requests. The workload counts above are baseline nominal evaluations, not measured physical requests. Retry runtime can increase a private-runner bill.

### Private-repository and owned-runner cost

Upptime's setup guide estimates approximately **3,000 build minutes/month in the default setup**. It does not benchmark 5, 25 and 100 targets. The estimate is not multiplied by endpoint count or treated as a guaranteed monthly invoice.

Current GitHub billing lists **$12 USD included monthly compute on GitHub Free**, shared with other eligible usage. Its standard Linux example is **$0.006 USD/minute**. For an **illustrative assumed 3,000 chargeable Linux minutes**, with the full $12 allowance available:

`compute value = 3,000 × $0.006 = $18 USD`

`estimated extra compute = max(0, $18 − $12) = $6 USD/month`

This is an example of the platform formula, **not a priced 5/25/100-endpoint Upptime workload**. Other account consumption, storage, runner type, budget enforcement, paid account requirements and taxes can change the total. For an owned Linux runner:

`estimated operating total = 0 software license + runner compute + storage/backup + network/domain + email/SMS supplier`

Exact total is **unknown**. Official Upptime docs do not provide workload-qualified server sizing, and no host or external sender was selected. The platform's free treatment of self-hosted-runner usage does not make the underlying machine free. Labor is excluded.
