## Scope and evidence

Attempted 34 distinct field IDs: all 27 core fields, four error fields and three logging fields. Logging is included because it stores the underlying error records and can create the bill, even for direct Error Reporting API calls. This is not research into all Google Cloud Observability products. Cloud Monitoring uptime/synthetic checks, Cloud Trace, Cloud Profiler, customer status pages and job scheduling are separate jobs; their field groups and cost scenarios are outside this product's established scope. No complete self-hostable Error Reporting backend was established.

Read the official documentation index, setup and language guides, grouping, error management, notifications, payload/API references, quotas, pricing, cost-control guides, service terms, Cloud Data Processing Addendum, Cloud Privacy Notice and subprocessor policy. Followed the pricing link into the shared Observability rate card and its Logging rules. Read the official client source/license linked by the Node.js guide. Its standalone repository announces a move; that is not a product shutdown.

Every table row carries the requested evidence shape and a note explaining its scope. Multiple source-update dates follow URL order. Dates are UTC. “Not stated” means no update label was established for that source; it is not the research date. Legal dates were checked against their full-page version labels. Only the owner's six states are used. not_published is bounded by the named checked sources, not a claim of universal absence. Failed guessed URL paths were replaced by the actual documented methods; recovered retrievals are not counted as failed fields. ## Cost examples — our calculation, estimated

Use recurring public list rates, not the temporary US$300 trial credit. Price-list guidance names USD; an actual billing account can be charged in a supported local currency. No currency conversion is made here. Taxes, paid technical support, compute, external destinations, existing unrelated logs and optional AI features are excluded. Error Reporting itself has no separate charge.

### Errors: one builder, three apps, 30 days

Inputs: 5,000 / 50,000 / 500,000 reports per month; three applications represented as three services in one project; one builder with the needed IAM permissions; 30 days of underlying error-log detail; no paid replay or AI extras.

Additional assumptions needed for a number: each generated stored log entry is exactly **1 KiB of billable pre-index size**, one entry/report, one stored copy in a chargeable log bucket, no other chargeable logs in that project, and no existing consumption of the 50-GiB monthly allowance. This is a modelling assumption, not a measured average or the SDK's advertised event size.

Formula:

- Stored GiB = reports × 1,024 bytes ÷ 1,073,741,824 bytes/GiB.
- Chargeable GiB = max(0, stored GiB − 50).
- Monthly model cost = US$0 Error Reporting fee + chargeable GiB × US$0.50/GiB.
- No extra retention charge at the default 30-day raw-log retention.

| Reports/month | Assumed entry size | Stored GiB, rounded to nine decimal places | Chargeable GiB after unused allowance | Estimated monthly model cost |
| --- | --- | --- | --- | --- |
| 5,000 | 1 KiB | 0.004768372 | 0 | US$0 |
| 50,000 | 1 KiB | 0.047683716 | 0 | US$0 |
| 500,000 | 1 KiB | 0.476837158 | 0 | US$0 |

These are conditional model totals. **An exact bill cannot be determined from error counts alone.** Actual pre-index stored-entry size includes the entry, not just a short error message. Other application/platform logs share the free allowance. Multiple stored copies can create multiple charges.

Retention compatibility also needs qualification. Error Reporting retains information for 30 days, but samples events and extrapolates counts. It is not a guaranteed full-fidelity list of all 500,000 occurrences. Store the underlying logs for 30 days to inspect ingested occurrences through Logging. The 10,000 deployment/group-pair cap can evict Error Reporting data earlier; report bursts must remain within API limits. These limits are not removed by a US$0 model.

The model assumes normal eligible routing and no exclusions that drop the evidence. Three app services do not require buying three Error Reporting plans. It does not assume creating extra projects to multiply free allowances; service terms prohibit artificial resource/account splitting to circumvent fees or quotas.

## Conflicts and unknowns

No unresolved direct source contradiction was established. Several apparent conflicts resolve only when collection path, data class or product boundary is kept explicit:

- **Free service versus generated bill:** the Error Reporting fee is zero, while direct reports generate Logging records. The shared rate card and setup guide both disclose possible Logging charges. No count-only exact total or separate paid Error Reporting plan should be invented. Sources: https://cloud.google.com/products/observability/pricing ; https://docs.cloud.google.com/error-reporting/docs/setup .
- **CMEK:** overview/setup prohibit automatic analysis of CMEK-protected log buckets. Node.js/Python setup guides explicitly describe direct client reporting even when application log buckets use CMEK. This is a path distinction; it does not promise that the separate Error Reporting record inherits those encryption or residency controls. Sources: https://docs.cloud.google.com/error-reporting/docs/setup ; https://docs.cloud.google.com/error-reporting/docs/setup/nodejs ; https://docs.cloud.google.com/error-reporting/docs/setup/python .
- **Regional labels versus a global service:** log buckets can be regional and the console groups errors by that region. The overview explicitly says error groups can be accessed from any region and this is not configurable. Regional-looking endpoint selectors are not a residency promise. - **Cross-project routing:** routing through a destination project that stores logs in its own bucket satisfies the documented pattern. A direct sink from the source to another project's bucket does not establish the same analysis behavior in the source project. Sources: https://docs.cloud.google.com/error-reporting/docs/setup ; https://docs.cloud.google.com/error-reporting/docs/troubleshooting ; https://docs.cloud.google.com/logging/docs/routing/overview .

Scope/window is not precise enough to convert these into a complete guaranteed per-group event history. Logs Explorer is the documented route to the underlying ingested records.
