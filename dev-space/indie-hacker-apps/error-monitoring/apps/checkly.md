## Field problems

- **C11/U03 need separate meter types.** A scheduled URL uptime monitor is count-billed, an API synthetic run is execution-billed, a Multistep chain counts requests, and a native suite counts thirty-second blocks. Putting all under “checks” produces the wrong price.
- **C11 scenarios need explicit compatibility.** The uptime scenario's thirty-day month does not demand thirty-day raw retention; browser scenario does not specify raw history. Heartbeat start/success and general-traffic APM scenarios are not equivalent to the documented products.
- **C11/S01 module coupling is not fully specified publicly.** Detect and Communicate are presented separately with add-on language. Status-only examples show the add-on subtotal and state the assumed free base, rather than pretending purchase eligibility was tested.
- **C14 and S03 describe different histories.** Raw results, aggregate metrics, ninety-day component uptime and an incident archive are not interchangeable retention periods.
- **C06/H scope needs component separation.** Apache-licensed CLI and customer-operated probes do not establish a fully self-hostable backend; H running-cost estimates are therefore not invented.
- **C23 DPA destination is ambiguous.** A contractual reference to a privacy URL does not itself expose a processing agreement with annexes. This remains an evidence gap, not a legal conclusion.
- **States differ from fields.md.** This file uses only the six user-approved states. Calculations use confirmed arithmetic with “our calculation, estimated,” not a seventh derived state. not_published means absent from the named checked sources, never a universal absence claim.
- **Optional context stays bounded.** Rocky paid invocation tiers are included only to explain module costs; no unrelated AI feature inventory is added.
