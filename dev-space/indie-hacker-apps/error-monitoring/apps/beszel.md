**Lifecycle and ownership check:** The project is active. The latest published release is `v0.21.1`, dated 2026-10-22. I checked the official release list, project repository, official site and its blog route for shutdown, sunset, or acquisition notices; I found none. The public project is presented under an individual maintainer account, with no company or maintainer country published. No personal name is included here.

**Scope:** This record covers the free, self-hosted Beszel Hub and Agent. The Hub stores data and serves the dashboard; an Agent runs on each monitored system. Beszel has no vendor-hosted plan listed on its official site or docs. Its network monitors are checks run by its own Agents, not a global vendor probe service. The optional heartbeat sends Beszel's state outward to another monitor; Beszel does not receive job pings.

**License:** The Beszel project is MIT licensed. The Hub and Agent are open-source software; hosting, backups, operating-system services, and any notification-provider fees belong to the operator.

## Cost examples

Beszel publishes no hosted plan or usage rate, so the hosted error, uptime, and log cost scenarios do not apply. H02 contains **our calculation** for one Agent on an existing host with spare capacity: $0/month license + $0/month new host = **$0/month incremental cost**. This is not the total cost of a new monitoring deployment. The Hub host, storage, backup destination, notification provider, and operator time may add cost; Beszel does not publish sizing sufficient to price a typical new deployment.

## Conflicts and unknowns

- The official project documentation identifies a self-hosted Hub and Agent. I found no vendor-hosted plan or hosted pricing page, so hosted billing fields are not applicable to this edition.
- The current release page shows `v0.21.1` dated 2026-10-22. The v0.21.0 notes list TLS expiry checks for HTTPS monitors, while the current network-monitor page covers protocol behavior; I used the release note for the feature's introduction and the current guide for its operation.
- Metrics retention comes from the current project source code, not a marketing page. The official network-monitor guide and deletion code checked do not state a separate network-history retention duration.
- `/blog`, `/newsroom`, `/privacy`, and `/terms` were tried. The blog and policy routes could not be retrieved, and the official site navigation did not expose a newsroom. Current releases, the repository, and docs were checked as alternatives. A failed route is not treated as proof that a legal page does not exist elsewhere.
- No numerical minimum host profile, maximum user/system count, service-log redaction control, or formal LTS/security-fix window was published in the official pages checked.

## Field problems

- C09–C11 and C13 describe vendor-hosted trials, paid plans, usage prices, and bill controls. They are not applicable to the self-hosted edition. H02 remains applicable because operators still pay for infrastructure.
- The product's primary type is server and container monitoring. U01–U05 apply because Agents can run endpoint probes. Error-tracker, log-ingestion, APM, status-page, and inbound cron-heartbeat groups do not fit its documented scope. The optional outbound heartbeat monitors Beszel through another service; it does not turn Beszel into a job-ping receiver.
- C22 still applies to systemd service logs: the docs warn that all users who can view a system can read those logs, and the documented control is to disable log serving.
- The public GitHub namespace is used in exact source URLs for the repository, license, releases, and code. The file does not name the individual maintainer.
