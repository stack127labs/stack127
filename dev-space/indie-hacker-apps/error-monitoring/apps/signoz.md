## Cost examples: our calculation, estimated, not quoted

All examples use **USD**, one builder, one Cloud workspace and monthly billing. They exclude tax, startup discounts, extra workspaces, customer collector infrastructure and external archives. No currency conversion or trial credit is used.

The pricing page's public calculator supplies these rates:

| Signal | Retention | Rate |
| --- | --- | --- |
| Logs or traces | 15 days | USD 0.30/ingested GB |
| Logs or traces | 30 days | USD 0.40/ingested GB |
| Logs or traces | 90 / 180 / 365 days | USD 0.60 / 0.80 / 1.40 per ingested GB |
| Metrics | 1 / 3 / 6 / 13 months | USD 0.10 / 0.12 / 0.15 / 0.18 per million samples |

**Formula:** `monthly Teams total = max(USD 49, log usage + trace usage + metric usage)`.

The included USD 49 is shared monetary usage across these signals. It is not 163 GB free for each signal in addition to the subscription. Sources: https://signoz.io/pricing/ ; https://signoz.io/_next/static/immutable/chunks/1u-jarru9v-1j.js ; https://signoz.io/docs/metrics-management/reducing-costs/ (checked 2026-11-05; source dates in the table/inventory).

### Errors: 5,000 / 50,000 / 500,000 reports

Inputs: three apps in one workspace, one builder, **30 days of error detail**, no replay or AI extras.

**Exact totals remain unknown at all three report counts.** SigNoz builds the Exceptions view from recorded trace span events. A report count supplies neither span count nor ingested trace bytes. At 30-day trace retention, the known expression is:

`max(49, trace GB × 0.40 + any other billed telemetry)`.

Do not assume one report equals one GB-priced unit, or invent an average stack size. Stack detail exists only when the instrumentation recorded it; sampling can remove the event and related request. Logs emitted under newer log-only exception conventions do not automatically populate the Exceptions view. Sources: https://signoz.io/docs/userguide/exceptions/ ; https://signoz.io/docs/cost-control/optimize-traces/ ; https://signoz.io/pricing/ ; https://signoz.io/_next/static/immutable/chunks/1u-jarru9v-1j.js (checked 2026-11-05; source dates in the table/inventory).

Community has no software-license fee. Its 30-day retention must be configured and provisioned with enough storage. The conflicting seven/15-day default documentation is not relied on to meet this condition. Source: https://raw.githubusercontent.com/SigNoz/signoz/v0.149.0/LICENSE ; https://signoz.io/docs/userguide/retention-period/ ; https://signoz.io/docs/install/docker/ (checked 2026-11-05; source dates in the table/inventory).

### Metric samples and combined usage

Metrics use **samples**, not series count alone. For example, 10,000 ordinary series exporting twice/minute over 30 days produce:

`10,000 × 2 × 43,200 = 864,000,000 samples`.

At one-month retention: `864 × USD 0.10 = USD 86.40`; with no other usage, `max(49, 86.40) = USD 86.40/month`. This is our calculation, not USD 135.40. Histograms/summaries can produce multiple samples per point. Sources: https://signoz.io/pricing/ ; https://signoz.io/docs/metrics-management/reducing-costs/ (checked 2026-11-05; source dates in the table/inventory).

For a combined illustration, **100 GB 30-day logs + 50 GB 15-day traces** cost `40 + 15 = USD 55`, so the assumed one-workspace total is **USD 55/month**. Do not add another USD 49. Sources: https://signoz.io/pricing/ ; https://signoz.io/_next/static/immutable/chunks/1u-jarru9v-1j.js (checked 2026-11-05; source dates in the table/inventory).

## Conflicts and unknowns

- **Self-host retention:** The newer retention guide says 15 days for logs/traces; Docker installation says seven. Both say 30 days for metrics. Preserve both until checking the deployed Workspace settings. Sources: https://signoz.io/docs/userguide/retention-period/ ; https://signoz.io/docs/install/docker/ (checked 2026-11-05; source dates in the table/inventory).
- **Installation/upgrade guidance:** Current Docker docs and migration file use Foundry and deprecate bundled deploy/ files. The generic standard-upgrade page still contains the older git/Compose flow. Use the current installation/migration and required-stop guidance for the chosen deployment. Sources: https://signoz.io/docs/install/docker/ ; https://raw.githubusercontent.com/SigNoz/signoz/main/deploy/MIGRATION.md ; https://signoz.io/docs/operate/migration/upgrade-standard/ ; https://signoz.io/docs/operate/upgrade/ (checked 2026-11-05; source dates in the table/inventory).
