## Cost examples

These are **our calculation, estimated**, not an Errbit quote or a measured host requirement. The comparable error workloads are 5,000 / 50,000 / 500,000 notices per month, with one builder, three applications and at least 30 days of error detail. Replay and optional AI are excluded. No currency conversion is used.

The MIT software grant has no license fee. The license does not name a currency or a per-report billing rate. The license component is therefore recorded as zero, without relabelling it as a quoted USD subscription. Official source, checked 2026-11-04: https://github.com/errbit/errbit/blob/v0.11.6/LICENSE.

A complete monthly operating total would require:

`total(N) = software license fee (0) + Errbit app hosting(N, burst rate) + MongoDB compute/storage(N, record size, indexes) + backups + network/egress + email/notification delivery + allocated domain/TLS costs + any paid operations/support`.

The formula names cost inputs, not extra Errbit charges. Some components may already be available to an owner; that does not make a new deployment free by default. Labor and incident recovery are excluded from any future infrastructure-only estimate and should be stated separately.

| Scenario | Inputs held constant | Known software component: our calculation, estimated | Full monthly result | What blocks a reliable total |
| --- | --- | --- | --- | --- |
| Small | 5,000 notices/month; 1 builder; 3 apps; 30-day detail | License fee = 0 | Unknown | No official CPU/RAM/database sizing for this load; stored report size, bursts, backup requirements and provider choice are unspecified. |
| Growing | 50,000 notices/month; same user/app/history inputs | License fee = 0 | Unknown | The same missing sizing inputs apply. A monthly count is not a peak requests-per-second budget. |
| Busy | 500,000 notices/month; same user/app/history inputs | License fee = 0 | Unknown | No release-matched capacity benchmark or reference deployment at this workload was established. Storage/index/backup and incident-email volumes remain unknown. |

A future storage estimate needs the actual average stored notice footprint, shared backtrace behavior, problem metadata, indexes and backups. The 1,000-byte message cap is only one field's limit; it does not mean a whole error costs 1 KB. It cannot safely convert the three workloads into required disk space.

Three apps can be represented by separate app records and keys. No per-app or per-seat license fee was found. Actual supported counts at a chosen resource size are not published. Setting 30-day cleanup does not create an automatic 30-day event TTL: clear_outdated works on a problem's last occurrence. To retain at least 30 days of detail, an owner must avoid earlier resolved-problem deletion and verify their own cleanup/backup policy.

There is no software annual-billing saving to calculate. ## Field problems

- **C07–C11 need edition-aware wording.** A free software license is an ongoing right, not a hosted free-plan allowance or a free operating bill. Subscription trial, paid-tier and annual-payment fields are not applicable to this edition. H02 carries the separate infrastructure-cost question.
- **C12/C14 need source-level detail here.** The project has no priced report quota in the researched paths. It still truncates the stored message field, filters old versions and requires owner-run cleanup. Problem-level age is different from a rolling event-retention window.
- **C15 needs access scope as well as counts.** Watchers are notification recipients. The reviewed app policy scopes applications to all and app editing to admins; a separate watcher list is not evidence of isolated multi-tenant access.
- **C20/E01/E04 cannot inherit the full client protocol.** Airbrake compatibility is narrowed by the actual parser and setup flags. The parser consumes the first error and maps selected fields. Hosted Airbrake pricing, APM, jobs, code-hunks and replay are not Errbit facts.
- **C21/H03 need a distinction between export, storage and recovery.** Owning MongoDB is useful, but the read API is a summary interface. A persistent database volume is not a backup, and deleting visible problems does not prove every shared record or copy was removed.
- **H01/H02 allow honest unknowns.** No public resource/capacity sizing was established. Choosing a VPS and calling it sufficient would add false precision, so all full operating totals remain unknown.
- **Evidence states follow the owner's override.** Only confirmed, not_published, unclear, conflicting, not_applicable and check_failed are used. Cost arithmetic is labelled our calculation, estimated instead of introducing a derived state.
- **apps.md:** active/error/self-host/open-source description fits. Maintainer home region remains unknown. No row error was found and no source-list file was edited.
