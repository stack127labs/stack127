## Conflicts and unknowns

Every URL below was checked 2026-11-04. These are bounded public-source gaps, not proof the vendor never supplies the answer.

- **Free commercial eligibility, C08:** https://betterstack.com/pricing/ labels Free for personal projects; https://betterstack.com/community/comparisons/uptime-robot-alternatives/ explicitly says commercial projects can use it. Current terms https://betterstack.com/terms do not settle the plan-specific distinction. Keep commercial Free unresolved.
- **Monitor arithmetic, C07/C26:** rate card sells additional blocks of 50 monitors, but https://betterstack.com/community/comparisons/better-stack-vs-hyperping/ calls USD 21 per 50 equivalent to USD 0.21 per monitor and prices 100 monitors with a single USD 21 block. That unit division is wrong: 21/50 = 0.42. https://betterstack.com/community/comparisons/better-stack-vs-uptimerobot/ instead uses two blocks for 100 monitors. Our monthly count estimate uses ceil((N−10)/50) and the current monthly block rate, not the comparison's incorrect unit rate.
- **UDP, U01:** https://betterstack.com/community/comparisons/better-stack-vs-uptimerobot/ says Better Stack lacks UDP. Current https://betterstack.com/docs/uptime/api/create-a-new-monitor/ and https://betterstack.com/pricing/ explicitly include it. Use current API capability; exact entitlement still requires account-specific confirmation.
- **Browser meter, C11:** https://betterstack.com/community/comparisons/transaction-monitoring-tools/ says USD 4 per 10,000 executions. Current pricing meters Playwright minutes. No conversion without runtime and rounding rules. https://betterstack.com/docs/uptime/playwright-monitor/ documents setup, not complete billing semantics.
- **Regions, C23:** https://betterstack.com/community/blog/changelog-9-advanced-data-options-for-everyone/ lists US East, US West, Germany, Singapore. https://betterstack.com/docs/logs/api/create-a-source/?format=markdown lists us_west, germany, singapore for most plans. Region-specific availability needs checking for the chosen source/account. The DPA https://betterstack.com/dpa permits international processing/transfers. Probe regions are not storage regions.
- **Status plan vocabulary, S02:** https://betterstack.com/docs/uptime/creating-status-report-and-status-update/ refers to Small Team and onward for subscriber notification, while current rate card uses responders and add-ons. https://betterstack.com/docs/uptime/subscribing-to-status-updates/ explains delivery but not an exact current entitlement matrix. Ten components/page, subscriber allowance scope, and public history duration were not established from these pages and https://betterstack.com/demos/status-page/.
- **Refund/evaluation, C09:** pricing advertises a 60-day money-back guarantee, but https://betterstack.com/terms says no general refund obligation on access termination. Do not interpret a conditional guarantee as an unconditional refund right or free trial. Trial-specific card/expiry/automatic-payment rules not established.
- **Telemetry costs, C11/L01/L03:** checked pricing, ingest API, source/collector API, metrics-billing guide, own-bucket guide and Query boost guide. Found published GB rates and control behavior, not a complete log/trace byte-billing definition, compression factor or storage-size function for our workloads. Metrics guide explicitly uses retained uncompressed database bytes and legacy pre-2026 billing can differ. Do not apply metrics' byte definition automatically to logs/traces.
- **Spending limits, C12/C13:** https://betterstack.com/community/blog/200x-cheaper/ describes alerts and forthcoming cap; current log HTTP API confirms HTTP 402 for spend limits. Error spike protection is documented at https://betterstack.com/docs/errors/using-the-product/spike-protection/. - **Job signals, J01/J02:** https://betterstack.com/community/comparisons/better-stack-vs-healthchecks-io/ claims start pings and cron syntax. Setup and create API establish completion, explicit fail, interval/grace, and timezone support, but not the concrete start signal/duration protocol or full cron-expression field. Do not publish our required start-plus-success scenario as verified.
