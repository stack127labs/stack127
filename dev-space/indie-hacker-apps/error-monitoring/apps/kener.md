Kener is free, MIT-licensed status-page and uptime-monitoring software that you run yourself. It can run checks from the machine where you deploy it, publish one or more status pages, manage incidents and maintenance, and notify subscribers. Kener.ing is a public demo/example, not a documented managed hosting plan. You choose and pay for the server, database, Redis, backups and email provider.

## Conflicts and unknowns

- GitHub’s releases index showed v4.1.10, but the direct v4.1.11 release page is marked “Latest” and dated November 2, 2026. The direct release page and docs changelog index support v4.1.11.
- The landing/docs headline says 11 monitor types; the detailed v4 overview lists 12, including Group and Prometheus monitors.
- The v4.1.9 security changelog says v4.0.0 through v4.1.8 allowed an encoded-path request to reach protected API routes without a key. v4.1.9 fixes it; the advisory says to review logs and rotate exposed secrets when relevant. v4.1.11 includes additional secret masking and dependency fixes.
- The v4.0.0 migration guide says Redis became required, the API changed, heartbeat routes changed, v3 subscriptions do not migrate automatically, and existing monitors must be assigned to pages. It also calls for site-image re-upload and checking old timeout values.
- I tried the official pricing, blog, newsroom, Terms and Privacy paths. No hosted price sheet, SaaS policy or separate company newsroom was readable. I used the v4 docs changelogs and GitHub releases for project updates.
- The self-host guides describe configurable monitor-data retention and indefinite maintenance-event retention, but incident database retention and full backup/restore procedures are not stated in the pages checked.
