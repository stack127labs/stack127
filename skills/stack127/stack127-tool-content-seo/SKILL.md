# stack127 tool content and SEO

Plan only the content needed to use, understand, and verify the working tool. Read the actual interface, `stack127_docs/tool-pages.md`, the visual-first guidance, SEO rules, and the shared writing voice.

Update the `Public content` section of `content_docs/<slug>/tool-spec.md`. Do not create a separate writing plan for new work. Preserve historical plans for existing tools.

Record:

- the primary query and immediate answer;
- the meaningful input choices users need help with;
- how to read the lead answer and supporting evidence;
- concepts, syntax, ordering, or uncertainty that commonly cause mistakes;
- what the tool does not calculate, inspect, prove, or guarantee;
- privacy or data handling when it materially affects use;
- the next real verification step and useful internal links;
- the best medium for each explanation.

Keep the tool first. Do not repeat result narration, ordinary button instructions, keyword variants, an FAQ by default, or methodology filler. Use a table for repeated facts, an exact chart for quantitative comparison, marker art only for a concept, and prose for connected judgment or limits.

Mark the plan ready when a writer can produce concise public words without reopening technical or interface decisions.
