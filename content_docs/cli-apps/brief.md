# Brief: cli-apps

## Who is here

A developer or terminal power user is looking for a tool to run in their terminal: a TUI app, a shell, a prompt, a CLI for work, or an AI agent. They may not know the exact name yet, and they care about platform support, install method, price, license, and whether anyone still maintains it.

## The job

They should narrow the directory with filters or search, compare candidates as structured facts on cards, and reach the official website, repository, or documentation without guessing which facts were verified.

## Show vs say

Filters and the card grid do all discovery work. Repeated facts (type, platforms, install method, pricing, source model, license, maintenance) stay structured on cards and in the full-records block; they are never compared in paragraphs. The one accent mark in the h1 names the page. Unknown values render as "unknown" so unverified facts are visible, not hidden. Sentences exist only to say what the directory includes and that open and closed tools both belong here. There is no article section: this page is a directory, not an essay about command-line software.
