# Brief: Home

## Who is here

A solo builder, indie hacker, content creator, or tech tinkerer has landed without a specific tool in mind, or has heard about stack127 and wants to see what is available. They may be exploring a project, solving a work problem, or learning something new. They should not need a homelab background to understand the site.

## The job

They should identify a useful resource for their current task and reach it in one click. The opening uses the line, "A toolbox and reference hub for indie hackers," followed by a short description of the site's free tools, calculators, directories, and reference data. Start here offers existing paths into domain tools, CLI apps, keyboard shortcuts, and the self-hosting course.

## Show vs say

Keep the current layout and generated artwork. Use a short introduction and existing published links. Describe the broader audience without presenting future paid tools, ads, or topic landing pages as available.

List every published tool catalog first, then the published top-level software directories, hardware directories, and reference pages. Keep the course and Labs collection. Do not feature individual tools or individual shortcut reference sheets. Publication still comes from the central registry, not this navigation list. Catalog order comes from `stack127_tool_catalogs.home_order`.

Every card has a meaningful count from the same data used by its destination. Count apps, devices, coordinators, UPS models, cameras, tools, licenses, status codes, domain extensions, lessons, or projects as appropriate. Domain tools and references have separate counts. Keep the existing card layout. Every featured page needs its own generated marker spot. A missing spot is an error, never a reason to enlarge the title's interface icon.

The sidebar and linked card sections are the product map. Catalog cards come from the catalog table and use a shared component. The other resource cards follow in their own section. Each card uses one marker drawing to signal the subject, a short description to set scope, and a live count only when the repository or database can provide it. The dotted opening uses two stacked app windows with one chartreuse terminal prompt, matching the site's software and tools. This corner drawing has no labels, branching connectors, or extra symbols and stays hidden on narrow screens. The opening needs only one sentence to define the territory. The small Start here list carries the few recommendations that require words rather than another card.
