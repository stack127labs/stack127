# Edge cases and tests: `.dockerignore` Pattern Tester

Status: ready
Tool: `.dockerignore` Pattern Tester
Route: `/dockerignore-tester`
Depends on: `competitive-report.md`, `implementation-report.md`, `brief.md`

## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | The tool disagrees with pinned Moby behavior, reports an excluded path as included, leaves a plausible stale or partial result, leaks pasted project data, executes untrusted text, or makes testing inaccessible. |
| P1 | A common validation, recovery, action, state-cleanup, narrow-layout, provenance, copy, or publication boundary fails without materially changing the matcher truth. |
| P2 | An uncommon resilience or presentation issue exists while the verdict, privacy boundary, recovery path, and primary action remain correct. |

The central hazard is false confidence. `Included` and `Excluded` are the only verdicts and must be treated as exact outcomes under contract `moby-patternmatcher-v0.6.1-linux-slash`, not as generic-glob approximations and not as security guarantees. Matcher parity, all-or-nothing validation, correct inherited parent-result tracing, successful current BuildKit verification, and local-only handling are release gates.
