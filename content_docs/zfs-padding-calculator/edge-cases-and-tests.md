## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | The calculator displays materially wrong sector or byte counts, presents a stale result as current, restores foreign or hostile shared state, leaks inputs, regresses the existing ZFS pool formula, or makes calculation inaccessible. |
| P1 | A common input, submit, recovery, share, reset, keyboard, responsive, theme, or publication-state flow fails while the underlying formula remains intact. |
| P2 | An uncommon presentation, resilience, or scanability defect does not change the answer and leaves a clear recovery path. |

Matrix/property invariants, applied to every supported tuple:

- `dataColumns = N - P` and is positive after validation.
- `logicalSectors = ceil(L / S)` and `roundedDataBytes = logicalSectors × S >= L`.
- `parityRows = ceil(logicalSectors / dataColumns)` and `paritySectors = P × parityRows`.
- `allocatedSectors >= rawSectors` and `allocatedSectors mod (P + 1) = 0`.
- `0 <= paddingSectors < P + 1`.
- `physicalBytes = L + sectorRoundingBytes + parityBytes + paddingBytes`.
- `overheadBytes = physicalBytes - L`, `0 < efficiencyBasisPoints <= 10000`, and multiplier is at least `1000000` millionths.
- Changing only workload terminology cannot change a result when the selected byte size is valid in both modes.
- Repeating a calculation yields a deeply equal immutable result; comparison order and input order are deterministic.
