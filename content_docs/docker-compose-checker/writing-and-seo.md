## Search intent

The in-app Browser reported `No browser is available`, so the Bing probe ran with standalone Playwright CLI in headless Chromium at 1280 x 900 after the normal sandbox browser launch failed. The web connector's exact-query results included CodeTidy, Deftools, PureDevTools, YAML Config Validator Pro, Yoryantra, and generic YAML validators. These pages use paste fields, explicit validation, line or path findings, and small service summaries. The same results also put Docker documentation near the top. The Bing exact and long-tail probes returned mostly Docker home and documentation pages rather than a clean direct-tool set. This is current result-shape evidence, not a ranking or traffic claim.

### Intent not targeted

- Docker installation or engine setup: the page assumes the reader has a Compose file and sends setup questions to the self-hosting course.
- Full multi-file validation, override merging, profile activation, or generated Compose output: v1 accepts one pasted file and marks `include` and `extends` as incomplete.
- Image, Dockerfile, registry, bind-mount, host-port, runtime, or security verification: those require project files, a host, a Docker Engine, or a separate security workflow.
- A generic YAML tutorial, Dockerfile linter, Compose file generator, or CI action: these are adjacent jobs and would dilute the source-location answer.

## Page promise

The page should promise a browser-local check of one pasted Compose YAML document and optional interpolation values, with separate YAML, Compose-model, and static-advisory findings, source locations when available, stable codes, and a compact normalized summary. The promise must also state the boundary: no upload, no code execution, no file or Docker access, no automatic `include` or `extends` resolution, and no runtime or security guarantee.

Reading flow: The H1 introduction identifies the preflight problem and cues the tool. The result UI supplies the answer and exact repair evidence. The guide then explains what the two inputs represent, why interpolation and service environment are separate, how references, ports, profiles, healthchecks, and advisories should be read, why `version`, `include`, and `extends` affect completeness, and what `docker compose config` must verify in the real project.

## Formula explanation

This is a resolution tool, not a numeric calculator. The writer should explain the validation order and evidence path rather than inventing a formula or a percentage score.

| Concept | What the reader needs | Presentation | Example or source | Caveat placement |
