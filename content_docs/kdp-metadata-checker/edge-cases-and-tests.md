## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | A wrong status, unsafe preview, privacy leak, false KDP verdict, or inaccessible primary check could cause an author to submit bad metadata or expose private copy. |
| P1 | A common check, recovery path, browser state, result snapshot, or important accessibility behavior fails. |
| P2 | An uncommon resilience, layout, or presentation issue makes the local check harder to use without changing its answer. |

The main risk is false confidence. A clean local result must remain a bounded rule check, and a warning must remain a review prompt. The second risk is changing or exposing source text. The engine and client must preserve the submitted strings, keep the preview non-executable, and perform no metadata network or storage operation.

## Formula or resolution fixtures

This is a resolution contract because the engine resolves input shape, normalization, parser findings, heuristic prompts, status, counts, and preview tokens into one local result. The official KDP pages define the documented boundaries. The implementation report defines the local normalization and precedence rules. Fixtures must assert exact fields, severity, status, and ordering where stated, not only that a generic warning exists.
