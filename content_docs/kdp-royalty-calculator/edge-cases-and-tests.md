## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | A wrong cost, rate, floor, royalty, target count, or fallback could cause an author to price a book from false economics. A privacy leak, stale result, or inaccessible primary answer also belongs here. |
| P1 | A common format change, invalid-input recovery, keyboard flow, copy action, responsive layout, publication check, or state transition fails while the engine's answer remains otherwise correct. |
| P2 | An uncommon rendering, resilience, wording, theme, or performance issue makes a correct result harder to inspect without changing the calculation. |

## Formula or resolution fixtures

This is a formula contract. The primary oracles are the versioned implementation report and the official KDP pages for [paperback costs](https://kdp.amazon.com/en_US/help/topic/G201834340), [print royalties](https://kdp.amazon.com/en_US/help/topic/G201834330), [hardcover costs](https://kdp.amazon.com/en_US/help/topic/GHT976ZKSKUXBB6H), [eBook pricing](https://kdp.amazon.com/en_US/help/topic/G200634560), and [eBook delivery](https://kdp.amazon.com/en_US/help/topic/G200634500). All money expectations below are integer cents unless marked as a display string.

## Test plan

- tests/pages/kdp-royalty-calculator/kdp-royalty-calculator.test.mjs: add table-driven tests for EC-003 through EC-016 and EC-033. - tests/pages/kdp-royalty-calculator/kdp-royalty-calculator.test.mjs: assert that invalid input always returns status invalid, values null, and no plausible partial economics. Assert that valid comparison rows are sorted, unique, within the active price range, and independently recalculated.

## Test data and mocks

- Use a fixed formula version kdp-us-amazon-com-2026-09-16-v1, source date 2026-09-16, and the official KDP URLs in the implementation report. Do not use the current date or live price scraping in assertions.
- Keep fixtures grouped by branch: regular and large paperback, each paperback profile, regular and large hardcover, eBook delivery, eBook floors, print threshold, floor solver, target math, invalid states, and formatted output. Give every fixture a stable FF ID or EC ID.
- Use the exact trim and page-limit catalog from lib/kdp/specs.ts, including 5x8, 6x9, 6.14x9.21, 8.25x11, 8.27x11.69, and 8.5x11 edge cases. Do not invent unsupported trims or profiles.
- Browser tests should mock only clipboard permission and deterministic local failure seams. They must fail if the page calls fetch, writes storage, changes history, sends analytics, or fetches pricing rules.
- Use long values $250.00, $200.00, $1,000,000.00, 650 MB, and the longest supported labels. Use malicious strings such as <img src=x onerror=alert(1)>, javascript:alert(1), __proto__, control characters, and oversized decimal text only in browser injection checks.
- Do not mock Amazon responses because v1 has no upstream request. A source-data failure fixture must remove or mismatch local versioned constants and assert a closed failure, not a guessed answer.
- Clipboard success must capture the exact text written. Clipboard failure must reject the write or omit the API. Reset and refresh tests must inspect localStorage, sessionStorage, cookies, URL, history, and analytics spies after every state transition.
