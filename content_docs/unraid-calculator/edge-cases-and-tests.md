## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | A materially wrong data-capacity or parity result, an invalid array presented as valid, a lost explicit role or dependency, a plausible stale result, unsafe shared state, private topology leakage, or an inaccessible primary calculation. |
| P1 | A common input, submission, recovery, history, sharing, keyboard, responsive, theme, or performance flow fails while the core formula remains correct. |
| P2 | Uncommon presentation, copy fallback, long-value, motion, or visual-density polish issue that leaves the answer and recovery intact. |

Every P0 and P1 case below has an automated owner. Manual review supplements hierarchy, clipping, density, and two-second comprehension; it is not the sole proof for a P0 or P1 case.

## Formula or resolution fixtures

The implementation report is a formula contract. These fixtures use literal `bigint` byte oracles, not formatted UI strings. The role and parity rules are derived from the [Unraid array overview](https://docs.unraid.net/unraid-os/using-unraid-to/manage-storage/array/overview/), [Unraid adding-disks documentation](https://docs.unraid.net/unraid-os/using-unraid-to/manage-storage/array/adding-disks-to-array/), and [Unraid replacing-disks documentation](https://docs.unraid.net/unraid-os/using-unraid-to/manage-storage/array/replacing-disks-in-array/). Unit oracles use the [BIPM SI prefixes](https://www.bipm.org/en/measurement-units/si-prefixes), [NIST binary prefixes](https://physics.nist.gov/cuu/Units/binary.html), and the repository shared byte contract in `content_docs/storage-tools/calculation-engine.md`.
