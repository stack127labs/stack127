## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | The planner shows materially wrong capacity, gap, or parity information; accepts an impossible expansion; exposes private input through state or telemetry; executes an unsafe capability; or makes the primary planning job inaccessible. |
| P1 | A common edit, submit, recovery, copy, share, restoration, focus, announcement, responsive, publication, or clean-URL flow fails even though the underlying formula remains correct. |
| P2 | An uncommon presentation, formatting, theme, long-string, or resilience detail is wrong without changing the decision or blocking recovery. |

### Formula invariant set

- `D = floor(memberBytes / S) * S`; only member capacity is sector-aligned. `A` and its remainder remain exact.
- For all widths, `P` is unchanged, `P < N <= 64`, `B(N) > 0`, `C(N) = D*N`, `0 <= A <= C(N0) <= C(N)`.
- `oldBlockCount*B(N0) + occupancyRemainder = A` and `0 <= occupancyRemainder < B(N0)`.
- `newBlockCount(N)*B(N) <= freePhysical(N) < (newBlockCount(N)+1)*B(N)`.
- `immediate(N) = oldLogical + newWritable(N)`; `gain(N) = immediate(N) - currentImmediate`.
- The pre-clamp `native(N) - immediate(N)` must be nonnegative. A negative value is an invariant failure, never a zero gap.
- Final `oldLogical + newWritable(Nf) + gap(Nf) = native(Nf)` exactly.
- `steps.length = Nf-N0`; widths are contiguous and strictly increasing by one; `A`, old count/logical, and remainder are identical across them.
- `addedDiskExcess = max(0, added-member)` and total excess multiplies by step count but never enters `C(N)`.
- All engine integers are `bigint`, all results are deterministic and deeply immutable, friendly formatting never changes exact stored bytes, and reported capacity has no numeric field.
