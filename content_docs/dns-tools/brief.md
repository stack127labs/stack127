# Brief: DNS tools

## Who is here

A domain owner or technical operator has a DNS question or an active failure and needs to choose the right diagnostic path. They know the symptom but may not yet know which DNS layer is responsible.

## The job

They should reach the tool that matches the symptom, run one bounded check, and read an evidence-backed answer that separates authoritative data, resolver caches, referrals, and cryptographic validation.

## Show vs say

The hub is a problem-to-tool list: each card names the real tool, states the symptom it handles, and gives one scope sentence. Marker art may explain a relationship such as the path through DNS, never exact results. Individual tools put the form and conclusion first, use tables for repeated records or server replies, and use small chain figures for referrals and DNSSEC relationships. Sentences carry only interpretation, caveats, and the next useful action.
