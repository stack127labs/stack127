## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | A wrong capacity, wrong failure-domain requirement, misleading loss result, privacy leak, or inaccessible primary calculation would make the planner unsafe to use. |
| P1 | A common input, sharing, recovery, keyboard, responsive, or stale-result flow fails while the core formula remains correct. |
| P2 | An uncommon resilience, presentation, performance, or copy issue needs refinement but does not change the modeled answer. |

The main risk is false confidence. Every displayed number must come from the exact route-local engine, and every result must disclose that it is a planning model rather than proof of a live CRUSH placement or durability guarantee.

## Test plan

### Pure engine and unit tests

- `tests/pages/ceph-capacity-calculator/ceph-capacity-calculator.test.mjs`: parser grammar, unit multipliers, BigInt totals, replication and EC fixtures, grouping, tie ordering, placement states, largest-loss invariants, reserve floors, display rounding, validation bounds, serialization, malicious labels, deterministic output, and the 32-row/256-OSD performance cap. Every FF fixture is a named test with exact byte assertions.
- Use a small internal helper to construct inputs from explicit rows. Do not test React state through the engine file. Assert invalid output contains stable field keys and that invalid input cannot produce a `values` object.
- Benchmark only the pure engine with deterministic in-memory data. Run 100 calculations for the legal maximum fixture and use the contract's under-10-ms focused budget with a CI-safe warning threshold if shared-host timing is noisy. A failed calculation or unstable output is P0/P1 even if timing passes.

### API or route tests

- Not applicable: the planner has no API route, server action, upstream Ceph query, cache, or request-response contract. Route behavior is covered by the static ownership and SEO checks plus the guarded rendered browser suite.
