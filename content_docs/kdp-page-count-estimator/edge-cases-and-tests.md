## Risk model

| Priority | Meaning for this tool |
| --- | --- |
| P0 | A wrong page range, wrong rounding, missing invalid-state guard, privacy leak, public publication, or inaccessible primary result could lead to a bad print decision or make the tool unusable. |
| P1 | A common input, recovery, keyboard, responsive, history, or result-hierarchy failure could leave the author with a stale or misleading estimate. |
| P2 | An uncommon presentation, resilience, or performance issue that does not change the calculation or block the primary job. |

## Test plan

### Pure engine and unit tests

- `tests/pages/kdp-page-count-estimator/kdp-page-count-estimator.test.mjs`: add `FF-001` through `FF-010`; assert all intermediate values, totals, warnings, source versions, and exact issue fields.
- The same file should cover defaults, every inclusive and exclusive numeric bound, strict input grammar, unsupported enum and trim values, exact key-set validation, impossible text geometry, finite-safe output, zero-word behavior, addition invariants, monotonicity, and deterministic repeated calculation.
- Use property checks for these invariants: increasing words cannot reduce either text-page endpoint; increasing an addition cannot reduce either raw or displayed total; `totalPages.min` and `totalPages.max` are even; `totalPages.min <= totalPages.max`; zero words create zero text pages and zero chapter starts; invalid input always returns `values = null`.
- The engine fixture file must not import React, browser globals, network clients, storage, or a live clock. No fixture may depend on locale formatting.

### API or route tests

- No API or upstream route exists for this tool. A route-level request test should prove that a valid calculation does not create a fetch or server calculation request and that embedded trim and guidance data are sufficient offline.
- If a future adapter accepts untyped form payloads, test the parser boundary separately from the typed engine. It must classify empty, whitespace, locale separators, signs, decimals, exponent notation, unsafe integers, unknown keys, and malicious strings before calling the engine.
- Keep failure injection local to the route test. Do not add a production network mock or a fake upstream dependency merely to manufacture a loading state.

### Browser tests

- Proposed route file: `tests/pages/kdp-page-count-estimator/kdp-page-count-estimator.spec.ts`. The existing ownership manifest currently names `page.test.mjs`; the build stage must add this Browser file to the manifest before treating the route as complete.
- Cover clean state, visible controls, valid submit, zero words, odd and even result values, warnings, result order, duplicate-text counts, table headers, disclosure links, stale-result clearing, invalid recovery, reset, Enter submission, rapid repeated submit, retry, query and reload behavior, request and storage inspection, and accessibility tree assertions.
- Run the same state matrix at 320px, 375px, 390px, 760px, and 1280px in dark and light themes. Assert `document.documentElement.scrollWidth <= window.innerWidth` for document overflow, then allow only the additions or guidance table wrapper to own local horizontal overflow.
- Use keyboard-only procedures for every action. Assert visible focus, result focus after success, first-invalid focus after failure, one live announcement, persistent labels, associated errors, table header semantics, and warning text that remains meaningful without color.
- Add manual comprehension checks for the two-second result scan, distinct purpose of each result region, whether the model assumptions are understandable, and whether any repeated range or `Other pages` value can be removed without losing meaning.

### Static and SEO tests
